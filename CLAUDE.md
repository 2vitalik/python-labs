# python-labs

Вебсистема для лабораторних ХНУРЕ. Робоча памʼять проєкту — `.dev/` (спека, тікети, статус); спільне ядро всіх сайтів — `core/` (`api/` — пакет `core`, `ui/` — Vue; [README](core/README.md)); сайт python — `app/` (`api/` — FastAPI-бекенд, `vue/` — Vue 3 SPA): ігри й реєстри сайту; сайт ods — `sites/ods/` (`api/`, `vue/`; `data/` — поза git).

## Правила коду

- Код лаконічний і максимально зрозумілий, «ніби писав сам Vitalik»: мінімум шарів, магії та залежностей.
- Дрібні файли: один файл — одна відповідальність, орієнтир ≤ ~80 рядків; виріс — розбити.
- Код, ідентифікатори, коментарі — EN; тексти UI — UA; відповіді в чаті — UA.
- Коментарі — лише там, де код сам не пояснює «чому».

## Контент ODS

- Лекції й лаби ODS — лише в Mongo, **ніколи в git**: ні файлами, ні знімком, ні цитатами в `.dev` (репо може стати публічним). До бази — `sites/ods/data/` на диску, поза git.

## Коміти й паралельні сесії

Рішення Vitalik 2026-11-17; у цьому проєкті воно старше за глобальне «коміти робить користувач».

- **Комітить агент сам і одразу** — щойно готовий логічний шматок: один коміт — одне рішення, після нього збірка й смоуки цілі. Не накопичувати зміни до кінця сесії. Невдалий поділ можна обережно переробити, поки коміт останній, свій і не запушений. Меседж — за глобальним форматом (Conventional Commits, тікети в кінці, трейлери `Co-Authored-By` / `Claude-Session`). `git push` — лише на пряме прохання.
- **У репо часто працює кілька сесій одночасно; робоче дерево й індекс git у них спільні.** Тому:
  - на старті — `dev live` + `ListAgents`, записка кожній живій сесії цього репо через `SendMessage`: що роблю, які файли мої, що з нею перетинається; відповіді не чекати; чужі файли й тікети не чіпати;
  - комітити лише своє й лише за шляхами: `git add <свої нові файли>` → `git commit -m … -- <свої шляхи>`; нічого не лишати в індексі між кроками; ніколи `git add -A` / `git commit -a` / `git stash` / `git rebase`, ніколи `git checkout` / `restore` / `reset` чужих файлів;
  - `--amend` — лише коли HEAD — власний останній коміт; інакше — новий коміт;
  - спільні файли (`router.js`, `api.js`, `site.js`, `style.css`, `main.py`, `db.py`, `.dev/CHANGELOG.md`, `.dev/README.md`, STATUS) — точковий Edit по свіжому читанню, без перезапису цілого файла; перед комітом такого файла — `git diff` на нього: чужі рядки в коміт не брати (проміжна версія файла → `git hash-object -w` → `git update-index --cacheinfo` → `git commit` без шляхів) або домовитись із сусідом;
  - `index.lock` зайнятий — почекати й повторити, не видаляти;
  - MAP / TREE — автоген: комітить той, хто щойно згенерував; номер тікета дає `dev new`, а не recap;
  - задуми, що зачіпають чужу ділянку (спільні компоненти ядра, моделі, меню), — спершу записка сусідові.
- **Що показала ніч 2026-11-17 (шість сесій разом)** — зведено з досвіду всіх:
  - **записка на старті** — свої файли, порти й база стенда, і що з твого вже закомічено: сусіди бачать у дереві зміни й не знають чиї; форму даних між сесіями просити й віддавати одним рядком («хто віддає дані, той каже форму»); закомітив спільний файл — скажи тому, хто править його ж;
  - **стенд — свій на сесію**: порти й база записані в `.dev/.drafts/STANDS.md` (сесія · API · Vite · Chrome · база · з якого часу); перед запуском — рядок у реєстрі й `lsof -nP -iTCP:<порт> -sTCP:LISTEN`; пішов — рядок прибрати. Смоукам — своя база на прогін: `python_labs_<тікет>_<назва>_smoke`;
  - **дерево збирається на кожному кроці**: новий файл створити раніше, ніж імпорт на нього; розірвав імпорт — зший у тому ж кроці, не «потім»;
  - **чуже незбірне дерево не лагодити й не чекати** — своє перевіряти на копії `HEAD`: `git archive HEAD app/api core/api data/guide | tar -x -C <скретч>`, свої змінені файли поверх, запуск інтерпретатором venv з `PYTHONPATH=<копія>/core/api` і `SESSION_SECRET=…` (не `uv run` з іншої теки: він перепризначить editable-шлях `labs-core` усім сесіям); фронт — так само `git archive HEAD app/vue core/ui`, симлінк `node_modules`, `vite build`. Стенд — без `--reload`: чужі правки в `app/api` перезапускають його посеред сценарію;
  - **переробка, що надовго ламає дерево**, — в окремому робочому дереві поза Dropbox (`git worktree add`) зі своїм venv; `.dev` і тоді вести в спільному дереві (`dev new` бачить чужі незакомічені номери лише там); наприкінці — перенести гілку на свіжу основну й `merge --ff-only`;
  - **MAP / TREE після `dev new`** — комітити одразу разом зі своїм тікетом, хоч би й заготовкою: наступний `dev gen` сусіда інакше змішає зміни; чужі ще не закомічені тікети в них — норма;
  - **коміт**: шляхи писати явно (у zsh список у змінній — один аргумент); після невдалого `git commit` — `git status`: доданий файл лишився в індексі; після вдалого — `git show --stat HEAD`: чи всі шляхи в ньому;
  - **субагентам спільні файли не давати** (`Icon.vue`, `style.css`, `api.js`, `router.js`): значки й рядки додає головна сесія наперед;
  - STATUS «Агент» — один блок на всіх: перед записом прочитати й злити, чуже не стирати.
