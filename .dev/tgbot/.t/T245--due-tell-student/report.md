# T245 · /due: повідомлення студентові від викладача з підписом бота — звіт

`2026-10-28` · ⚙️ задача · план — `plan.md` · попередник — [T244](../T244--due-asked/report.md) · вибори — [T243](../T243-Q--due-command-choices.md) (Q1 → «b», сказано в чаті)

## Зроблено

- **У чаті зі студентом** після `/due <лаба> <дата | ? | ->` бот пише **від акаунта Vitalik** (Chat Automation, `business_connection_id`) — команда зникає, замість неї студент бачить від викладача:
  ```
  🤖 Бот Python Labs записав на сайті:
  📅 Лаба 1 — дедлайн подовжено до чт 5.11, 23:59
  ```
  `?` → «📅 Лаба 1 — дедлайн подовжено, дату узгодимо окремо»; `-` → «📅 Лаба 1 — подовження знято, дедлайн знову вт 20.10, 23:59» (без базового дедлайну — лише «подовження знято»). `!` і «без змін» — студентові нічого. Причина, вердикт, 🙋 — лишаються в тебе.
- Назва сайту — `settings.site_name` (`SITE_NAME` у `site.env`: «Python Labs»; ods підставить своє), день тижня — `lab_marks.day()`.
- Telegram відмовив (право «Reply to messages» вимкнене, або студент не писав у цей чат за останню добу — Bot API дозволяє боту писати від імені акаунта лише в такі чати) → позначка на сайті все одно стоїть, алерт 📅 додає «⚠️ Студентові не написав: …» і підказку.
- З форуму й чату з ботом (`/due <нік> …`) студентові нічого не йде: там нема бізнес-зʼєднання; підтвердження — як раніше, алерт.
- Повідомлення лягає в журнал `messages` як вихідне (`chat_type: business`) — видно в стрічці `/activity` студента.
