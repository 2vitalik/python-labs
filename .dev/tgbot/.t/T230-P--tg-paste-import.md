# T230 · Імпорт листування з Telegram вставкою тексту

`2026-10-24` · 💡 proposal

Контекст:
- запит Vitalik (чат, 2026-10-24): бот через Chat Automation старі повідомлення не бачить → «щоб я просто скопіював повідомлення, вставив на сайті десь у комірку студента, і ти імпортував це в нашу структуру»;
- журнал `messages` і його поля — [T132](T132--chat-automation-notes/report.md), [T138](T138--tg-footprint/report.md); показ на `/activity` — [T146](../../platform/.t/T146--activity-page/report.md), підпис непривʼязаних рядків при читанні — T150;
- зразок вставки з того ж роду — імпорт студентів із ЦІСТ/DL (`parse_students`, `/students`), 2026-10-23.

## Проблема

- Bot API історію чату не віддає: ні при підключенні Chat Automation, ні при додаванні студента в «Selected Chats». У `messages` є лише те, що прийшло, поки бот працював.
- Старе листування зі студентами (до підключення або поки бот лежав) у журналі відсутнє, а воно й є «слід студента».

## Рішення

- **Де:** картка студента в адмінці (`/students/<нік>/edit`), окрема картка «Telegram: вставити листування» під формою профілю.
- **Що вставляти:** виділені в Telegram повідомлення → «Копіювати». Клієнти дають текст виду `Імʼя, [24.10.2026 12:34]` + рядки тексту, повідомлення розділені порожнім рядком. Парсер терпимий: шапка — `^<імʼя>, [<дата>]$`; усе до наступної шапки — текст (порожні рядки всередині тексту не ламають); дата — `дд.мм.рррр` або `дд.мм.рр`, `рррр-мм-дд`, `24 Oct 2026`, час `гг:хх[:сс]` з необовʼязковим AM/PM; зона — `TZ` сайту (Europe/Kyiv, як у дайджесті й зведенні людей). Шапка з нерозібраною датою → помилка з цитатою рядка (не мовчки в текст: невідомий формат краще побачити).
- **Хто є хто — два кроки:** «Розібрати» → сайт показує авторів із кількістю рядків і сам пропонує, хто з них студент (збіг слова імені з ПІБ, `name`, `aliases`, ніком студента; інакше — той, хто не збігається з іменами викладача); перемикач дозволяє виправити; «Імпортувати» → запис. Решта авторів — викладач. Вгадування без підтвердження відкинуто: помилкова сторона — зіпсований журнал, який потім чистити руками.
- **Запис у `messages`** — як живі рядки Chat Automation, щоб `/activity` показував імпортоване тим самим кодом:
  - `chat_type=business`, `dir=in`, `kind=import`, `content_type=text`, `message_id=0`, `at` — з шапки, `raw={"author": <імʼя з шапки>}`;
  - `user` — пошта автора (студент або викладач), `from_id`/`username` — його Telegram id і нік, якщо привʼязаний; `chat_id` — Telegram id студента або `0`, поки не привʼязаний;
  - нове поле `about` — пошта студента на кожному імпортованому рядку: живі рядки викладача стрічка студента знаходить за `chat_id`, а в непривʼязаного студента його нема; `about` — явна привʼязка чату до людини, що не залежить від привʼязки бота.
- **Дублі:** повторна вставка того самого шматка і накладання на живий період (бот уже зловив частину) не множать рядків — ключ `(хвилина, текст)` серед рядків цього чату (`about` або `chat_id`, `chat_type=business`); у вставці час з точністю до хвилини, живі рядки округлюються до неї.
- **На `/activity`:** бейдж «імпорт» поруч із «особистий чат»; рядки викладача в стрічці студента — з його імʼям, як живі; у загальній стрічці рядки викладача сховані, як усі службові (`staff`).
- **Відповідь сайту після імпорту:** скільки додано (студента / твоїх), скільки пропущено як дублі.

## Чому так, а не інакше

- Вставка тексту, а не `result.json` з Telegram Desktop → Export chat history: у JSON є `message_id`, секунди й медіа, але це зайвий крок для викладача; запит був саме «скопіював — вставив». Експорт можна додати тим самим ендпоінтом пізніше, якщо знадобляться медіа чи точний час.
- Поле `about` замість перекручування `dir`/`user` (варіант «рядок викладача = `dir=out` від імені студента» відкинуто): семантика `dir` і `user` у живих рядках лишається, стрічка студента отримує одну додаткову умову.
- Ніяких алертів і нотаток з імпорту: це минуле, бот у ньому не учасник.

## Не робимо зараз

- Медіа (у вставці їх нема — лише `[Photo]`-подібні підписи клієнта, лишаються текстом), правки й видалення, реакції.
- Імпорт у форум чи груповий чат — лише особисті чати зі студентом.
- Експорт у JSON — за потреби, окремим кроком.
