# T130 · Сигнал боту з приватного чату: Chat Automation, Guest Bots, ефемерні команди

`2026-09-24` · 🔆 clarification

Контекст:

- Стан бота: aiogram 3.31 = Bot API 10.3 (серпень 2026) — усе нижче вже є в бібліотеці, оновлювати нічого.

## Коротко

«Нова фішка» — оновлення Telegram 7 травня 2026 (Bot API 10.0): **Chat Automation** — бот, підключений до власного акаунта, читає і відповідає у твоїх приватних чатах (раніше це був Telegram Business для Premium, тепер безкоштовно) — і **Guest Bots** — бота можна @згадати в будь-якому чаті, де його нема, і він відповість там. Плюс з липня 2026 (Bot API 10.2) — **ефемерні команди** в групах: команда, яку бачать лише автор і бот. Для «сигналу з приватного чату» підходить перше; друге — для видимих студенту дій; третє — для форуму потоку.

## 1. Chat Automation (Business / «Secretary Mode») — рекомендую

- Що це: Telegram → Settings → **Chat Automation** → обрати бота → **які чати** (усі 1:1 · крім контактів · лише нові · вибрані користувачі; є виключення) → **права**. Бот отримує `business_message` для **кожного** повідомлення в обраних чатах — і студентських, і твоїх («the bot will receive messages from both chat participants»), а також `edited_business_message` і `deleted_business_messages`. Історію до підключення не бачить.
- Ідентифікація: `chat.id` = Telegram-id студента (той самий, що `User.tg_chat_id`), `from.id` = хто написав (ти чи студент); у кожному повідомленні — `business_connection_id`.
- Сигнал: пишеш у чаті зі студентом `/late`, `/note …` тощо → бот бачить це як твоє повідомлення в чаті цього студента → записує, а команду може **видалити з чату** (`deleteBusinessMessages`, право `can_delete_all_messages`; студент може встигнути побачити на секунду); підтвердження — алерт у твій адмін-чат, не в чат зі студентом. За бажанням бот відповідає **від твого імені** (`can_reply`, лише в чатах із вхідними за останні 24 год; такі повідомлення клієнт помічає — поле `sender_business_bot`).
- Ціна: безкоштовно — «Allowed Business Bots to manage accounts without Premium subscription» (Bot API 10.0, 2026-05-08); в docs: «Connecting a business bot does not require Telegram Premium».
- Увімкнути: BotFather → бот → Bot Settings → **Secretary Mode** (стара назва — Business Mode). У коді: той самий `log.incoming` як outer-middleware на `dp.business_message` + хендлер команд з умовою `from.id == адмін`; `message.answer()` в aiogram сам підставляє `business_connection_id`.
- Правила (ToS для розробників ботів, §5.4): чесно описати, що бот робить і **які дані зберігає та як довго**; листування — лише для сервісу, нікому не передавати; нічого не приховувати від власника акаунта (це ти). Практично — рядок у `/howto` і в описі бота: «листування з викладачем і ботом зберігається в системі курсу».
- Мінуси: бот бачить обрані чати цілком — обсяг збереження вирішує [T131](T131-Q--message-log-2.md) Q2; підключення живе на твоєму акаунті.

## 2. Guest Bots (Bot API 10.0, травень 2026)

- Що це: пишеш `@python_nure_bot /late` у **будь-якому** чаті, зокрема приватному зі студентом — бот не член чату, але отримує `guest_message` з цим повідомленням і, якщо це відповідь, з повідомленням, на яке відповідаєш; має **одну** відповідь (`answerGuestQuery`), яку бачать усі в чаті. Історії, списку учасників і наступних повідомлень не бачить, доки не згадають знову. До 3 guest-ботів в одному повідомленні.
- Увімкнути: BotFather (міні-апка) → **Guest Mode**. У коді — `dp.guest_message`.
- Ідентифікація студента: надійно — відповідати на його повідомлення (`reply_to_message.from`); що саме в `chat` при згадці в приватному чаті — перевірити на клік-тесті (docs: id «may not coincide with other existing bot chats sharing the same identifier», тобто, імовірно, id співрозмовника).
- Підходить для **видимих** дій — «зараховано», «постав ✔️»: студент бачить і згадку, і відповідь бота. Тихим сигналом бути не може.

## 3. Ефемерні команди в групах (Bot API 10.2, липень 2026)

- Що це: команда, зареєстрована з `is_ephemeral` (`setMyCommands`), при відправці в групі **невидима** іншим учасникам і ботам; бот відповідає ефемерно (`ephemeral_message_parameters(receiver_user_id=…)`) — теж бачиш лише ти; відповісти на ефемерне можна лише протягом 15 с. Лише групи й супергрупи, не приватні чати.
- Для форуму потоку — ідеальний тихий сигнал: `/late vasya` у гілці, ніхто не бачить. Чи можна ефемерну команду відправити як відповідь на повідомлення студента — перевірити на клік-тесті; якщо ні — нік у аргументі.

## 4. Без нових фіч, уже зараз

- **Форвард**: переслати повідомлення студента боту (або в адмін-гілку) і наступним рядком команду. `forward_origin.sender_user` дає студента, якщо в нього відкрита приватність «Пересилання повідомлень», інакше — лише імʼя (`MessageOriginHiddenUser`).
- **У форумі потоку** — відповідь на повідомлення студента командою: команди бот отримує і в privacy mode, `reply_to_message.from` = студент. Але команду бачать усі.
- **Інлайн-режим** (`@bot запит`): бот отримує лише `chat_type`, не чат; обраний результат стає видимим повідомленням; після появи Guest Mode сенсу нема.

## Журнал форуму потоку (Q3 з T129 у новому розумінні)

- У privacy mode бот у групі бачить лише команди, відповіді собі й службові повідомлення. Щоб бачити **все** — зробити бота **адміністратором** форуму (жодних прав не треба: «bot admins always receive all messages») або вимкнути privacy mode у BotFather (тоді бота треба перезаходити в усі групи). Рекомендую адміна — точково і без перезаходу.
- Що приходить: нові повідомлення, правки (`edited_message`), реакції (`message_reaction` — лише адмін-боту і якщо підписатись), вступи/виходи. **Видалення в групах боту не приходять** (лише в бізнес-чатах — `deleted_business_messages`). Історії до додавання — нема.
- Гілки: `message_thread_id`; назва — зі службових `forum_topic_created`/`forum_topic_edited`; методу «список гілок» для ботів нема.

## Рекомендація

1. Зараз (зроблено в T129): журнал усього, що бот бачить і шле; ти робиш бота адміном форуму потоку — форум теж у журналі.
2. Сигнал із приватних чатів — **Chat Automation**: Secretary Mode у BotFather + підключення на твоєму акаунті з вибором «студенти» (вибрані користувачі або «всі, крім контактів»); бот пише команди в журнал, прибирає їх з чату, підтверджує алертом. Обсяг збереження приватного листування — [T131](T131-Q--message-log-2.md) Q2.
3. Форум — ефемерні команди, коли зʼявиться каталог зауважень ([T14](../../remarks/.t/T14-Q--remarks-open-questions.md)): та сама команда, що й у приватному чаті.
4. Guest Mode — увімкнути «про запас» (нічого не коштує) для видимих відповідей студентам у їхніх чатах.
