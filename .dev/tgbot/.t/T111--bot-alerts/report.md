# T111 · Адмін-алерти про зміни профілю: чат/гілка через /here — звіт

`2026-09-19` · ⚙️ задача · план — [plan.md](plan.md)

Зроблено за планом; смоук `tests/smoke_notify.py` **21/21**, `smoke_bot.py` **12/12**. Живий клік-тест — за Vitalik (потрібен `TG_BOT_TOKEN` і привʼязаний бот у твоєму профілі).

## Як налаштувати (раз-раз)

1. У своєму профілі на сайті — «Привʼязати бота» (адмін — теж юзер, посилання є). Відтоді всі алерти йдуть тобі особисто в чат з ботом; це вже робочий стан, далі — за бажанням.
2. Захотів окремий чат: створи групу (можна форум із гілками), додай туди бота, і в потрібному чаті чи гілці напиши `/here change` — усе, зміни й видалення йдуть сюди. В іншій гілці — `/here fill`. Або `/here all` — усе сюди.
3. `/here` без слів — куди що йде зараз; `/here off` — цей чат/гілка більше нічого не отримує (види повертаються в «особисто»).

Правила: `/here` слухає лише адмін, що привʼязав бота (`tg_chat_id == from_user.id` + статус `admin`); вид привʼязаний до одного місця — повторний `/here` в іншій гілці перетягує його; privacy mode бота вимикати не треба (команди в групах доходять і так); у групах бот мовчить на все, крім `/here`.

## Види й тексти

`KINDS` у `bot/notify.py`:
- `fill` — 🟢 нові дані в профілі: заповнив порожні поля (ПІБ, GitHub, нік), привʼязав бота;
- `change` — 🟠 зміни й видалення в профілі: замінив наявне (🟠), стер поле чи відвʼязав бота (🔴), перепривʼязав з іншого Telegram (🟠 «інший Telegram» — підозрілий випадок з [T110](../T110-Q--bot-link-edge-cases.md)), змінив або прибрав `@username` у Telegram (дзеркало [T107](../T107-Q--tg-username-field.md));
- `login` — 👋 нові входи на сайт: увійшла людина, якої нема в базі (не з імпорту) — статус «очікує», лінк одразу на редагування.

Рівень алерту = найгірше поле в збереженні: 🟢 заповнено · 🟠 замінено · 🔴 видалено; 🟢 → вид `fill`, 🟠/🔴 → `change`. Три поля ПІБ згортаються в один рядок; порожнє після зміни — «✖️». Шапка — імʼя-лінк на `/students/<nick>` + група; без прев'ю посилань. Приклади:

```
🟢 Профіль · Пупкін Василь · ПЗПІ-25-1
🪪 ПІБ: Пупкін Василь Іванович
🐙 GitHub: github.com/vasya/labs
```
```
🟠 Профіль · Пупкін Вася · ПЗПІ-25-1
🪪 ПІБ: Пупкін Василь Іванович → Пупкін Вася Іванович
```
```
🔴 Профіль · Пупкін Василь · ПЗПІ-25-1
🤖 Бот: відвʼязано
✈️ Telegram: @vasya_tg → ✖️
```
```
👋 Новий вхід · New Person
📧 new@nure.ua
☝️ Не було в списках — статус «очікує»
```

Відповіді `/here`:

```
✔️ Сюди йтимуть:
🟠 зміни й видалення в профілі
```
```
🗂 Куди що йде:
🟢 нові дані в профілі → особисто адмінам
🟠 зміни й видалення в профілі → тут
👋 нові входи на сайт → Labs › Зміни
☝️ /here fill · change · login · all · off
```

Не доставилось у привʼязане місце (вигнали з групи, гілку закрили) → те саме повідомлення тобі особисто з рядком «⚠️ Не доставив у Labs › Зміни: <помилка Telegram>» зверху.

## Код

- `models/history.py` — `record()` повертає diff (`{}` якщо нічого не змінилось) — те саме, що лягає в `history`.
- `models/notify.py` — `Route(kind unique, chat_id, thread_id, title)`, колекція `routes`; `db.py` реєструє.
- `bot/notify.py` — `KINDS`; `bot()` — один `Bot` на процес (`@cache`, HTML, `link_preview_is_disabled`), його ж бере `__main__`; `send(kind, text)`: маршрут → `send_message(chat, thread)`; нема маршруту або `TelegramAPIError` → усім адмінам із `tg_chat_id`. Порожній `TG_BOT_TOKEN` → тихий вихід.
- `bot/alerts.py` — `who()`, `rows()` (рядок на поле: 🪪 ПІБ / 🐙 GitHub / ✈️ Telegram / 🤖 Бот), `profile()`, `signed_in()`.
- `bot/here.py` — окремий роутер із root-фільтрами `Command("here")` + `is_admin`; назва місця — `chat.title › гілка` (з `reply_to_message.forum_topic_created`: повідомлення в гілці — відповідь на її відкриття; інакше `#thread_id`). `__main__` підключає його перед `start`, бо fallback `start` ковтав би `/here` у приваті.
- `bot/start.py` — `router.message.filter(F.chat.type == "private")`: у групах бот мовчить, middleware дзеркала ніка по групах не бігає.
- Хуки: `routes/profile.py` і `routes/me.py` — `BackgroundTasks` після відповіді; `routes/auth.py` — `upsert_user(info, tasks)` → `signed_in` для нового; `bot/link.py` — `bind()`/`sync()` віддають diff у `alerts.profile` (там синхронно — це процес бота).
- Адмінські правки (`/api/students/…`, імпорт) алертів не дають — це дії самого Vitalik.

## Рішення по ходу

- Надсилання з API напряму, без черги в Mongo: aiogram `Bot` — це просто HTTP-виклик; черга з поллером — зайвий шар. Ціна — API теж читає `TG_BOT_TOKEN` (він і так у тому ж `.env`). Бот-процес для алертів не потрібен: надсилання не залежить від поллінгу.
- Рівень — по кожному полю, без правила «перше збереження = завжди 🟢»: в імпортованих студентів ПІБ уже правильне, тож перше збереження (GitHub/нік) і так 🟢; лише не з імпорту (Google-префіл латиницею) перше збереження дасть 🟠 «Pupkin → Пупкін» — рідко й видно з рядка. Тонше правило — [T112](../T112-Q--bot-alerts-questions.md) Q4.
- Один маршрут на вид; кілька місць на вид не потрібні — Telegram-гілки й так поруч.
- Рядок ПІБ один на три поля, рівень — найгірший із трьох: додане по батькові — 🟢 без стрілки, заміна імені — 🟠 зі стрілкою.
- `login` додано як пропозицію: дешево (один виклик в `auth.py`), а «невідомий увійшов — треба підтвердити» інакше видно лише зайшовши в `/students`.
