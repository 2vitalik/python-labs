## Вирішено / реалізовано

- **Бот існує: `@python_nure_bot`** (факт від Vitalik, [T60](../platform/.t/T60-Q--profile-questions.md) Q3); юзернейм — у `TG_BOT_NAME` конфіга сайту, токен BotFather — у `TG_BOT_TOKEN` (потрібен лише для запуску бота).
- Привʼязка акаунтів — deep link `t.me/python_nure_bot?start=<токен>` ([T58](.t/T58-C--tg-link-binding.md)): випадковий `tg_token` у документі юзера (не пошта і не ID — їх можна підробити), кнопка на сторінці профілю; бік сайту — [T64](../platform/.t/T64--profile-v1/report.md). Нюанс клієнтів (2026-09-19): у новому чаті лінк показує кнопку **Start**, а якщо чат з ботом уже є — клієнт шле `/start <токен>` сам (спека `core.telegram.org/api/links` обіцяє кнопку завжди, tdesktop авто-шле при `!history->isEmpty()`); підказка в профілі описує обидва випадки.
- ✅ **Бот-пустишка в коді** (2026-09-19, [T106](.t/T106--tgbot-stub/report.md)): `app/api/bot/` на aiogram 3 — спільні `config`/`db`/`models` з API, тому не окремий пакет; запуск `cd app/api && uv run python -m bot` (long polling, вебхук — з деплоєм). Контракт T58 виконано: `/start <token>` → юзер за `tg_token`, запис `tg_chat_id` + справжній `tg_username` через `record()` з actor `tgbot` (захоплення чужого токена видно в `history`); невідомий токен → відсилає до кнопки в профілі; нік дзеркалить Telegram — без `@username` поле стає порожнім (з 2026-09-19, [T107](.t/T107-Q--tg-username-field.md) Q2; до того не затиралось); повторний `/start` — перепривʼязка chat_id. Голий `/start` і будь-який інший текст — підказки. Смоук `tests/smoke_bot.py` (8 перевірок на заглушці повідомлення, без Telegram).
- ✅ **Привʼязка: слідкування, авто-детект, відвʼязка** (2026-09-19, чат): бот оновлює `tg_username` з кожного повідомлення привʼязаного чату (`sync()` у `bot/link.py` через outer-middleware — нік у Telegram міняється будь-коли; порожній теж записується — [T107](.t/T107-Q--tg-username-field.md) Q2); профіль після кліку «Привʼязати бота» опитує `/api/me` кожні 2 с до 3 хв і сам показує «✅ Бот привʼязаний»; «відвʼязати» → `DELETE /api/me/telegram`: стирає `chat_id` + нік через `record()` (actor — студент) і обертає `tg_token`, тож старе посилання мертве — для випадку «привʼязав не той акаунт». Доля ручного поля ніка — вирішено в [T107](.t/T107-Q--tg-username-field.md).
- ✅ **Ручне поле ніка лишається, нік = реальний стан Telegram** (2026-09-19, відповіді [T107](.t/T107-Q--tg-username-field.md)): поле в студентській формі не прибираємо — порожнє воно натякає, що це важливо, а без бота хоч ручний нік видно (Q1 b); `bind()`/`sync()` у `bot/link.py` пишуть `@username` як є, порожній стирає старий (Q2 a) — «актуальний стан, не слід». Помилково затерти живий нік бот не може: у приватному чаті відправник — завжди власник акаунта, Telegram шле поточний `username` з кожним повідомленням (або нічого, якщо його справді нема), групові чати не збігаються з `tg_chat_id` (їхні id відʼємні), а кожна зміна лягає в `history` з actor `tgbot` — відкат видно і можливий. Смоук `tests/smoke_bot.py` **9/9**.
- ✅ **Повідомлення бота в стилі Vitalik** (2026-09-19, зразки — [T109](.t/T109-C--bot-message-style.md)): кожен рядок починається з емодзі-ролі (👋 привітання · ✔️ результат · 🤖 хто я · ➕ умова · 🌐/✅ кроки · ❌ помилка · 🔁 зміна · ☝️ підказка), одна думка на рядок, без крапок, «)» замість смайлика, жирним — назви/кнопки/посилання, курсивом — умови. Тексти — `bot/texts.py`, HTML-розмітка (`parse_mode=HTML` за замовчуванням, імʼя — `html.quote`). Гілки `/start <token>`: перша привʼязка · той самий чат знову («вже було записано») · інший чат («🔁 …тепер писатиму сюди», перепривʼязка за T58) · невідомий токен («❌ Не впізнаю це посилання» + кроки) · без `@username` — «☝️ додай юзернейм»; голий `/start` і будь-який текст: привʼязаному — «вже записано» / «далі буде», чужому — інтро з лінком на `SITE_URL/profile` (`site_url` у конфігу: дев `http://localhost:5030`, прод — `https://python.labs.in.ua` у `.env.example`). Смоук `tests/smoke_bot.py` **12/12**.
- ✅ **Адмін-алерти про зміни профілю** (2026-09-19, [T111](.t/T111--bot-alerts/report.md)): кожне збереження студентом профілю, привʼязка/відвʼязка бота, дзеркало ніка і вхід невідомої людини → повідомлення адмінам у стилі T109: шапка «🟢/🟠/🔴 Профіль · імʼя-лінк · група», рядок на поле («🪪 ПІБ: старе → нове», «🐙 GitHub», «✈️ Telegram», «🤖 Бот: привʼязано / інший Telegram / відвʼязано», порожнє — ✖️). Види `fill` (🟢 нові дані) · `change` (🟠 заміна, 🔴 видалення) · `login` (👋 новий вхід, не з імпорту → «очікує»). **Налаштування — в Telegram:** без нічого — особисто кожному адміну, що привʼязав бота; у групі чи гілці форуму адмін пише `/here change` (`/here fill`, `/here all`, `/here off`, `/here` — статус) — вид привʼязується до цього місця (`Route` у Mongo). Недоставлене (вигнали з групи) → адмінам особисто з «⚠️ Не доставив у …». Шле API напряму через aiogram (`BackgroundTasks`), бот-процес для алертів не потрібен; порожній `TG_BOT_TOKEN` — тихо вимкнено. У групах бот мовчить на все, крім `/here`. Смоук `tests/smoke_notify.py` **21/21**.
- ✅ **Алерти, друга хвиля** (2026-09-19, [T113](.t/T113--bot-alerts-2/report.md), ідеї T112 Q3): видів сім — до `fill`/`change`/`login` додано `claim` 🎯 (заявка створена/відредагована/видалена, з назвою картки й обʼєктом), `game` 🧩 (картка гри створена/змінена, обʼєкт чи правило додано/видалено — правило реченням «КОЛИ … → ТО …» як на сайті; правки й скриншоти — ні, шум), `error` 💥 (необроблені винятки API і бота: перший рядок + «наш» кадр трейсбека; 4xx не алертяться), `digest` 📊 (щодня 09:00 Київ з процесу бота: по групах, скільки без ПІБ/GitHub/бота; усе заповнено — тиша); `login` тепер про **кожен** перший вхід (поле `User.seen_at`). `/mute <види>` вимикає вид (статус «🔇 вимкнено»), `/here <види>` вмикає назад; `/here` показує ключі видів. Смоук `tests/smoke_events.py` **18/18**, `smoke_notify.py` **25/25**.
- ✅ **Журнал повідомлень** (2026-09-24, [T129](.t/T129-Q--bot-message-log.md), Q1–Q2 «a» в чаті): колекція `messages` (`models/message.py`, `TgMessage`) — усе, що бот отримує і шле: `dir`, чат і гілка, `from_id`/`username`, email привʼязаного (`user`), текст або підпис, `content_type` + `file_id` для медіа, `message_id`, `kind` (вид алерту · `reply` · `edit`), час за Telegram. Вхідні — outer-middleware `bot/log.py` на `dp.message` до всіх роутерів (чужі й необроблені теж), правки — хендлер `edited_message` (окремий рядок `kind=edit`); вихідні — session-middleware `notify.outgoing()` на спільному `Bot`, тож відповіді бота, дайджест і алерти з процесу API — в одній колекції; вид алерту передає `ContextVar` із `send()`. Недоставлене не пишеться. UI перегляду — потім, обовʼязково (Q4). Смоук `tests/smoke_log.py` **9/9**. Форум потоку потрапляє в журнал, щойно бот стане його адміном (privacy mode — [T130](.t/T130-C--signal-from-private-chat.md)).
- ✅ **Chat Automation, нотатки, ефемерні команди, Guest Mode** (2026-09-24, [T132](.t/T132--chat-automation-notes/report.md), відповіді [T131](.t/T131-Q--message-log-2.md) у чаті): бот — адмін форуму потоку і privacy mode вимкнено (усе з форуму — в журнал); підключені чати Chat Automation (лише вибрані студенти — усі в контактах Vitalik) теж у `messages`, включно з правками й видаленнями. Нотатки про студента — колекція `notes` (`Note`): `/note <текст>` у чаті зі студентом — тихо (бот прибирає команду з чату, право «видаляти всі повідомлення»), «📝 текст» — видима студенту, `/note` у форумі — ефемерна команда для адмінів (бачить лише автор; студент з відповіді або з ніка), те саме в чаті з ботом; кожна нотатка — алерт виду `note` 📝. Guest Mode — одна відповідь-інтро на згадку в чужому чаті. Кроки підключення — у README бота; смоук `smoke_notes.py` **16/16**.
