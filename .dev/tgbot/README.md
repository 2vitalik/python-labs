# tgbot — Telegram-бот: нотифікації, опитування, вхід у систему

Бот як другий інтерфейс до тієї ж БД: нотифікації (захисти, дедлайни, зарахування), опитування зі статистикою, кандидат на основну автентифікацію сайту. Сусіди: [defense](../defense/README.md), [journal](../journal/README.md), [platform](../platform/README.md).

## Вирішено / реалізовано

- **Бот існує: `@python_nure_bot`** (факт від Vitalik, [T60](../platform/.t/T60-Q--profile-questions.md) Q3); юзернейм — у `TG_BOT_NAME` конфіга сайту, токен BotFather — у `TG_BOT_TOKEN` (потрібен лише для запуску бота).
- Привʼязка акаунтів — deep link `t.me/python_nure_bot?start=<токен>` ([T58](.t/T58-C--tg-link-binding.md)): випадковий `tg_token` у документі юзера (не пошта і не ID — їх можна підробити), кнопка на сторінці профілю; бік сайту — [T64](../platform/.t/T64--profile-v1/report.md).
- ✅ **Бот-пустишка в коді** (2026-09-19, [T106](.t/T106--tgbot-stub/report.md)): `app/api/bot/` на aiogram 3 — спільні `config`/`db`/`models` з API, тому не окремий пакет; запуск `cd app/api && uv run python -m bot` (long polling, вебхук — з деплоєм). Контракт T58 виконано: `/start <token>` → юзер за `tg_token`, запис `tg_chat_id` + справжній `tg_username` через `record()` з actor `tgbot` (захоплення чужого токена видно в `history`); невідомий токен → відсилає до кнопки в профілі; без `@username` у Telegram ручне поле не затирається; повторний `/start` — перепривʼязка chat_id. Голий `/start` і будь-який інший текст — підказки. Смоук `tests/smoke_bot.py` (7 перевірок на заглушці повідомлення, без Telegram).
