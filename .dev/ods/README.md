## Рішення

- **Один репо з python-labs**, деплой сайту — зі своєї гілки · [T164](../.rounds/.t/T164-R--ods-kickoff.md).
- **Окрема база** на сайт; користувачі з python-labs не спільні · T164.
- **Вхід** — Google OAuth, пошта NURE; бот привʼязується, як на python · T164.
- **Контент у два етапи** · T164:
  - зараз — md-файли в git, агент править їх напряму;
  - згодом — Mongo з редактором, як методичка python-labs.
- **Версії для викладача в git не потрапляють** · T164:
  - зараз — файли `*.hid.*` на диску, синк — Dropbox;
  - згодом — лише база.
- **Репо може стати публічним:** у `.dev` і в `sites/ods/data/` нічого з розвʼязків.
- **Код базового варіанта** пише модель Opus 5.5, окремим запитом Vitalik.

## Де що лежить

```text
sites/ods/
├── data/                 # у git
│   ├── lectures/         # README.md, NOTES.md, lec01…lec15: lecNN.md + img/
│   └── labs/             # README.md, lab1…lab5: labN-student.md + img/
│                         # поза git: NOTES.hid.md, labN-teacher.hid.md,
│                         #           lab4-correction.hid.md, img/*.hid.*
└── orig/                 # поза git: pptx/, docx/
```

- Коду сайту ще нема: `sites/ods/api/` і `sites/ods/vue/` зʼявляться з базовим варіантом.
- Опис формату md — у README поруч із даними: [лекції](../../sites/ods/data/lectures/README.md), [лаби](../../sites/ods/data/labs/README.md).

## Правила роботи з контентом

- Нове для викладача — одразу з `.hid.` у назві. Страховка в `.gitignore` ловить `*teacher*` і `*correction*` у лабах, але інші назви не зловить.
- Зображення, потрібне лише версії для викладача, — теж `.hid.`.
- Перед комітом контенту — `git status`: серед нових файлів не має бути нічого з розвʼязками.
- Авторський текст лекцій і лаб не виправлявся. Правки змісту — лише за рішенням Vitalik; підказки, де дивитися, — у `NOTES.md` і `NOTES.hid.md`.
