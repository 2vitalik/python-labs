# T377 · База ods на сервер: vv db push — параметри, що замінюється, коли востаннє

`2026-11-19` · 🔆 clarification

Контекст: питання Vitalik-а в чаті 2026-11-20 — чи можна зараз виконати `./vv/bin/vv db push ods-labs vv3`, щоб на сервері вже щось побачити, а коли всі сесії допрацюють локальну базу — запустити ту саму команду ще раз, «щоб вона вся потрапила на сервер як є».

**Коротко.** План логічний, але команда в такому вигляді зупиняється, нічого не зробивши: потрібні `--from` і `--drop`, пушити — копію `ods_seed`, після push — перезапуск API. І вдруге базу возити не треба: лекції й лаби оновлює `bin/content -t ods push` — з диска, через API сайту, лише змінене, скільки завгодно разів і вже при студентах. База цілком потрібна один раз — заради карток і списку потоку.

```sh
# раз: копія без дев-слідів (§3) → на сервер → перезапуск API ods на сервері
./vv/bin/vv db push ods-labs vv3 --from ods_seed --drop
# далі, щоразу як контент змінився: що відрізняється → відправити
~/.venvs/python-labs/bin/python bin/content -t ods ls
~/.venvs/python-labs/bin/python bin/content -t ods push
```

---

## 1. Чому не спрацює як є

Код — `vps-infra/vv/lib/vv/dbpush.py`.

| Що | Чому | Що скаже vv |
|:--|:--|:--|
| нема `--from` | база на сервері — `ods_labs` (`apps/ods-labs/app.conf`), локальна — `ods`; без `--from` vv бере локальну з імʼям серверної | «локальна база ods_labs порожня або її нема» |
| нема `--drop` | база сервера не порожня вже після першого старту API: `init_db` створює колекції з індексами, `seed()` кладе методичку з файлів (`core/api/core/app.py:49`) | «ods_labs не порожня — --drop, щоб замінити» |

З `--drop` сервер питає «Замінити N колекцій у ods_labs?» — `y`.

## 2. Що саме замінюється

- `mongorestore --drop` стирає й кладе наново **кожну колекцію, що є в архіві**, цілком. Колекцій, яких в архіві нема, не чіпає.
- Отже повторний push дає «як локально» для колекцій з архіву; колекція, яку локально прибрали, на сервері лишиться.
- Усе, що зʼявилось на сервері в цих колекціях між двома push, зникає: у `users` — входи, привʼязки бота, профіль викладача (створиться знову при вході за `ADMIN_EMAILS`); у `variants` — заняті картки.

## 3. Що пушити

Не всю `ods`: у ній дев-адмін, тестовий студент, 4 картки «ТЕСТ», `activity` 2227, `history` 353, 12 видів (`views`, `view_versions`) з колонками python. Копія — рецепт [T372](T372--ods-roster/report.md):

```sh
mongosh ods --quiet <<'JS'
const seed = "ods_seed", plain = ["guide", "media", "lab_pages", "lab_shapes"];
db.getSiblingDB(seed).dropDatabase();
for (const c of plain) db[c].aggregate([{ $out: { db: seed, coll: c } }]);
db.variants.aggregate([{ $match: { group: { $ne: "ТЕСТ" } } }, { $out: { db: seed, coll: "variants" } }]);
db.users.aggregate([{ $match: { status: "student", test: { $ne: true } } }, { $out: { db: seed, coll: "users" } }]);
const s = db.getSiblingDB(seed);
print([...plain, "variants", "users"].map((c) => c + " " + s[c].countDocuments()).join(" · "));
JS
```

На 2026-11-20 04:20 друкує `guide 47 · media 158 · lab_pages 27 · lab_shapes 5 · variants 310 · users 48`. Картинки й файли — `Binary` у самих документах (`media`, `lesson_files`), окремої теки з файлами нема.

**Список колекцій відстає від бази.** Не в рецепті: `lecture_changes` (каталог змін лекцій, [T374](T374--lectures-candy/plan.md); порожня), `lessons` 3 і `lesson_files` 14 (неопубліковані заняття, залив агент). Перед остаточним push — звірити кожну непорожню колекцію `ods` зі списком.

## 4. Після push — перезапуск API

`$out` створює колекцію лише з індексом `_id`, тож в архіві `ods_seed` індексів нема, а `--drop` стирає серверні. Унікальні — `users.email`, `guide.slug`, `media.path`, `lab_pages.slug`, `lab_shapes.lab`, `variants.lab+vid` — повертає `init_db` при старті API (юніт за `apps/ods-labs/units/ods-labs-web.conf`).

## 5. Оновлення контенту — `bin/content`, без заміни бази

Джерело лекцій і лаб — диск (`sites/ods/data/`), а не дев-база: «що йде на сайт, вирішує диск» ([T357](T357--ods-site/report.md)). `bin/content -t ods push` звіряє диск із сайтом за sha1 і шле лише різницю: сторінки, картинки й файли, слайди лектора, каталоги змін, дані пошуку, перелік сторінок лаб. `users`, `variants`, історію не чіпає.

Дев-база від диска відстає, тож db push найсвіжішого не привезе:

| | диск → сервер (`bin/content -t ods ls`, 2026-11-20 04:40) | дев-база `ods` |
|:--|:--|:--|
| сторінки | 47 нових | `guide` 47 |
| файли | 460 нових | `media` 158 |
| каталоги змін лекцій | 15 нових | `lecture_changes` 0 |

Той самий `ls` показав: сервер приймає токен агента (`ODS_TOKEN`), і контенту там зараз нема — усі 47 сторінок «нові».

| Що | Чим їде на сервер |
|:--|:--|
| лекції, лаби, старі лаби, картинки, файли, слайди, каталоги змін, пошук | `bin/content -t ods push` — повторюване |
| картки `variants`, форми `lab_shapes`, список потоку `users` | db push копії — раз, до студентів |
| дедлайни, гейти лаб, види | на сайті руками викладача |

Системний `python3` на ноутбуці — 3.9, `bin/content` на ньому падає (`dict | None`): запускати пітоном venv.

## 6. Коли db push востаннє

- До оголошення студентам: тимчасовий push і скільки завгодно повторних — безпечно.
- Після першого входу студента головна — база сервера. Далі контент їде `bin/content`, решта — через сайт.
- Код їде окремо (`git push origin ods`): на 2026-11-20 04:20 локальна `ods` на 2 коміти попереду `origin/ods`, у дереві 46 незакомічених файлів. Розбіжність сторінки на сервері з локальною — найімовірніше код.

## Не перевірено

- Базу сервера напряму: ssh нема. «Не порожня» — з коду старту API; сайт відповідає (`https://ods.labs.in.ua/` → 200), контенту нема — з `bin/content -t ods ls` (лише читання).
- `vv db push` і `bin/content push` не запускались: перше запускає Vitalik, друге — я за словом.
- Чи серверний код приймає все, що шле `bin/content push`: `ls` пройшов без помилок, сам push не пробувано.
