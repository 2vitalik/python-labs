# T181 · Деплой ods: вибори

`2026-10-01` · ❓ question

Контекст:
- план і знахідки — [T180](T180-P--ods-deploy-plan.md);
- план іде за варіантами «a»: мовчання = як у плані; інший вибір — правка одного-двох рядків маніфесту або хука;
- Q6 — не про ods: знайшлося дорогою.

**Q1 — Як ods отримує оновлення.**
- a) вручну: `git push origin main:ods`, коли хочеш оновити ods (рекомендую — це та пауза, заради якої гілку заводили в [T163](../../platform/.t/T163-P--core-and-sites.md): правка ядра їде на python одразу, на ods — коли готовий; правки ігор сайт із лекціями не перезапускають);
- b) автоматично: кожен push у `main` пересуває й `ods` — одна команда, але кожен пуш перезапускає обидва сайти й обох ботів;
- c) симетрично: python теж на свою гілку `python`, `main` нічого не деплоїть — доки й правки ods не перезапускають python; ціна — звичний `git push` перестає деплоїти, плюс правка маніфесту python-labs.

> 

**Q2 — Імена.** slug `ods-labs` → `/srv/ods-labs`, користувач `app-ods-labs`, юніти `ods-labs-web` і `ods-labs-bot`, база `ods_labs` (локально лишається `ods`), порт 8035, гілки `ods` і `www-ods`.
- a) так (рекомендую — за зразком `python-labs` ↔ `python.labs.in.ua`; гілки названі за сайтом, наступний сайт дасть `oop` і `www-oop`);
- b) інакше — напиши, що саме.

> 

**Q3 — OAuth-клієнт Google.**
- a) окремий клієнт для ods у тому самому проєкті, одна адреса `https://ods.labs.in.ua/api/auth/callback` (рекомендую — так зроблено для prod python: секрети сайтів незалежні);
- b) дописати адресу в prod-клієнт python — жодного нового секрету, але один secret на два сайти.

> 

**Q4 — Як контент потрапляє на сервер.** Продовження [T171](T171-Q--ods-base-choices.md) Q5.
- a) перший раз — `vv db push ods-labs vv3 --from ods`: локальна база без дев-користувача й дев-шуму; далі текст правиться на сайті або через `bin/guide -t ods`, нові картинки — окремим рішенням, коли знадобляться (рекомендую — нуль нового коду, та сама команда, що для python);
- b) `content_io.py` через SSH-тунель до Mongo сервера — і перший раз, і надалі; після першої правки на сайті повторний запуск затирає правки;
- c) API для сторінок і картинок із токеном агента — новий маршрут до деплою.

> 

**Q5 — Доступ агента до ods на сервері.** `bin/guide -t ods`: лекції й лаби як файли в `.site/ods/`, поза git.
- a) одразу: `AGENT_TOKENS!` у `env.conf` ods, токен у `.site/.env` (рекомендую — правки тексту лекцій без тунелів; спершу закрию `snap` для цілі не `prod`, щоб лекції не потрапили в `data/guide/`);
- b) пізніше — рядок `AGENT_TOKENS!` з маніфесту прибрати.

> 

**Q6 — Страховий файл опитувань на сервері.** Зараз бот python на сервері записати його не може — [T180](T180-P--ods-deploy-plan.md) «Побічні знахідки».
- a) налаштування `LOGS_DIR` у ядрі, як `UPLOADS_DIR`: на сервері `{DIR}/shared/logs` і `RW_PATHS="shared/logs"` у юніті бота (рекомендую — файл поза чекаутом, переживає перезаливку `repo/`);
- b) без коду: `RW_PATHS="repo/app/api/logs"` у юніті бота — тека всередині чекауту;
- c) лишити як є: голоси йдуть у Mongo, копії на диску на сервері нема.
