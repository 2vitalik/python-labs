## Вердикт

- **Варіант студент більше ніде не обирає й не називає.** Картку закріплює викладач; «Моя лаба» її показує; картка у файлі лише звіряється — чужа дає відмову зі словами.
- **Шлях студента по лабах 1–3 пройдено в браузері на копії бази з 48 закріпленими студентами: блокерів нема.** Знайдене дорогою виправлено тієї ж ночі.

- **Дві речі поза кодом сайту вирішують, чи запрацює здача лаби 3:** ліміт запиту на сервері (`BODY_MAX`, зараз 1,1 МБ проти 12 МБ на сайті) і дедлайни на «Строках».
- **Одне питання лишається відкритим і важить найбільше — чи номери 1–48 ті самі, з якими робили лаби 1–2** ([T380](../T380-Q--labs-1-3-choices.md) Q1).

## Пастки здачі, які закрито

Знайшли читач коду (Opus) і прохід у браузері; кожна має перевірку в смоуках.

| Що сталося б | Чому | Тепер |
|:--|:--|:--|
| студент після переносу з Telegram завантажує той самий файл «для певності» — і стає «після дедлайну» | кожне завантаження було новою версією й новою спробою | ті самі байти, що в найновішій версії, — не версія й не спроба; сторінка каже «Такий самий файл уже тут» |
| вчасна здача + виправлена версія після дедлайну = червоне «після дедлайну» | рахувалась лише остання версія | студент бачить «є версія, здана вчасно; остання — після дедлайну» без червоного (Q3) |
| ноутбук лаби 2, здане в лабу 3, приймається | картка однакова в усіх лабах | остання клітинка кожного шаблону друкує `LABn` — «Це ноутбук лаби 2, а тут лаба 3» |
| подовження «дата ще невідома» дає «після дедлайну» | враховувалась лише дата | таке подовження означає «дедлайну нема» — на «Моїй лабі» й на «Вхідних» |
| «Відкрити в браузері» для лаби 3 мовчки стирає лабу 2 в marimo | marimo.app тримає один ноутбук на браузер | сайт памʼятає, яка лаба там зараз, і питає перед заміною |
| два перші відкриття сторінки дають два різні токени — `check()` з ноутбука мовчки не доходить | токен ставився без умови | ставиться лише в порожнє місце й перечитується |
| посилання `javascript:…` у полі ноутбука стає клікабельним у викладача | поле зберігалось як є | лише `https://`, для ноутбука — лише Colab чи Drive; відхилене не зберігається |
| викладач звільнив картку помилково й закріпив знову — старих версій не видно, а той самий файл удруге не здається | версії лишались привʼязані до студента, а картка їх уже не показувала | версії картки, що починає з чистого, відкладаються (`origin: freed`): лишаються в базі, картці не заважають |
| ноутбук понад 1,1 МБ на сервері — «Помилка 413» | ліміт веб-сервера нижчий за 12 МБ сайту | сторінка каже, що робити; сам ліміт — у «Чекає тебе» |

По порядку, до оголошення студентам:

1. `git push origin ods` і перезапуск API ods — код цієї ночі (коміти нижче). Міграцій бази нема.

6. Оком студента («Очима студента» → студент зі списку): домашня → «Мої лаби» → «Моя лаба 3».
7. Оголошення — текст нижче.

Після дедлайну лаби 2: переслати боту одну розмову, глянути відповідь, далі решту; «Вхідні»; клік «сайт» на лабах 1–2 (Q4).
