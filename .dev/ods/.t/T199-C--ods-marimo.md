## Коротко

- **marimo** — ноутбук, який зберігається як звичайний `.py`: кожна клітинка — функція `@app.cell`, виводи у файлі не зберігаються, клітинки звʼязані графом залежностей: змінив число — усе, що від нього залежить, перерахувалось. Версія 0.25.1 (1 жовтня 2026), релізи що 2–3 тижні, Apache-2.0, 23 тис. зірок; компанію-розробника в жовтні 2025 купила CoreWeave з обіцянкою лишити ноутбук вільним.
- **Замінити Jupyter повністю — не варто цього семестру**: студенти знають Colab, marimo вимагає нової звички (одна змінна — одна клітинка), інтерфейс лише англійською, мобільна версія — відкрите питання, API ще 0.x.
- **Зробити marimo другим форматом з того самого джерела — варто**: конвертація в обидва боки є, перевірка робіт у marimo простіша (словник змінних замість розбору виводів), реактивність — готовий інструмент для «а що, якщо» на захисті.
- **Сайт від формату не залежить**: картку видає і рядок приймає він; рахувати студент може де завгодно.

## Що вміє marimo, що важливо для лаб

| Що | Як | Перевірено |
|:--|:--|:-:|
| файл | чистий `.py`, `@app.cell def _(x): … return (y,)`; у кінці `app.run()` | так |
| правило | кожна глобальна змінна визначається лише в одній клітинці; `_імʼя` — локальне для клітинки | так |
| без інсталяції | marimo.app — виконується в браузері (Pyodide/WASM, є numpy, scipy 1.18, sympy 1.14, matplotlib), акаунт не потрібен, збереження — лише в local storage цього браузера; molab — хмарні ноутбуки з акаунтом, безкоштовно «поки розумно», 4 CPU / 32 GB, 12 годин сесія | частково |
| у Colab | офіційного шляху нема (запит у трекері Colab відкритий з 2024); хак через проксі порту — не для 60 студентів | — |
| конвертація | `marimo convert nb.ipynb -o nb.py`: перевизначення змінних конвертер лагодить сам — зайві стають `_імʼя`, ланцюжки `df`, `df_1`, `df_2`; назад — `marimo export ipynb --sort top-down`; експортований `.ipynb` починається клітинкою `import marimo as mo`, яку для Colab треба прибрати | так |
| перевірка робіт | `python nb.py` виконує в порядку залежностей; `outputs, defs = app.run()` повертає словник імʼя → значення; `app.run(defs={"CARD": …})` підставляє картку, якщо вона в окремій клітинці | так |
| лінтер | `marimo check` — помилки будови: кілька визначень, цикли | так |
| інтерактив | `mo.ui.slider` → усі залежні клітинки перераховуються; в Jupyter `interact` перевиконує лише свою функцію | так |
| редактори | VS Code — офіційне розширення; PyCharm — плагін команди marimo, «early preview» з липня 2026 | — |

Що робить конвертер із нашим ноутбуком лаби 1 (перевірено на `lab1-solved.hid.ipynb`): `rng` у трьох зірочках → `_rng`; циклові `i`, `k`, `xi` → локальні; наївне `S` у справі 4 (бо `S` уже є у справі 3) → `S_1`; `marimo check` без зауважень. Тобто з ноутбука Jupyter marimo-варіант робиться однією командою, але одна змінна отримує негарне імʼя — це лікується перейменуванням у джерелі або постобробкою.

## Що зручніше перевіряти

- **Зараз** перевірка — рядок `LAB1 <варіант> d1=…`, і вона однакова для обох форматів: студент друкує рядок, сайт або `check.py` його звіряє. Формат ноутбука тут ні до чого.
- **Якщо колись виконувати роботу студента сервером**: marimo — `app.run(defs=картка)` і прочитати змінні; Jupyter — papermill/nbclient і розбирати виводи клітинок. marimo простіший і детермінований (нема прихованого стану «у мене все працювало»). Для 60 студентів це не критично, поки є рядок відповідей.
- Готові грейдери для Jupyter (nbgrader 0.9.6, otter-grader 7.0) живі, але потребують JupyterHub або Docker-конвеєра — для Colab-студентів здачу однаково збирати самому.

## Ризики marimo для курсу

- Нова звичка для студентів і для викладача; підтримки в групі від одногрупників нема.
- 0.x: поведінка конвертера й лінтера ще змінюється; molab без гарантій; мобільний інтерфейс — відкрите питання; WASM-ноутбук тягне в браузер сотні мегабайтів.
- Два формати — подвійна підтримка: кожну правку шаблона треба перевіряти в обох.

## Рекомендація

1. **Лаба 1 цього тижня — Colab.** Нічого не міняти в шляху видачі.
2. **Варіант для marimo — зробити з того самого джерела й запропонувати як альтернативу** «для тих, хто хоче»: файл `.py` поруч із `.ipynb`, запуск локально (`uv run marimo edit lab1-marimo.py`) або в marimo.app без інсталяції; картка та сама, рядок відповідей той самий. Це коштує генератора в `tools/` і сторінки інструкції — зроблено для лаби 1 цією ж сесією, звіт — задача варіанта.
3. **Після лаби 1 — порахувати, скільки студентів обрали marimo**, і за цим вирішити формат за замовчуванням для лаб 2–5. Джерело лаб лишається одним (`labN-solved.hid.md`), тож зміна — це лише інший файл у видачі.
4. **Сайт** — єдине місце для картки й здачі в обох випадках ([T200](T200-P--ods-my-lab-design.md)); виконання роботи сервером — не зараз.
