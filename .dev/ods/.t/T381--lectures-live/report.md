## Вердикт

- **Усе з лекцій тепер на основному дев-сайті** `http://127.0.0.1:5035`: кольори лектора, «оригінал», сторінка «Зміни», пошук. Раніше це жило лише на стенді — тому ти не бачив ні кольорів, ні видів пошуку: код там був новий, а тексти в дев-базі — вересневі. Стенд зупинено.
- **Історія лекції — як ти просив:** перша версія — «початок · текст із презентації лектора, до вичитки», далі кожна правка окремою версією зі своїм словом і часом (8–11 на лекцію). «Крихти» — `Лекції › Лекція N › Історія`, адреса `/history`.
- **«Щось пішло не так» при редагуванні** — справжній баг: олівець біля заголовка, що починається з цифри («1. …»), ламав сторінку. Виправлено; ще один такий самий блок вискакував при переході з лекції на «Історію» — теж.
- **Кнопки-перемикачі**: під мишкою — блідий відтінок, натиснута — залита. Правило одне на обидва сайти.
- **Колір усередині формул повернуто**: 145 формул зі 162, де лектор фарбував частину (величину, яку формула вводить чи рахує); решта 17 уже мали свій колір від тега тексту.
- **Шапка лекції** й **панель лаб** — як ти описав; подробиці нижче.
- **На сервер нічого не їздило.** Команди — нижче, прогнані на копії «як сервер».

## Команди для сервера (завтра, по порядку)

Прогнано на копії бази, складеній так само, як серверна (`guide`, `media`, `lab_pages`, `lab_shapes` без історії): заливка — 18 секунд, повторний запуск нічого не шле.

```sh
cd "$HOME/Main Dropbox/Dev/Dev.v4/Nure/python-labs"

# 1. код: хук pre-push сам збере статику ods
git push origin ods

# 2. перезапуск API ods на сервері (нові маршрути й поля)
ssh -t vv3 sudo systemctl restart ods-labs-web

# 3. що поїде — лише читання
~/.venvs/python-labs/bin/python bin/content -t ods ls | grep -v '^  [+~] '
```

Третя команда має надрукувати (числа на 2026-11-20, ранок):

```text
сторінок 47: нових 0 · змінених 28 · тих самих 19
файлів до відправки: нових 323 · змінених 0
каталогів змін до відправки: нових 15 · змінених 0
перелік сторінок лаб: той самий або не чіпаємо
```

Якщо останнім рядком стоїть «код сайту: старий — історію лекцій ще не приймає» — сервер ще не взяв новий код: зачекай хвилину й повтори крок 2, потім 3. Заливка на старий код сама зупиниться з тим самим поясненням, нічого не зіпсувавши.

```sh
# 4. заливка: тексти лекцій з історією, виправлені тексти лаб, знімки слайдів, каталог змін, дані пошуку
~/.venvs/python-labs/bin/python bin/content -t ods push | grep -v ': new$'

# 5. перевірка: має бути «змінених 0 · нових 0» у трьох рядках
~/.venvs/python-labs/bin/python bin/content -t ods ls
```

Четверта друкує по рядку на лекцію (`lec01: updated · rev 7 · версій 7` …), по рядку на сторінку лаби й на каталог (`lec01: каталог змін · new`).

- **Базу цілком пушити не треба.** `vv db push` потрібен був раз — заради карток і списку потоку; контент їде цією командою скільки завгодно разів, і при студентах теж. Повторний db push стер би все, що зʼявилось на сервері після першого (входи, привʼязки бота).
- Найбільший запит — 0,78 МБ, тож нинішній ліміт сервера 1,1 МБ заливці не заважає (ліміт для ноутбуків лаби 3 — окрема справа з [T375](../T375--labs-1-3-clear/report.md)).
- Те саме для дев-сайту: `bin/content -t odsdev push` (ціль `odsdev` — у `.site/.env`).
