# T251 · Деплой ods: вибори перед стартом

`2026-11-01` · ❓ question

Контекст:
- огляд і репетиція — [T250](T250-P--ods-deploy-go.md); runbook — vps-infra [T76](../../../../../My/vps-infra/.dev/apps/ods-labs/.t/T76--ods-labs/plan.md); старі вибори [T181](T181-Q--ods-deploy-choices.md) Q1–Q6 — без відповідей, план іде за їхніми «a» (ручний `main:ods`, імена `ods-labs`/`ods_labs`/8035, окремий OAuth-клієнт, `db push`, токен агента одразу);
- мовчання = «a»; інший вибір — правка одного-двох рядків у логах T76 або маніфесті.

**Q1 — Крок 4e (`env.conf`) перед ods.** На vv3 `vv` досі зі старим `ENV_KEYS`; маніфест ods — у форматі `env.conf`.
- a) спершу довезти 4e: коміт незакомічених змін vps-infra з 2026-09-27 (+ `AGENT_TOKENS!` python-labs), push, `sudo vv self-update`, перевірка за log/4e, **разом із `unit apply` python-labs** (ліміт бота 256M → 384M, рестарт python-бота ≈15 с); маніфест ods приїжджає тим самим `self-update`, але окремим комітом — відкат точковий (рекомендую: `deploy` від `vv` не залежить, автодеплой python не зачіпається; місячний борг закривається);
- b) ods у старому форматі (`ENV_KEYS=…` в `app.conf`), 4e — колись (два формати на машині; секрети видно в редакторі під час `env edit`);
- c) як a, але `unit apply` python-labs не зараз — python-бота не рестартити.

> 

**Q2 — Колізія `GET /api/labs`** ([T238](T238-Q--ods-labs-2-5-questions.md) Q6): ядро (дедлайни, адмін) перекриває список лаб студента на ods → 403; смоук лаб 26/28. Лекцій не стосується, «Мою лабу» ламає.
- a) виправити зараз, до деплою: префікс ядра → `/api/deadlines` (`core/api/core/routes/labs.py` + три рядки `core/ui/api.js`), смоуки обох сайтів; їде на python з `main`, на ods — з `ods` (рекомендую: T238 казав «у тій сесії», але вона не жива, незакомічених чужих правок у дереві нема; це S);
- b) після деплою ods, окремим кроком;
- c) не чіпати — ods без «Моєї лаби» (варіантів у базі й так 0).

> 

**Q3 — Старі лаби в базі ods.** `lab1…lab5` — старі тексти; нові 1–5 ([T234](T234--ods-labs-2-5-ready/report.md)) на диску.
- a) лишити як є: активних студентів на ods ще нема (`GUIDE_READERS=active`), нові тексти — після деплою через `bin/guide -t ods push` або `content_io.py` (T238 Q5) (рекомендую);
- b) перед seed обгорнути тіла старих лаб у `<!-- … -->` — чернетка, бачить лише адмін;
- c) імпортувати нові `lab*-task.md` у локальну `ods` до seed (`content_io.py`, M — разом із заміною лаби 1).

> 

**Q4 — Перенос бази.**
- a) seed-копія `ods_seed` з `guide` + `media` (команда в T76 log/00 §0.6) → `./vv/bin/vv db push ods-labs vv3 --from ods_seed`; локальна `ods` не чіпається (рекомендую: dev-адмін і 1048 рядків дев-кліків на сервер не потрапляють фізично; повторювано);
- b) як у T180 блок 3: `drop` users/activity/events і `history` users у `ods`, потім `--from ods`.

> 

**Q5 — Гілка `ods` і два незапушені коміти `main`** (T248/T249 — бриф звітів, `reviews --dry`).
- a) `git push origin main main:ods` — python отримує T248/T249, ods стартує з того самого коміту (рекомендую, якщо T248/T249 готові до проду — вони твої й уже закомічені);
- b) `git push origin origin/main:refs/heads/ods` — `ods` від уже задеплоєного на python `4235a9c`; `main` пушиш окремо, коли захочеш.

> 

**Q6 — Мій доступ під час сесії.** Ключ vv3 під `v6u` — з passphrase, `AddKeysToAgent 1m`; `sudo` — твій пароль.
- a) як завжди: ти в `ssh vv3`, вивід мені (рекомендую — працює, і все, що міняє машину, лишається за тобою);
- b) + на час сесії `ssh-add -t 2h ~/.ssh/id_ed25519_vps_56429` — я сам читаю без `sudo`: `free -m`, `systemctl is-active`, health з `127.0.0.1:8035`, зовнішній смоук; менше копіювання;
- c) `NOPASSWD` sudo для `vv check`/`journalctl` — не раджу: розширює, що може будь-який процес під `v6u`, поки ключ в агенті.

> 

**Q7 — Бот на старті.** Памʼять vv3 — єдиний спільний ресурс; ods додає ≈375M (web 200 + bot 175).
- a) бот стартує в блоці 4 разом із сайтом (`vv start` піднімає обидва юніти), гейт `free -m` після: `available` > 250M — далі, інакше `systemctl stop ods-labs-bot` до рішення (рекомендую);
- b) спершу лише web (`systemctl start ods-labs-web`), бот — після `free -m`;
- c) бот не зараз: ods стартує без бота (вхід Google і лекції від нього не залежать), бот — коли буде памʼять або тариф.
