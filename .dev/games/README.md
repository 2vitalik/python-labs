# games — ігрові концепти: клітинне поле, каталог ігор, варіанти

Формат робіт студентів: ігри на клітинному полі за мотивами класики. Сусіди: завдання-цеглинки — [tasks](../tasks/README.md), ціни — [grading](../grading/README.md).

**Дальня мета вузла — лудопедія** (мрія Vitalik, 2026-08-17): єдина мова опису ігрового розмаїття світу без синтаксису — словник (картки) + морфологія (сутності+слоти) + граматика (речення КОЛИ→ЯКЩО→ТО) + корпус (приклади з реальних ігор, осі варіацій); той самий апарат описує і референсні ігри з YouTube, і роботи студентів · [T98](.t/T98-B--ludopedia.md). **Будівництво стартувало** 2026-08-18 ([T100](../.rounds/.t/T100-R--ludopedia-kickoff.md)): сутності, правила-речення і інбокс знахідок `/refs` уже живі в пілоті ([T101](../platform/.t/T101--ludopedia-core/report.md)).

## Матеріали

- Девʼять ігор-прикладів зі старого Notion — `data/v2/notion/games/` (Maze, Boulder Dash, New Ball Game, Lode Runner, Battle City, Mined-Out, Inertia, Bomberman, Pac-Man): задум, елементи, покрокові ігрові моменти.
- Ресерч-каталог ~40 зовнішніх grid-ігор у 7 сімʼях (штовхання, копання, аркади, тактики, thinky, курсорні, автомати) з лінками й ідеями механік · [T32](.t/T32-C--grid-games-catalog.md); шортліст кандидатів у приклади: Sokoban, Snake, Minesweeper, 2048, PvZ-лайт, Frogger.
- Пропозиція spec-моделі: гра = сума фрагментів обраних тасків, спека генерується системою (чек-ліст захисту, порівняння варіантів) · [T34](.t/T34-P--game-spec-model.md).
- База знань — **`data/wiki/games/`** (створено 2026-08-03): 17 чернеток ігор — девʼятка (зведена зі старого Notion) + шортліст T32 (Sokoban, Snake, Minesweeper, 2048, PvZ-лайт, Frogger) + парасолі нових класів (chess, paper-puzzles); карта класів — `data/wiki/games/_classes.md`.

## Корпус лудопедії · [T253](.t/T253--ludopedia-corpus/report.md) (2026-11-02)

- **`data/ludopedia/`** — 275 референсних ігор у 17 сімʼях-теках (`games/<сімʼя>/<slug>.md`), кожна за одним шаблоном: шапка (клас, осі, ⭐-лінки, теги-механіки, пропозиції до словників) → Суть → Поле → Сутності (роль, параметри) → Правила КОЛИ→ЯКЩО→ТО → Керування → Вікна/меню/HUD → Фічі поза полем → Варіації → Цікавинки для курсу → Мапа на каталог → Пропозиції → Джерела → Непевне. Навігація — `README.md` корпусу; живі індекси — `index/` (реєстр з ⭐-входами, механіки→ігри, пропозиції за правилом трьох, жнива по секціях, `card-examples.yaml` для Д3).

## Мова опису гри v2 · [T261](.t/T261-P--game-desc-v2-concept.md), код [T259](../platform/.t/T259--game-desc-v2/report.md) (2026-11-09)

- Опис гри — документ із шести частин: **поле** (розмір, сітка, тор, вид, гравітація, час, керування, шари) → **сутності** (роль із 20, параметри HP/життя/швидкість/броня…, стани, механіки-картки, правила про неї) → **правила** «КОЛИ → ЯКЩО → ТО» → **вікна й меню** (тип із 32, елементи, пункти → вікно/картка, карта переходів) → **гра загалом** (заявки за зонами, порядок тіку) → **чернетки** (картки без господаря). Форми з селектами, без синтаксису; «інше (словами)» легальне всюди.
- Словники — один модуль `app/api/models/vocab.py`: 20 ролей, 37 тригерів, 35 умов (з запереченням і предикатами пазлів), 67 ефектів, властивості поля, підказки параметрів; аргументи типізовані (сутність · вікно · число · текст · список), сутність у реченні — конкретна, «будь-хто» або сторона тригера А/Б. Той самий модуль валідує API, будує форми (`GET /api/vocab`) і рендерить речення для бота. Нові слова — правилом трьох, як було.
- Стани, фази й обмеження (T257) — не окремі таблиці: стани — імена на сутності + правила `set_state`/умова `state`; фази — список на грі + тригер `phase_start`; обмеження пазлів — умови `unique/sum/connected/…` у реченнях з тригерами `constraint_broken`/`all_constraints_met`. Перегляд — за реальними роботами семестру ([T262](.t/T262-Q--game-desc-v2-choices.md) Q7).
- **Еталон = меню** (Д4): `data/catalog/templates/<основа>.yaml` для всіх 17 базових ігор — поле, сутності зі статами/станами/картками, правила, вікна з меню, заявки — тією ж мовою (формат і правила — `templates/README.md`, перевірка — `validate.py`); «Почати з еталона» у «Моїй грі» наливає їх у гру студента, збіг назв не дублюється. Написали 4 Opus-агенти з файлів корпусу й текстів каталогу; числа з памʼяті позначені `(?)` у нотатках.
- Опис гри ≠ робота студента (T98): монетки живуть лише на заявках; вердикт викладача (зараховано/повернуто) — на заявці ([reports](../reports/README.md)).

## Класи ігор (прийнято) · [T49](.t/T49-B--game-classes.md), рішення [T54](../.rounds/.t/T54-R--kb-round-decisions.md)

- Перша вісь опису гри — клас за актором: **аватарні · курсорні · фігурні · пазли-розмітки**; усі чотири — **рівноправні напрями робіт** одразу (T53 Q1a).
- Решта осей: поле (квадрат/гекс/граф/вільне) · час (покрокове/real-time/статичне) · суперник (нема/AI/hot-seat) · інформація · випадковість · мета.
- Фігурні: база — hot-seat на двох + правила ходів/перемоги; AI-суперник — золоте завдання зверху (T53 Q2a).
- Пазли-розмітки: робота студента — плеєр пазлів (поле, ввід, перевірка, банк рівнів); генератор і розвʼязувач — золото (T53 Q3a).
- Нестандартні поля (гекс, вільні координати, графи) — тег-модифікатор «для сміливих», не окрема гілка (T53 Q4a).
