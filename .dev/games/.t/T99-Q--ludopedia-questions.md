# T99 · Питання по лудопедії

`2026-08-17` · ❓ question · концепт — [T98](T98-B--ludopedia.md); пілотні питання [T97](T97-Q--mechanics-session-questions.md) лишаються в силі окремо

**Q1 — Readback мрії.** Я правильно почув? (енциклопедія розмаїття з прикладами-джерелами · опис гри «комірками» до розуміння всієї механіки · той самий апарат для робіт студентів · рівень 3 формочками, не синтаксисом). Якщо десь мимо — напиши, що поправити.

> 

**Q2 — Ядро з чотирьох механізмів.** Приймаємо north star «словник (картки) + морфологія (сутності+слоти) + граматика (речення КОЛИ→ЯКЩО→ТО) + корпус (приклади+осі)» як напрям руху?
- a) так, це воно — рекомендую;
- b) частково — напиши, який механізм муляє;
- c) ще один захід думання (скажи, з якого боку).

> 

**Q3 — Розділення «опис гри ≠ робота студента».** Фіксуємо як архітектурний принцип (референсні ігри отримують той самий Part-шар; заявки — окремий шар зверху; еталонні описи стають меню для студентів)?
- a) так, фіксуємо — рекомендую;
- b) поки лише для робіт студентів, референси відкладаємо.

> 

**Q4 — Речення замість таблиці одразу.** E3 з [T96](../../platform/.t/T96-P--entities-slots-model.md) будувати одразу на загальній моделі `Rule` (КОЛИ→ЯКЩО→ТО), де UI v1 показує єдиний тригер «контакт A×B» (виглядає точно як таблиця взаємодій)?
- a) так, модель загальна одразу, UI нарощуємо словниками поступово — рекомендую (без переробки потім);
- b) ні, спершу простенька таблиця взаємодій, речення — окремою міграцією пізніше.

> 

**Q5 — Перший крок мрії.** Що робимо найближчим (після пілотних E1–E2)?
- a) Д2 «інбокс референсів» (кнопка «кинути лінк» — збирати починаєш одразу) — рекомендую;
- b) Д3 «приклади на картках»;
- c) Д4 «еталонні описи референс-ігор»;
- d) поки нічого — семестр, мрія після старту.

> 

**Q6 — Студенти як співавтори корпусу.** Золоте завдання «розклади улюблену гру в лудопедію» (аналіз чужої гри картками/реченнями + приклади в корпус) — додаємо в каталог чернеткою?
- a) так — рекомендую;
- b) не зараз.
