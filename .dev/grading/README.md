# grading — монетки, шкала балів, політики оцінювання

Оцінювання: 5 типів монеток (курс ×2), нелінійна шкала 60–100, пороги захисту, дедлайни, прозорість «зроби і набереш». Сусіди: ціни завдань — [tasks](../tasks/README.md), захисти — [defense](../defense/README.md).

Шапка:
- Оновлено: 2026-08-16
- Інтегровано: [T08](.t/T08-Q--grading-open-questions.md) Q1–Q2 (перші рішення, див. нижче)
- Не інтегровано: [T07](.t/T07-C--coins-system.md) (формалізація монеток; пропозиція «монетки=кількість, ворота=якість»; анти-ізмор слотами)

## Зафіксовані напрями (ще без моделі)

- **Бали лише ростуть** (T08 Q1a, 2026-08-16): жодних штрафів і знижень — монетки тільки накопичуються; «ворота якості» вирішують стелю, а не віднімають.
- **Захистів — мінімум** (T08 Q2, свій варіант, 2026-08-16): студентів багато (6 груп), захист довгий (~година+), тому захищаються лише охочі на 80+; формальні слоти/тиждень поки не потрібні — механізм проєктуватимемо від «як мінімізувати кількість захистів», а не від анти-ізмору.

- **Деградуючі ціни повторів** (Vitalik, [T70](../.rounds/.t/T70-R--catalog-decisions.md), 2026-08-05): повторювані завдання (напр. додаткові рівні) — перші ~5 повторів повна ціна, наступні дешевше, далі ще дешевше; «робити можна багато, але без фанатизму» — повтори не повинні ламати систему і робити перекоси (був неприємний досвід). У каталозі v1 поки просте `max_count`; формула знижок — сюди, разом із моделлю обміну.
