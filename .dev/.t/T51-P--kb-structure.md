## Принципи

- База знань (далі КБ) — **чернетковий простір контенту курсу**, не процесу. Правило межі з `.dev/`: «те, що колись побачить студент у каталозі → КБ; те, як ми будуємо систему → `.dev/`». Тікети лишаються трейлом «чому», КБ — сировиною «що».
- Вільний режим без бюрократії: жодних frontmatter, ID, обовʼязкових полів — чистий Markdown зі списками й підзаголовками. Дисципліна лише у двох місцях: імена файлів і граматика пунктів-завдань — щоб майбутня конвертація в каталог була механічною.
- Версії — git-історія, без папок-версій: `v1/v2/v3` у `data/` — знімки *імпортів*, їм версійність потрібна; КБ — жива база, «як було» їй дає git. Великий рефакторинг структури — просто окремий коміт.
- КБ редагована обома (тут NO-EDIT не діє — це не тікети): ти пишеш вільно будь-де, я зводжу і підтримую охайність.

## Пропонована структура

```
data/kb/
├─ README.md          # що це, конвенції, межа з .dev, статус гілок
├─ games/
│  ├─ README.md       # індекс: гра → файл · клас · зрілість (💭/🌿/✅)
│  ├─ _classes.md     # класи й осі опису (робоча копія T49)
│  ├─ maze.md         # одна гра = один файл
│  ├─ sokoban.md
│  ├─ chess.md        # нова гілка: файл-парасоля, поки матеріалу мало
│  └─ paper-puzzles.md
└─ tasks/
   ├─ README.md       # індекс груп + граматика пунктів
   ├─ _map.md         # карта зон/підзон (робоча чернетка T50)
   ├─ entities.md     # одна зона = один файл
   ├─ game-logic.md
   ├─ levels.md
   ├─ interface.md
   ├─ code.md
   └─ support.md
```

- Імена файлів EN-kebab, вміст UA — симетрично пропозиції «назва UA + slug EN» ([T37](../tasks/.t/T37-Q--taxonomy-questions.md) Q5).
- Гранулярність: **файл-на-гру** і **файл-на-зону**; виріс за ~200 рядків → розгортається в папку (`chess.md` → `chess/README.md + variants.md + …`). Стартувати одразу папками не варто — порожня ієрархія демотивує наповнення.
- Файла `algo.md` свідомо нема — за [T33](../tasks/.t/T33-B--task-taxonomy.md) алгоритмічність = тег ⭐ у пунктах; якщо [T37](../tasks/.t/T37-Q--taxonomy-questions.md) Q2 вирішиться інакше, додати файл дешево.
- `_`-префікс — службові карти гілки (не одиниці контенту); індекси README тримають список файлів зі статусом зрілості: 💭 чернетка · 🌿 зводиться · ✅ стабільне (готове до конвертації).

## Формат файла гри (скелет)

```markdown
# Sokoban — штовхання ящиків на цільові клітини
Клас: аватарна · Поле: квадрат · Час: покрокове · Суперник: нема

## Ядро
2–3 речення правил — що робить гравець і коли перемога.

## Можливості (сировина для tasks/)
- **назва можливості** — пояснення, лише якщо неочевидно
- …

## Варіації і підігри
## Джерела
## Сире
```

- Шапка-рядок осей — з [T49](../games/.t/T49-B--game-classes.md); «Можливості» — головна секція: кожен пункт потім стає завданням чи сімʼєю в tasks-гілці або в каталозі.
- «Сире» — буфер для швидких вкидів (твоїх, з зовнішніх джерел, зі старих матеріалів) без вимог до форми.

## Граматика пункту-завдання (tasks/)

- Одна форма скрізь: `- **коротка назва** — пояснення (лише якщо неочевидно)`; варіанти сімʼї — вкладеними пунктами під карткою; підгрупи — заголовками `##`/`###`.
- Легкі маркери в кінці рядка: `⭐` — алгоритмічне золото; `` `chess` ``/`` `avatar` `` — застосовність до гри чи класу; без маркерів = універсальне.
- Це рівно та «коротка назва + пояснення до неочевидних», яку ти описав, і водночас парсибельний формат: конвертація «пункт → картка каталогу» потім робиться скриптом + ручною правкою, як у v3.

## Зведення джерел («ти щось додаси, я щось опишу»)

- Тіло файла — **єдиний зведений текст**, підтримую я; різнорідні шматки (твої думки, витяги з вікі/Notion, ідеї з чату) падають у `## Сире` або просто в чат — я вплавляю їх у тіло і чищу буфер тієї ж сесії.
- Дзеркало нашого циклу `>`-відповідей, тільки без заморозки: КБ — жива, історію правок тримає git, а не NO-EDIT.

## Стартове наповнення (після твого «ок» — [T52](T52-Q--kb-questions.md))

- `games/`: чернетки девʼятки з `data/v2/notion/games/` + шортліст [T32](../games/.t/T32-C--grid-games-catalog.md) (Sokoban, Snake, Minesweeper, 2048, PvZ-лайт, Frogger) + парасолі нових гілок (`chess.md`, `paper-puzzles.md`) — генерую я, правиш ти.
