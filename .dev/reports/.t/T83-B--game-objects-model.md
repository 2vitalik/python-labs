## Ключова ідея: три шари замість двох

Твої «вікна + елементи + функції» природно розкладаються, якщо між каталогом і заявками додати шар **обʼєктів гри**:

- **Каталог** (вже є): типи завдань з цінами — «головне меню», «слайдер гучності», «зміна гучності», «патрулювання ворога».
- **Обʼєкти гри** (нове): іменовані екземпляри в конкретній грі студента — вікно «Налаштування», меню «Головне», сутність «Ворог-танк», рівень «3». Обʼєкт має тип, назву, короткий опис, скриншот(и).
- **Заявки** (концепт є, [T09](T09-C--reports-concept.md)): «обʼєкт X реалізує картку Y» — монетки живуть на цій звʼязці; життєвий цикл незмінний: заявлено → перевірка → зараховано.

Чому обʼєкти, а не просто плоский чек-ліст карток:

- **Скриншот кріпиться до обʼєкта один раз** і покриває всі його заявки: один скрин вікна налаштувань доводить і вікно, і всі 5 елементів на ньому. Це головний механізм зняття тягаря — інакше «скриншот на кожну заявку» вбʼє задоволення.
- **Наочність задарма:** сторінка гри студента = галерея вікон зі скриншотами + список механік + монетний підсумок. Читається як паспорт гри — і для захисту, і як промо (синергія з картками support: «сторінка гри» фактично генерується системою).
- **Чесність:** другий інтерфейс тієї самої функції — це друга заявка інтерфейсної картки на іншому обʼєкті (повторювана картка, 🔁/`max_count`, далі деградація цін за [T70](../../.rounds/.t/T70-R--catalog-decisions.md)); сама функція-можливість — окрема картка, зараховується один раз. Твій приклад із гучністю лягає без милиць.
- **Різниця варіантів** ([T34](../../games/.t/T34-P--game-spec-model.md)) виходить безкоштовно: порівняння двох ігор = порівняння наборів обʼєктів і заявок.

## Вікна і меню — конкретна модель

- **Вікно:** тип з каталогу (підзона interface/menus вже має main-menu, pause-menu, end-screen, confirm-dialog; список типів добудувати: splash/лого, екран налаштувань, вибір рівня, магазин…) + власна назва + скриншот. Нестандартне вікно — картка `custom-window` з ручною ціною (пайплайн «запропонувати завдання» — хвіст [T05](../../tasks/.t/T05-C--task-catalog-concept.md)).
- **Елементи вікна:** чіпи-чекліст на формі вікна — кожен чіп = заявка інтерфейсної картки (слайдер гучності, перемикач музики, вибір теми, вибір аватару, розмір поля…). Для цього в каталог треба сімʼю «елементи налаштувань» з дітьми — можу засіяти чернетками за командою.
- **Функції за елементами:** окремі картки-можливості (зміна гучності застосовується, тема реально перемикається…). УІ-автопідказка: клацнув елемент «слайдер гучності» → система пропонує заявити й функцію, якщо ще не заявлена. Один клік замість пошуку по каталогу.
- **Меню:** обʼєкт з упорядкованими пунктами. Пункт = назва + опційна **дія**: `→ вікно` (посилання на інший обʼєкт) · `→ функція` (посилання на заявку) · просто текст. Пункт коштує найдешевшу 🌱, дія оцінюється своєю карткою.
- **Граф переходів — безкоштовний вау-ефект:** якщо пункти знають цільове вікно, система малює діаграму навігації гри автоматично (вікна-вузли, стрілки-переходи). Красиво на захисті, а ще виявляє вікна-сироти, до яких нема шляху. Жодних додаткових даних збирати не треба.

## Докази (evidence) — атрибут картки, не глобальне правило

Рівень доказу визначає картка каталогу (розвиток «вимог до звіту» з [T05](../../tasks/.t/T05-C--task-catalog-concept.md)):

- `none` — видно з коду/на захисті (архітектура, тести, типізація);
- `screenshot` — статичні речі: вікна, меню, HUD, рівні;
- `gif` — **динаміка: рух, анімації, взаємодії — статичний скрин їх не доводить.** Короткий gif/запис екрана 5–15 с; студенти таке вміють (peek/licecap/вбудований запис ОС);
- `link` — місце в коді (алгоритмічні ⭐-картки, де важливий сам код).

За замовчуванням вимоги мінімальні; скриншоти датуються і не «протухають» після зарахування ([T09](T09-C--reports-concept.md)).

## GitHub-посилання: три варіанти

- **a) Руками перма-лінк.** Студент тисне `y` на GitHub → URL з SHA коміта і рядками. Надійно, нуль розробки; але морока, і студенти плутатимуть гілку/коміт (лінк на гілку згниє після пушів).
- **b) Автоматом AI по репо** ([T15](../../github/.t/T15-C--github-integration.md)): при заявці агент шукає в репозиторії і пропонує місце. Мінімум тягаря, миттєвий фідбек, барʼєр фальшивим заявкам; але потребує моделі доступу (відкрите [T16](../../github/.t/T16-Q--github-open-questions.md) Q1) і це окрема фаза розробки.
- **c) Гібрид — рекомендую:** поле лінка на заявці опційне; обовʼязкове лише для ⭐/золотих карток (де код і є суттю). Система **нормалізує** будь-який вставлений GitHub-URL у коміт-пін (через API підміняє гілку на SHA, перевіряє, що файл/рядок існує) — студенту досить скопіювати адресний рядок. AI-передперевірка доганяє пізнішою фазою і починає пропонувати лінки сама — поле вже є, воно просто заповнюється легше.

## Принцип тягаря: «клац, а не форма»

- Створити вікно = вибрати тип (1 клік) + назва + drag-and-drop скриншота. Елементи = чіпи на тій самій формі. Функції = автопідказки. Мета: повністю заявити типове вікно ≤ 1 хв.
- Монетний лічильник росте на очах прямо у формі («+🌱+🥉 за це вікно») — заявляти стає приємно, що і є твоя третя вимога.
- Анти-фрод не через тягар, а через життєвий цикл: монетки лише за зараховане ([T09](T09-C--reports-concept.md)), AI-передперевірка — пізніше.

## Відкинуті альтернативи

- **Плоскі заявки без обʼєктів** (просто чек-ліст каталогу + скриншот на заявку): простіше в реалізації, але дублювання скриншотів, нема сторінки-паспорта, нема графа переходів, повторні екземпляри інтерфейсу не виразити. Відпадає.
- **Студентський YAML/JSON-файл як джерело:** усе через інтерфейс; файл — лише **експорт-артефакт** (YAML/PDF зі стану системи, [T09](T09-C--reports-concept.md)). Це твоє ж рішення з [T82](../../.rounds/.t/T82-R--game-desc-braindump.md), фіксую.
- **Вільні вікна без типів з каталогу:** втрачається ціна і чек-ліст; свобода лишається через картку `custom-window`.

## План руху (пропозиція, кроки ≠ дедлайни)

1. **«Моя гра» v1** (після відповідей [T84](T84-Q--game-objects-questions.md)): студент обирає гру-основу з каталогу ігор → додає вікна (тип + назва + скриншот) і меню з пунктами → сторінка гри з галереєю. Монетки поки довідково.
2. **Заявки і гаманець:** заявки з обʼєктів + заявки без обʼєкта (код/супровід/механіки списком), стани заявлено/зараховано, черга перевірки для тебе.
3. **Докази повністю:** gif, нормалізація GitHub-лінків, вимоги на картках, граф переходів вікон.
4. **Пізніше:** структуровані механіки ([T85](../../games/.t/T85-B--mechanics-formalization.md) рівень 1–2), AI-передперевірка по репо, деградуючі ціни ([T08](../../grading/.t/T08-Q--grading-open-questions.md)), експорт YAML/PDF.

Кроки 1–2 незалежні від монетної математики: поки [T08](../../grading/.t/T08-Q--grading-open-questions.md) без відповідей, ціни показуємо довідково, як уже робить каталог.
