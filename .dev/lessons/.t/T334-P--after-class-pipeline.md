## 1. Коротко

- Головна знахідка: **після пари майже все вже лежить на твоєму Mac.** Zoom складає в `~/Documents/Zoom/<дата час тема>/` шматки відео, субтитри всього запису, збережений транскрипт і чат; Wispr Flow тримає свої зустрічі локально. Ключі й API для цього не потрібні.
- Зроблено три команди: `bin/lesson scan` (що на Mac ще не зібрано), `collect <дата>` (чернетка заняття з частинами й сирими джерелами), `video <дата>` (шматки запису на Drive і в Telegram, посилання — у частини).
- Чого бракує до «без рук»: одноразові входи (Drive, бот-завантажувач), рішення, де крутиться обробка, і тригер «пара скінчилась».
- Відвідування без адміністратора — лише звіт CSV із сайту Zoom: один клік на пару ([T336](T336-C--zoom-no-admin.md)).

Що `collect` робить сам:
- знаходить теку запису за датою й темою; кілька тек одного дня (зустріч перезапускали) зводить в одне заняття;
- рахує шматки запису з годинниковим часом: рядок субтитрів шматка знаходиться серед субтитрів усієї зустрічі — похибка секунди;
- шматок без жодного слова позначає перервою; коротший за хвилину пропускає;
- кладе в `raw/`: `zoom.txt` (збережений транскрипт з іменами), `zoom-cc.txt` (субтитри всього запису), `chat.txt`, `wispr.txt` (зустрічі Wispr Flow за цей час, з годинником);
- створює на сайті чернетку з частинами — або доповнює наявне заняття, не чіпаючи частин, які ти правив руками;
- попереджає про несконвертований запис.

- **Субтитри запису є завжди й на весь час** — це надійна основа «коли й що». Імен у них нема.
- **Транскрипт з іменами** залежить від того, чи ти натиснув «Save transcript», і обривається на мить натискання. Із шести пар повний — у двох. Це найслабше місце, і його закриває одне налаштування Zoom ([T336](T336-C--zoom-no-admin.md) §2).
- **Wispr Flow** покриває від третини до всієї пари й знає, де говорив ти (мікрофон), а де інші.
- ⚠️ `2026-11-06 20.13.50 Python ЦПО` — запис не сконвертовано: відкрий Zoom → Recordings → Convert, поки сирі файли на місці.

## 4. Обробка: де їй крутитись

Три виходи, які ти назвав, тепер три тексти заняття: **транскрипт**, **докладний звіт** («📖 Докладно», для тих, хто не був) і **конспект** (коротко, з розділом «Важливо»). Правила — в skill `/lesson`: карта покриття джерел, відрізання перерв і запису після кінця, частини дня, приватні частини окремими файлами.

| Варіант | Як виглядає для тебе | Ціна | Коли |
|:--------|:---------------------|:-----|:-----|
| **A. Як зараз** | кажеш агентові «зведи 10 листопада» | підписка | вже працює |
| **B. Одна команда на ноутбуці** | `bin/lesson auto <дата>`: collect → зведення через `claude -p` → push чернетки → алерт «глянь і опублікуй» | підписка | S — рекомендую наступним |
| **C. Сам після пари** | launchd стежить за текою Zoom: запис сконвертувався → варіант B без тебе | підписка | S поверх B; встановлення — твоя команда |
| **D. На сервері** | кнопка «Зібрати» на сторінці: сервер бере джерела з бази й кличе модель через API | ≈ $1–3 за пару на Opus 5.5, потрібен ключ API | M; коли правила устояться на 5–6 парах |

- Рекомендую **B, потім C**: записи й джерела фізично на ноутбуці, туди ж їх не треба завантажувати; на сервер іде лише готовий текст і посилання.
- **D** має сенс, коли джерела приходять не з ноутбука (хмарний запис Zoom, Plaud) або коли обробку має запускати не твій Mac. Ключ API той самий, що чекає для ШІ-помічника (T293 Q7).
- Правда про B і C: `claude -p` за підпискою на власному ноутбуці працює, але це не гарантований сервіс — ліміт підписки може зʼїсти чергу з кількох пар (T265). Тому результат завжди чернетка, а не публікація.
