## 1. Відповіді на твої питання

- **Чи можуть боти слати відео?** Так, але не через звичайний Bot API: там стеля 50 МБ на файл (20 МБ за посиланням), і за 2025–2026 вона не змінилась. Запис пари — 100 МБ – 1,5 ГБ.
- **А як тоді?** Бот, який говорить із Telegram напряму (протокол MTProto, бібліотека Kurigram), а не через HTTP-шлюз, заливає до ≈ 2000 МБ. Це той самий бот із BotFather, просто інший спосіб підключення. Особистий акаунт не задіяний.
- **Без збереження у файл, запитом через сайт?** Технічно можливо, але гірше за все інше: відео йде двічі (ноутбук → сервер → Telegram), nginx за замовчуванням ріже тіло запиту на 1 МБ і буферизує його на диск, обрив означає почати спочатку. Відео вже лежить на ноутбуці — звідти й заливати. Сайту потрібне лише посилання.
- **«Від мого імені»?** Можна: той самий скрипт входить як ти (код із Telegram і пароль 2FA — раз). Ліміт 2 ГБ, з Premium 4 ГБ. Але файл сесії дає повний доступ до акаунта, а Telegram сповільнює заливку акаунтам без Premium після місячного обсягу. Тому це запасний шлях, не основний.
- **Google Drive: папка, завантаження, посилання?** Так, через `rclone` (він у тебе стоїть): створити теку дня, залити шматки, отримати посилання на кожен файл. Вхід у Google — один раз.

## 2. Рекомендований шлях

**Одна команда після пари — або нуль, коли буде автозапуск ([T334](T334-P--after-class-pipeline.md) §4):**

```
bin/lesson video 2026-11-10
```

Що вона робить для кожного шматка запису, який має частину заняття:

1. **Google Drive** — `rclone copyto` у теку «<дата> <назва>» всередині спільної теки. Теку «Записи пар» ти один раз розшарюєш «усім, хто має посилання» (або лише домену університету) — нові теки й файли успадковують доступ, скрипт нічого не шарить.
2. **Telegram** — бот-завантажувач шле відео в гілку групи з підписом «дата · частина · час»; перед тим файл перепаковується без перекодування, щоб грав одразу, і з нього береться мініатюра.
3. **Сайт** — обидва посилання лягають у частину заняття; студент на сторінці дня бачить кнопки «Telegram» і «Google Drive» біля кожної частини.

Винятки, закладені в код:
- **приватна частина** (індивідуальний захист) у Telegram не йде ніколи; на Drive — в окрему, нерозшарену теку, з посиланням лише на цей файл; посилання бачить лише її студент;
- **перерва** нікуди не йде;
- чого не налаштовано — те пропускається зі словами «не налаштовано»; `--dry` лише каже, що куди піде.

Чому окремий бот-завантажувач, а не бот сайту: бот сайту працює на сервері через звичайний Bot API. Підключати його ж із ноутбука іншим способом — ризик для його оновлень. Новий бот у BotFather — хвилина.

## 3. Запасні шляхи

| Шлях | Що робиш після пари | Коли брати |
|:-----|:--------------------|:-----------|
| Той самий скрипт від твого імені | нічого або одна команда | бот-режим повільний або файл > 2 ГБ |
| `tdl up` (готова програма, вхід QR-кодом) | одна команда | не хочеш Python-бібліотеку; посилання тоді ловить бот сайту |
| Перетягнути файли в гілку руками | перетягнути | коли все зламалось; бот-адмін бачить повідомлення й може сам записати посилання на сайт (S) |
| Dropbox замість Drive | нічого нового: `rclone` для Dropbox у тебе вже працює | Drive не налаштований або нема місця |
| YouTube «за посиланням» | — | найзручніший перегляд (якість, «з цієї хвилини», автосубтитри українською); з 2 листопада 2026 заливка через API більше не замикається в «приватне». Але посилання не обмежити доменом, у записі голоси студентів, потрібна верифікація каналу телефоном. Лише якщо скажеш |

## 4. Цифри й пастки

- **Місце.** Чотири пари «Python Labs» — це 2,1 ГБ відео; за семестр ≈ 6–8 ГБ. Особистий Google — 15 ГБ на все. Університетський — спільний пул закладу, квоту ставить адміністратор: подивись свою на `drive.google.com/settings/storage` до вибору акаунта.
- **Вхід у Google не на тиждень.** Спільний ключ `rclone` для Drive Google вимикає протягом 2026 року — потрібен власний OAuth-клієнт. Поки він у статусі «Testing», вхід живе 7 днів; треба натиснути «Publish app» (для себе верифікація не потрібна).
- **Ліміт 2000 МБ для бота** — висновок із двох джерел (сервер Bot API дає 2000 МБ тим самим протоколом), не пряма цитата (?). Найбільший твій шматок — 620 МБ, запас є; перша заливка це підтвердить.
- **«З цієї хвилини».** Посилання Telegram розуміють `?t=754` і в приватних групах; у Drive є «Copy link to this time». Чи відкривається це на телефоні студента — перевірити на першому відео (?); тоді рядки «Теми» конспекту зможуть вести у відео (S).
- **Швидкість.** Заливка 600 МБ ботом — хвилини, не секунди; бібліотека ставиться в окреме оточення зі швидким шифруванням.
- **Посилання Telegram відкриє лише учасник групи** — це добре для приватності й погано для того, хто ще не в групі.

## 5. Від тебе один раз

**Telegram (≈ 10 хв):**
1. <https://my.telegram.org> → «API development tools» → створити застосунок → `api_id`, `api_hash`.
2. @BotFather → `/newbot` → окремий бот для записів → токен.
3. Додати бота в групу курсу адміністратором.
4. Посилання на гілку для записів: правою кнопкою на гілці → «Копіювати посилання» → `t.me/c/<група>/<гілка>`.

**Google Drive (≈ 15 хв):**
1. Обрати акаунт (особистий чи `@nure.ua`) і глянути квоту.
2. Google Cloud Console: новий проєкт → увімкнути Google Drive API → екран згоди → клієнт «Desktop app» → «Publish app».
3. `rclone config` → новий remote `gdrive`, тип `drive`, свої client ID і secret, scope `drive.file` → вхід у браузері.
4. `rclone mkdir "gdrive:Записи пар"` і розшарити цю теку у вебі; `rclone mkdir "gdrive:Захисти"` — її не шарити.

**Файл `~/.config/python-labs/video.env`** (поза Dropbox — у ньому токен):

```
DRIVE=gdrive:Записи пар
DRIVE_PRIVATE=gdrive:Захисти
TG_API_ID=…
TG_API_HASH=…
TG_UPLOADER_TOKEN=…
TG_CHAT=-100…
TG_TOPIC=…
```

Потім: `bin/lesson -t dev video 2026-11-10 --dry` → подивитись, що куди піде → без `--dry`. Перший запуск я перевірю разом з тобою: поля відповіді Telegram і формат посилань звірені з документацією, але не з живим сервісом.
