## Що ми хочемо від звіту

Три питання викладача, у порядку важливості:

1. **Що це за код** — гра на клітинному полі, як просить лаба · вправи з тем без гри (трек «60» у `score.md`) · щось інше · порожньо. Зараз цього поля нема — вердикт `partial` не відрізняє «гра, недороблена» від «вправи без гри».
2. **Які з шести обовʼязкових завдань є** на зрізі до дедлайну — з доказом `файл:рядок`. Зараз є лише підсумковий вердикт; «4/6» у клітинці каже більше й читається швидше за абзац.
3. **Сигнали процесу і питання на захист** — ритм комітів, один великий коміт, зсув дат, згенерований на вигляд код; 3–5 питань по їхньому коду. Це вже є в тексті звіту й там і лишається: текст, не поля.

Додаткові завдання (5 груп синтаксису) — лишаються текстом у звіті: на зрізі 27.10 вони другорядні, а «використано зі смислом» усе одно вирішує захист.

## Поля — що лишається, що додається

| Поле | Було | Стає | Навіщо |
|:--|:--|:--|:--|
| `commit` | ✓ | ✓ | зріз, на який дивились; `stale`, якщо зріз змінився |
| `verdict` | ✓ | ✓ | `done` · `partial` · `none` по обовʼязкових на зрізі — те, що рахує стан клітинки |
| `head`, `head_verdict` | ✓ | ✓ | HEAD, якщо після зрізу комітили: 🕒 «зроблено після дедлайну» |
| `summary` | ✓ | ✓ | один рядок для клітинки й колонки |
| `report` | ✓ | ✓ | Markdown: обовʼязкові з доказами, додаткові, сигнали, питання |
| **`kind`** | — | `game` · `tasks` · `other` · `none` | питання 1 |
| **`required`** | — | список `done`/`partial`/`none` по кожному обовʼязковому завданню лаби (6 для лаби 1) | питання 2; клітинка «4/6» |

Нічого іншого не додаємо: бали, стелі, «ШІ-код» — не поля звіту (бали — [grading](../../grading/README.md), захист покаже).

## Бриф агента

Живий документ [review.md](../review.md): що отримує рецензент (зріз, HEAD, сторінка лаби), правила (лише читання, доказ на кожне твердження, не вигадувати), точна шапка, структура тіла, визначення `kind` і `required`. Один субагент (Opus) на репозиторій, код не запускається.

## Шлях

1. `bin/repos auto` (щогодини) — клони свіжі, факти на сайті.
2. `bin/repos cut 1 --checkout` — робоче дерево кожного на останньому коміті до **його** дедлайну (подовження враховані).
3. Субагенти пачкою → файли `data/reviews/<нік>/lab1.md` (поза git).
4. **`bin/repos reviews --dry`** (нове) — лише читає шапки й друкує таблицю: нік · kind · required · вердикт · summary, нічого не шле. Vitalik дивиться файли й таблицю.
5. `bin/repos reviews` — на сайт. Окремий крок, як і просив Vitalik.
6. Висновок по потоку — C-тікет у github: по групах скільки `game`/`tasks`/`other`/`none`, скільки `done`/`partial`/`none`, хто `other`/`none` поіменно, помітні сигнали; рядок у README вузла.

## Що міняється в коді (після «ок»)

- `Review.kind: Literal["game","tasks","other","none"] | "" = ""`, `Review.required: list[Verdict] = []`; `ReviewIn` те саме; `api()` віддає обидва. Старі звіти без полів — порожньо, UI не ламається.
- `bin/repos reviews`: читає `kind`, `required` (слова через пробіл) з шапки; `--dry`.
- UI: рядок звіту в `LabEdit.vue` і шапці `LabReport.vue` — «🤖 звіт: частково · 4/6 · гра»; `labs.js` — те саме в підказці клітинки; `tableCols.js` — колонки `lab1.kind` (enum, фільтр чіпом) і `lab1.required` («4/6»).
- `smoke_labs`: звіт із `kind`/`required` зберігається й повертається; без них — як було.
- Деплой: API з перезапуском; бот не мінявся.
