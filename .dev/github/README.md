# github — інтеграція з git/GitHub: доступ до коду, історія, дедлайн-зрізи

Інфраструктурний вузол: доступ до репозиторіїв студентів, їх історія як факти, дедлайни лаб і стани «вклався / ні», звіти агента по коду. Споживачі: [grading](../grading/README.md) (що дає дедлайн у балах), [reports](../reports/README.md) (верифікація заявок), [remarks](../remarks/README.md) (підказки цілей), [tgbot](../tgbot/README.md) (`/due`, алерт 📅).

## Модель доступу

- **Особисті репозиторії студентів + викладач-колаборатор** (T16 Q1 «b», 2026-07): студент створює приватний репозиторій, один на всі лаби, і додає `2vitalik` колаборатором (підказки в профілі на сайті); посилання — поле `User.github`.
- **Git обовʼязковий** (T16 Q2): без git — лише мінімальна оцінка.
- **Історія комітів — сигнал процесу, не вирок** (T16 Q3 «a»): ритм комітів, один великий коміт перед дедлайном, зсув дат — аргумент на захисті. Політика щодо ШІ-коду — дозволено з розумінням, захист покаже (T16 Q4).
- Доступ з машини викладача — SSH-ключем `2vitalik` (`git@github.com:<user>/<repo>.git`), без токенів; на сервері потім — deploy key бота або machine user ([T48](.t/T48-C--collaborator-access.md) c/d).

## Репозиторії на машині — `bin/repos` ([T235](.t/T235-P--lab-deadlines-design.md) §1, [T237](.t/T237--lab-deadlines-v1/report.md))

- `bin/repos [-t prod|dev] sync` — студенти з посиланнями з сайту → `data/repos/students.json`; друкує, що змінилось (`+` нове, `~` інше, `-` зникло).
- `bin/repos pull [нік…]` — клонує нові, решту `fetch` + `checkout --detach origin/HEAD` (переписана історія чи інша гілка не ламає); по 6 паралельно; помилка доступу записується і не зупиняє.
- `bin/repos status [нік…]` — рядок на студента: група · комітів · перший … останній · гілка · репозиторій, або помилка.
- `bin/repos push` — факти всіх репозиторіїв на сайт одним запитом (`PUT /api/repos`): посилання, гілка, HEAD, помилка, **журнал комітів** з `seen` — коли ми коміт побачили вперше.
- `bin/repos cut <лаба> [нік…] [--checkout]` — останній коміт до дедлайну лаби (дедлайн — з сайту, з подовженнями); `--checkout` — робоче дерево зрізу в `data/repos/.cut/<нік>/lab<N>/` для ревʼю.
- `bin/repos reviews [нік…]` — файли `data/reviews/<нік>/lab<N>.md` → сайт.
- Git-механіка — `core/api/core/repos.py` (лише stdlib): її ж візьме сервер, коли клонування переїде туди. `data/repos/`, `data/reviews/` — у `.gitignore`.
- Журнал комітів живе на сервері (`Repo.commits`): «останній до дедлайну», «комітів у вікні лаби» сайт рахує сам для будь-якого дедлайну чи подовження — без повторного запуску скрипта.
- Дата коміту — слово студента (`--date`, зсув годинника; GitHub час пушу не віддає): `seen` зі щоденного `pull` — верхня межа, коли коміт реально зʼявився; різниця author/committer зберігається (`authored`).

## Дедлайни і стани клітинки ([T235](.t/T235-P--lab-deadlines-design.md) §2)

- `Deadline {lab, at, groups}` — дедлайн лаби для всіх (`groups` порожні) або для вибраних груп; конкретніший перемагає; ставиться на `/deadlines` (✏️ у шапці колонки), час за умовчанням 23:59 Київ; кількість лаб — `LABS` у `site.env` (5).
- `LabMark {user, lab, until, open, reason, met, note}` — слово викладача про студента й лабу: подовження до дати (`until`) або «поки невідомо» (`open`), причина; вердикт `met` — вклався / не вклався / як рахує сайт; нотатка. Кожна зміна — `history` + алерт 📅 `due`.
- Стан клітинки (`core/labs.py`, пріоритет: слово викладача → звіт агента → факти): ✅ `ok` вчасно · 🕒 `late` зроблено після дедлайну · 🟡 `partial` частково на зрізі · ❌ `miss` не вклався · ⏳ `open` подовжено без дати · ⏱ `wait` дедлайн попереду · 🔍 `check` минув, вердикту нема · 🚫 `norepo` без посилання · ⚠️ `noaccess` репозиторій не клонується · — `nodue` дедлайн не заданий.
- Факти в клітинці завжди: комітів до дедлайну / у вікні лаби (від попереднього дедлайну) / після; останній коміт до дедлайну; ✍ — стоїть слово викладача.
- Сторінки: `/deadlines` (адмін; групи згортаються, чіпи груп і станів, клік по клітинці — редактор подовження/вердикту/звіту під рядком, 🐙 — стан репозиторію, Σ по лабах, на всю ширину); картка «Лаби» на `/students/<нік>/edit` — ті самі рядки для одного студента.
- Бот: `/due <лаба> <дата | ? | -> [причина]` — з чату зі студентом (Chat Automation, команда зникає як `/hide`), з форуму (ефемерна; відповіддю або `/due <нік> …`), з чату з ботом; `/due` без аргументів — стани лаб студента; підтвердження — алерт `due`, у чат студента бот не пише. Подробиці — [tgbot](../tgbot/README.md).
- API (адмін і агент за токеном): `GET /api/labs` (матриця) · `PUT /api/labs/{n}/deadline` · `DELETE /api/labs/deadlines/{id}` · `GET /api/students/{nick}/labs` · `PUT …/labs/{n}` (позначка) · `GET|PUT …/labs/{n}/review` · `PUT /api/repos`; `GET /api/students` тепер відповідає й агентові (як адміну) — для `sync`.

## Звіти агента ([T235](.t/T235-P--lab-deadlines-design.md) §3)

- `Review {user, lab, commit, verdict, head, head_verdict, summary, report}` — один на пару, перезапис з історією; `verdict` на зрізі до дедлайну, `head_verdict` — поточний стан, обидва `done | partial | none`; `stale` у клітинці — звіт на інший зріз, ніж поточний «останній до дедлайну».
- Файл `data/reviews/<нік>/lab<N>.md`: шапка `key: value` між `---`-рядками (`commit`, `verdict`, `head`, `head_verdict`, `summary`), далі Markdown: що є з обовʼязкових і додаткових завдань лаби, чого бракує, сигнали процесу, що спитати на захисті. `commit` можна коротким (7 знаків), як друкує `cut`.
- Шлях зараз: `bin/repos pull` → `push` → `cut <N> --checkout` → ревʼю в чаті (агент читає `data/repos/.cut/<нік>/lab<N>/` і сторінку лаби) → файл → `bin/repos reviews`. Далі — субагенти пачкою, потім на сервері.

## Не реалізовано

- ⬜ Клонування і звіти на сервері (кнопка «Оновити»), вебхуки GitHub, автоматичний прийом запрошень колаборатора ([T48](.t/T48-C--collaborator-access.md)).
- ⬜ Студентові його стани й подовження — [T236](.t/T236-Q--lab-deadlines-questions.md) Q3.
- ⬜ Щоденний `pull` за розкладом (launchd) — Q4; «без доступу» в ранковому дайджесті — Q6.
- ⬜ Звʼязка із заявками «Моєї гри» (що заявлено до дедлайну); повідомлення студентові про подовження від бота.
