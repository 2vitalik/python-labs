## Модель доступу

- **Особисті репозиторії студентів + викладач-колаборатор** (T16 Q1 «b», 2026-07): студент створює приватний репозиторій, один на всі лаби, і додає `2vitalik` колаборатором (підказки в профілі на сайті); посилання — поле `User.github`.
- **Git обовʼязковий** (T16 Q2): без git — лише мінімальна оцінка.
- **Історія комітів — сигнал процесу, не вирок** (T16 Q3 «a»): ритм комітів, один великий коміт перед дедлайном, зсув дат — аргумент на захисті. Політика щодо ШІ-коду — дозволено з розумінням, захист покаже (T16 Q4).
- Доступ з машини викладача — SSH-ключем `2vitalik` (`git@github.com:<user>/<repo>.git`), без токенів. **На сервері клонування не робимо** (2026-10-29, [T247](.t/T247--repos-auto/report.md)): fine-grained PAT чужих репозиторіїв колаборатора не бачить, а classic PAT чи SSH-ключ `2vitalik` на сервері = запис до всіх його репозиторіїв; безпечні варіанти — machine user або GitHub App ([T48](.t/T48-C--collaborator-access.md) c/d) — вимагають дії від кожного студента, тож лише коли знадобляться кнопка «Оновити» чи вебхуки.

## Репозиторії на машині — `bin/repos` ([T235](.t/T235-P--lab-deadlines-design.md) §1, [T237](.t/T237--lab-deadlines-v1/report.md))

- `bin/repos [-t prod|dev] sync` — студенти з посиланнями з сайту → `data/repos/students.json`; друкує, що змінилось (`+` нове, `~` інше, `-` зникло).
- `bin/repos pull [нік…]` — клонує нові, решту `fetch` + `checkout --detach origin/HEAD` (переписана історія чи інша гілка не ламає); по 6 паралельно; помилка доступу записується і не зупиняє; «нема звʼязку з GitHub» і таймаут — біда цієї машини, не студента: попереднє слово про доступ лишається (2026-10-29, [T247](.t/T247--repos-auto/report.md)); порожній репозиторій — «жодного коміту». Теки — **`data/repos/<група>/<нік>/`** (2026-10-26, [T242](../platform/.t/T242--table-v1/report.md)): клон під іншою групою чи старий `data/repos/<нік>/` переїжджає сам.
- `bin/repos status [нік…]` — рядок на студента: група · комітів · перший … останній · гілка · репозиторій, або помилка.
- `bin/repos push` — факти всіх репозиторіїв на сайт одним запитом (`PUT /api/repos`): посилання, гілка, HEAD, помилка, **журнал комітів** з `seen` — коли ми коміт побачили вперше.
- `bin/repos cut <лаба> [нік…] [--checkout]` — останній коміт до дедлайну лаби (дедлайн — з сайту, з подовженнями); `--checkout` — робоче дерево зрізу в `data/repos/.cut/<група>/<нік>/lab<N>/` для ревʼю.
- `bin/repos facts <лаба> [нік…]` — виміряти зріз (або HEAD, якщо до дедлайну комітів не було) без LLM → `data/reviews/<нік>/lab<N>.facts.json` ([labfacts.py](../../bin/labfacts.py), T254); рядок на студента.
- `bin/repos digest <лаба>` — звіти × профілі × факти: розбіжності, таблиця по групах, розподіли ([labdigest.py](../../bin/labdigest.py)).
- `bin/repos reviews [нік…]` — файли `data/reviews/<нік>/lab<N>.md` → сайт; `lab<N>.facts.json` і `lab<N>.profile.json` поруч ідуть як `profile`; `--dry` — лише таблиця з шапок, нічого не шле.
- `bin/repos auto` — `sync` → `pull` → `push` одним викликом; GitHub недосяжний — на сайт нічого не йде. **`bin/repos launchd on|off`** — агент launchd цього користувача (v6u), щогодини й після входу, пропущені години (сон) — один запуск після пробудження; журнал `~/Library/Logs/python-labs-repos.log`; plist пише сам скрипт зі справжніх шляхів ([T247](.t/T247--repos-auto/report.md)).
- Git-механіка — `core/api/core/repos.py` (лише stdlib): її ж візьме сервер, коли клонування переїде туди. `data/repos/`, `data/reviews/` — у `.gitignore`.
- Журнал комітів живе на сервері (`Repo.commits`): «останній до дедлайну», «комітів у вікні лаби» сайт рахує сам для будь-якого дедлайну чи подовження — без повторного запуску скрипта.
- Дата коміту — слово студента (`--date`, зсув годинника; GitHub час пушу не віддає): `seen` зі щоденного `pull` — верхня межа, коли коміт реально зʼявився; різниця author/committer зберігається (`authored`).

## Дедлайни і стани клітинки ([T235](.t/T235-P--lab-deadlines-design.md) §2)

- `Deadline {lab, at, groups}` — дедлайн лаби для всіх (`groups` порожні) або для вибраних груп; конкретніший перемагає; ставиться на `/deadlines` (✏️ у шапці колонки), час за умовчанням 23:59 Київ; кількість лаб — `LABS` у `site.env` (5). **Лаба 1 на проді — 27.10.2026 23:59 для всіх** (внесено через API 2026-10-29 за словом Vitalik у чаті; 20 подовжень з `/due` її перекривають; відповідь на [T236](.t/T236-Q--lab-deadlines-questions.md) Q2 для лаби 1).
- `LabMark {user, lab, until, open, reason, met, note, asked, asked_for}` — слово викладача про студента й лабу: подовження до дати (`until`) або «поки невідомо» (`open`), причина; вердикт `met` — вклався / не вклався / як рахує сайт; нотатка; **🙋 `asked`** — студент просив подовжити, `asked_for` — на скільки, його словами («на тиждень», «до 5.11») — клік у таблиці, рядок у редакторі на `/deadlines` і в картці, 🙋 у кутку клітинки, окремо від самого подовження ([T240](../platform/.t/T240-P--table-views.md); з бота — `/due … !`, а подовження з бота ставить 🙋 сама — [T244](../tgbot/.t/T244--due-asked/report.md)). Кожна зміна — `history` + алерт 📅 `due` («🙋 просив подовжити · на тиждень»).
- Стан клітинки (`core/labs.py`, пріоритет: слово викладача → звіт агента → факти): ✅ `ok` вчасно · 🕒 `late` зроблено після дедлайну · 🟡 `partial` частково на зрізі · ❌ `miss` не вклався · ⏳ `open` подовжено без дати · ⏱ `wait` дедлайн попереду · 🔍 `check` минув, вердикту нема · 🚫 `norepo` без посилання · ⚠️ `noaccess` репозиторій не клонується · — `nodue` дедлайн не заданий.
- Факти в клітинці завжди: комітів до дедлайну / у вікні лаби (від попереднього дедлайну) / після; останній коміт до дедлайну; ✍ — стоїть слово викладача.
- Сторінки: `/deadlines` (адмін; групи згортаються, чіпи груп і станів, клік по клітинці — редактор подовження/вердикту/звіту під рядком, 🐙 — стан репозиторію, Σ по лабах, на всю ширину; **назва лаби в шапці → `/table?view=labN`** — усе про дедлайн цієї лаби: вхід, бот, GitHub, коміти, стан, 🙋, подовження, відповіді опитувань з тегом `labN` і ⚖️ «розходиться з фактами», свої поля — вузол [platform](../platform/README.md), [T240](../platform/.t/T240-P--table-views.md)); картка «Лаби» на `/students/<нік>/edit` — ті самі рядки для одного студента.
- Бот: `/due <лаба> <дата | ? | ! | -> [текст]` — з чату зі студентом (Chat Automation, команда зникає як `/hide`), з форуму (ефемерна; відповіддю або `/due <нік> …`), з чату з ботом; `!` — лише «просив» зі словами, дата/`?` — подовження (і 🙋 сама), дата без слів лишає причину; `/due` без аргументів — стани лаб студента; підтвердження — алерт `due`; у чаті зі студентом подовження йде йому від акаунта викладача з підписом бота ([T245](../tgbot/.t/T245--due-tell-student/report.md)). Подробиці — [tgbot](../tgbot/README.md).
- API (адмін і агент за токеном): `GET /api/labs` (матриця) · `PUT /api/labs/{n}/deadline` · `DELETE /api/labs/deadlines/{id}` · `GET /api/students/{nick}/labs` · `PUT …/labs/{n}` (позначка) · `GET|PUT …/labs/{n}/review` · `PUT /api/repos`; `GET /api/students` тепер відповідає й агентові (як адміну) — для `sync`.

## Вердикт дедлайну — «вклався / ні» ([T341](.t/T341-P--due-verdict-model.md), [T340](.t/T340--due-verdicts/report.md))

- **Відповідь і випадок** на кожну пару студент × лаба рахує сайт (`core/api/core/due_case.py`): `answer` — ✅ `yes` · ❌ `no` · ❓ `ask` (пограничне) · ⏳ `wait`; `code` — чому саме. Порядок: слово викладача → звіт агента, звірений з журналом комітів → голі факти. Випадки: `ontime` · `extended` · `slip` (до години після) · `word` · `grace` · `late_bit` (до доби) · `late_days` (до трьох діб) · `late_far` · `late` · `near` (5 з 6, шостий частково) · `partial` · `other` (код не той) · `noaccess` · `after` (звіту нема, усі коміти після дедлайну) · `unreviewed` · `ahead` · `ext_run` · `ext_open` · `nodue` · `nothing` · `nowork` («нічого нового»: звіт каже «не зроблено», і після попереднього дедлайну жодного коміту) · `empty` · `norepo` · `nosite` · `word_no`. Пороги — константи `SLIP`, `NEAR`, `DAYS` (1, 24, 72 год).
- **Запізнення** (`late`, год) — від дедлайну студента до коміту, на якому звіт побачив лабу зробленою (`Review.head` у `Repo.commits`).
- **Слово студента** — «статусне» опитування лаби (`due_says.py`): тег `labN`, одна відповідь, варіанти з ✅ і 🚫; ✅ вклався · ☑️ з подовженням · ⏱️ ще працюю · 🚫 не вклався. Нічого не вирішує — лише прапорці.
- **Прапорці** `flags`: `says_more` ⚖️ каже «вклався», сайт бачить інакше · `says_less` 🙂 голос застарів · `ext_unknown` 📭 каже про подовження, якого не записано · `fresh` 🆕 після звіту були коміти · `noaccess` ⚠️ · `nobot` 🔕 · `reg_late` 🎫 (лише лаба 1).
- **Слово викладача**: `LabMark.met` + **`LabMark.grace`** — «вклався з поблажкою» 🤝 (`grace` тягне `met = true`; `met` не `true` знімає `grace`); алерт `due` каже «🤝 вклався з поблажкою».
- **Де видно**: `labs[n].case = {answer, code, late, says, said_at, flags}` — у кожній клітинці `GET /api/table`, у картці `GET /api/students/{nick}/labs` і у відповіді `PUT …/labs/{n}`; опитування у `/api/table` несе `says_lab` (лаба, чиє воно статусне). У «Зводі» — родина колонок «Вклався в дедлайн»: 🏁 `lab.answer` · 🗂 `lab.case` · ⌛ `lab.late` · 🗣 `lab.says` · 🚩 `lab.flags`; ✍ `lab.met` редагується на місці (вклався · з поблажкою · не вклався); 🤝 `graces` — скільки поблажок використано. Заводські види **«Дедлайн 1…5»** (`due1…due5`, папка «Дедлайни», на вкладках — перші два): групи «відповідь › випадок». Підписи — `core/ui/dueCase.js`.
- **`bin/due [-t prod] <лаба> [--who]`** — вердикт дедлайну одним екраном: лічильники за відповіддю й випадком, прапорці; `--who` — хто саме, ніками Telegram.
- **Стенд зі знімком сервера** — `.dev/.drafts/T340/stand/` (`up.sh`, `tree.sh`), база `python_labs_t340_stand` із `GET /api/table` сервера (`scripts/seed_stand.py`), ціль `-t t340` у `.site/.env`; 8039 / 5039.
- **Стани клітинки на «Строках»** (`core/labs.py`, нижче) лишились як були: вердикт — окремий, докладніший шар поверх тих самих даних.

## Звіти агента ([T235](.t/T235-P--lab-deadlines-design.md) §3, [T248](.t/T248-P--review-spec.md), [T254](.t/T254--reviews-lab1/report.md))

- `Review {user, lab, commit, verdict, head, head_verdict, kind, required, summary, report, profile}` — один на пару, перезапис з історією; `verdict` на зрізі до дедлайну, `head_verdict` — поточний стан, обидва `done | partial | none`; **`kind`** — що за код (`game` гра на клітинках · `tasks` вправи без гри · `other` інший код · `none` порожньо); **`required`** — слово на кожне обовʼязкове завдання лаби → «4/6» у клітинці й колонки `labN.kind`/`labN.required` на `/table`; **`profile`** — словник: що виміряв скрипт (`code`, `git`, `cut`, `head`) + `agent` (структуровані оцінки рецензента) — у базі є, в UI ще не показується ([T256](.t/T256-Q--lab1-review-followup.md) Q6). `stale` у клітинці — звіт на інший зріз, ніж поточний «останній до дедлайну».
- Файли на пару в `data/reviews/<нік>/`: **`lab<N>.md`** — звіт із шапкою `key: value` між `---` (`commit`, `verdict`, `head`, `head_verdict`, `kind`, `required`, `summary`) і Markdown (обовʼязкові з доказами `файл:рядок`, додаткові по групах, сигнали процесу, 3–5 питань на захист); **`lab<N>.facts.json`** — `bin/repos facts`: файли й рядки `.py`, функції, імпорти, `ui`, чим читається клавіша, AST-лічильники синтаксису додаткових завдань, вбудовані, сміття, форма історії (сесії, частка найбільшого коміту, автор ≠ комітер, пояси, веб-коміти, шаблонні повідомлення, гілки поза `main`); **`lab<N>.profile.json`** — оцінки агента за схемою брифу (`game`, `extra` по 5 групах, `extra_missing`, `beyond`, `quality` 1–5, `level` 1–5, `ai`, `process`, `risks`, `questions`, `confidence`).
- Конвеєр: `bin/repos auto` → `cut <N> --checkout` → `facts <N>` → субагенти (Opus, один на пару, за [prompt.md](.t/T254--reviews-lab1/prompt.md), пачками ≤ 20, код лише читається) → `digest <N>` → `reviews --dry` → погляд Vitalik → `reviews`.
- **Бриф рецензента — [review.md](review.md)** (T248, T254): що отримує, правила (лише читання, доказ `файл:рядок`, «CUT нема → HEAD»), точна шапка, тіло, схема профілю з визначеннями.
