# Звіт по лабі — бриф для агента-рецензента

Живий документ вузла [github](README.md): як робиться звіт по одній парі «студент × лаба». Дизайн — [T248](.t/T248-P--review-spec.md), поля на сайті — `Review` у `core/api/core/models/repo.py`, відправка — `bin/repos reviews`.

## Що ти отримуєш

- `CUT` — робоче дерево репозиторію студента на **зрізі**: останній коміт до його дедлайну (`data/repos/.cut/<група>/<нік>/lab<N>/`).
- `HEAD` — той самий репозиторій на поточному `origin/HEAD` (`data/repos/<група>/<нік>/`); якщо після зрізу комітів нема, `HEAD` = `CUT`.
- сторінку лаби `data/guide/lab<N>.md`: обовʼязкові завдання (пронумеровані), додаткові (групи синтаксичних можливостей), умова на вищу оцінку.
- шлях файлу, куди писати: `data/reviews/<нік>/lab<N>.md`.

## Правила

- Код **лише читається**: нічого не запускати, не встановлювати, не змінювати; у клоні можна `git log`, `git show`, `git diff` — лише читання.
- Кожне твердження — з доказом `файл:рядок` (шлях від кореня репозиторію). Не вигадувати: не знайшов — так і пиши «не знайдено».
- Українською, лаконічно, без переказу коду; оцінюєш, чи зроблено те, що просить лаба, а не стиль.
- Якщо в репозиторії кілька проєктів чи тек — скажи, яка з них лаба, і оцінюй її.

## Шапка файлу (між рядками `---`)

```
---
commit: <повний sha зрізу>
verdict: done | partial | none
head: <повний sha HEAD; той самий, якщо після зрізу комітів нема>
head_verdict: done | partial | none
kind: game | tasks | other | none
required: <по одному слову на кожне обовʼязкове завдання лаби, через пробіл: done | partial | none>
summary: <один рядок до 100 знаків для клітинки таблиці>
---
```

- `kind` — **що це за код**:
  - `game` — гра на клітинному полі, як просить лаба: поле, гравець, рух, клітинки реагують (навіть якщо частина обовʼязкових не доведена; pygame чи консоль — байдуже);
  - `tasks` — код по темах лекцій **без гри**: окремі вправи, скрипти «завдання 1.03» (трек «60» у [Балах](../../data/guide/score.md));
  - `other` — інший код: не гра на клітинках і не завдання з тем (інша задача, чужий чи шаблонний проєкт, гра не на клітинках);
  - `none` — Python-коду нема: порожньо, лише README, заготовка без логіки.
- `required[i]` — обовʼязкове завдання `i` на зрізі: `done` — є і по коду працює; `partial` — є частина чи заготовка (функція є, але не викликається; рух без перевірки клітинки); `none` — нема.
- `verdict` — підсумок по обовʼязкових на зрізі: `done` — усі `done`; `partial` — щось є; `none` — нічого (у `tasks`/`other`/`none` зазвичай `partial` чи `none` — обовʼязкові завдання лаби про гру).
- `head_verdict` — те саме для `HEAD`; якщо `HEAD` = зріз — повтори `verdict`.
- `summary` — факти, не оцінки: «6/6, додаткові майже всі; 8 комітів за 5 хв» · «2/6, main — заглушка» · «вправи з лекцій без гри».

## Тіло (Markdown після шапки)

```
# Лаба <N> · <нік> · <група>

<один абзац, якщо kind ≠ game: що це за код і чому не гра лаби>

## Обовʼязкові
1. ✅ | 🟡 | ❌ <назва пункту> — <доказ файл:рядок; що саме є / чого бракує>
…

## Додаткові
- <група 1 з лаби>: <що використано (файл:рядок)>; <чого нема>
…

## Сигнали процесу
- комітів: N · перший <дата час> · останній <дата час>  (зі зрізу; якщо є після — скільки)
- ритм: <одна сесія / рівномірно / один великий коміт перед дедлайном; розміри>
- дати: <автор = комітер, чи зсув; зміна поясу; `--date` на вигляд>
- повідомлення комітів: <осмислені / «...» / однакові>
- ознаки згенерованого коду: <нема / є: чому так здається>

## Спитати на захисті
- 3–5 питань **по їхньому коду** (файл:рядок): чому так, що буде якщо…, як поєднати
```

- Емодзі пунктів = `required`: ✅ `done` · 🟡 `partial` · ❌ `none`.
- Якщо `HEAD` ≠ зріз: коротко в «Обовʼязкові» після списку — «на HEAD: …» (що додалось), і `head_verdict` у шапці.
- Обсяг: 30–60 рядків. Довше — лише коли репозиторій справді великий.
