## 1. Три незалежні осі замість однієї «категорії»

Твої приклади категорій («архітектура», «конвенція», «імена», «дублювання», «великі методи», «рефакторинг») — це **про що** зауваження. Але в них сховані ще два питання: **наскільки це серйозно** і **чого я хочу від студента**. Змішані в один список, вони й дають відчуття, що «категорій не вистачає». Тому осей три:

- **Тема** — про що; теги, один-два на зауваження (§2).
- **Вид** — що це означає для студента; рівно один (§3).
- **Стан** — де зауваження в циклі «дав → відповів → перевірив»; рахується само (§4).

## 2. Тема — теги, а не папки

- Зауваження «метод на сто рядків, і половина з нього повторюється» — водночас «розмір» і «дублювання». Папка змусила б вибрати одне й зіпсувала б статистику; тег — ні.
- Перший тег — головний: за ним зауваження групується й фарбується. Другий — лише в статистиці й фільтрі. Більше двох — ознака, що рядок варто розбити на два зауваження.
- Список короткий і сталий, щоб модель і ти завжди влучали в ті самі слова:

| Тег | Про що |
|:----|:-------|
| Імена | змінні, функції, класи названі незрозуміло чи не за змістом |
| Стиль | PEP 8, форматування, імпорти, коментарі, мертвий код |
| Дублювання | копіпаст, однакові шматки |
| Розмір | завеликі функції, класи, файли; глибока вкладеність |
| Структура | поділ на модулі й класи, відповідальності, логіка впереміш із виводом |
| ООП | класи, наслідування, інкапсуляція, зайві чи відсутні обʼєкти |
| Дані | структури даних, магічні числа й рядки, константи, глобальні змінні |
| Логіка | зайві умови, складні вирази, «можна простіше», не по-пайтонівськи |
| Баг | працює не так, падає, крайні випадки |
| Помилки | винятки, перевірка вводу, робота з файлами |
| Гра | геймплей, інтерфейс, що бачить гравець |
| Репозиторій | коміти, зайві файли, структура тек, README |
| Розібратись | вивчити й пояснити наступного разу |
| Інше | не лягло нікуди — сигнал переглянути список |

- «Інше» — не смітник: коли в ньому збереться кілька схожих, зʼявляється новий тег (його додає один рядок у словнику).
- «Рефакторинг» серед тегів нема свідомо: це не тема, а дія — нею є майже кожне зауваження виду «покращення».

## 3. Вид — що з цим робити

| Вид | Що означає | Відповідь студента | Блокує «зараховано» |
|:----|:-----------|:-------------------|:--------------------|
| 🔴 борг | мало бути зроблено: помилка в заявленому або те, що курс уже пояснював | обовʼязкова | так |
| 🟡 покращення | працює, але можна краще | обовʼязкова: зробив або чому ні | ні |
| 🟢 виклик | нове завдання сильному студентові — понад те, що він приніс | за бажанням | ні |
| 💬 порада | думка на майбутнє | не потрібна | ні |

- Це відповідь на [T14](T14-Q--remarks-open-questions.md) Q2 (критичне · звичайне · порада) з одним доданком — «виклик».
- Вид ставить викладач одним кліком; модель лише пропонує. Нове зауваження народжується «покращенням».
- Від виду залежить, чи можуть бути монетки, — [T329](../../grading/.t/T329-P--defense-grading.md) §2.

## 4. Життєвий цикл

1. **Чернетка** — зʼявилась на сторінці захисту; студент не бачить.
2. **Надіслано** — викладач натиснув «Надіслати студентові» (усі чернетки захисту разом).
3. **Є відповідь** — студент на кожне каже: виправив · частково · не робив · не згоден або є питання; коментар; посилання GitHub.
4. **Прийнято** або **повернуто** — слово викладача з рядком чому; повернуте студент править і відповідає знову.

- Посилання — на коміт або на рядки файлу в коміті. Посилання на гілку (`blob/main/…#L10`) приймається з підказкою: рядки зʼїдуть після наступного коміту — на GitHub клавіша `y` дає постійну адресу.
- Посилання на чужий репозиторій (не той, що в профілі) приймається з позначкою для викладача.
- Думка агента — окреме поле поруч зі словом викладача: агент каже «схоже, виправлено» або «ні, ось чому», викладач підтверджує кліком. Агент не закриває зауваження сам.
- Уся історія відповідей і повернень лежить в історії правок (`record`).

## 5. Що зберігається

- `Remark`: захист, студент, текст (те, що читає студент), сирий текст диктовки (коли відрізняється), теги, вид, стан, відповідь `{state, note, link, at}`, слово викладача `{state, note, by, at}`, думка агента, пропозиція моделі, які поля викладач правив сам, монетка, порядок, час появи.
- Час появи мінус початок захисту — місце в записі розмови: «12:40».

## 6. Розкладання — три кроки, кожен наступний точніший

1. **Одразу, без ШІ** — за словами в рядку («назва», «дублю», «метод великий», «падає»): тег зʼявляється разом із зауваженням, навіть без інтернету й ключа.
2. **Модель** — коли є ключ API: один запит на пачку нових рядків, відповідь за схемою — теги, вид, чистий текст, «схоже на №…». Модель — Haiku: задача — вибір з короткого списку, найдешевша модель з нею справляється; перемикач у налаштуваннях сайту дозволяє поставити Sonnet. Захист на 15 зауважень — частки цента.
3. **Агент** — Claude на ноутбуці через API з токеном: те саме, що модель, плюс доступ до коду студента (`bin/defense`).

- Що викладач поставив рукою — ні модель, ні агент не чіпають.
- Теги й вид модель ставить сама (дешево виправити кліком). **Текст — ніколи сама:** чистий варіант зʼявляється під рядком як пропозиція «✨ …», один клік — прийняти. Сирий текст диктовки зберігається.
- «Схоже на №3» — підказка обʼєднати; обʼєднує викладач.

## 7. Доступ агента

- Маршрути викладача приймають адміна або агента з токеном (той самий механізм, що в методичці й каталозі, `editor_user`).
- Агент може: читати захисти й зауваження з відповідями, ставити теги й вид, пропонувати текст, писати думку про виправлення, додавати зауваження-чернетки.
- Агент не може: надсилати студентові, приймати чи повертати, ставити результат захисту, бачити й міняти враження та нотатку — це лише сесія викладача.
- `bin/defense` — список, один захист як Markdown, теги, думка.

## 8. Далі (не в цій задачі)

- **Каталог типових зауважень** ([T13](T13-C--remarks-concept.md)): текст «що не так → чому важливо → як виправити», швидка вставка пошуком; сировина — старий фонд (C#, ООП) і зауваження, які повторяться на перших захистах.
- **Статистика**: теги по студенту й по потоку — що погано пояснено в курсі.
- **Чернетка зауважень перед захистом** — агент проходить код і готує список, на захисті лишається підтвердити.
