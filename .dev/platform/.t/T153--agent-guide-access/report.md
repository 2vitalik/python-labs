# T153 · Методичка: доступ для ШІ-агента — звіт

`2026-09-28` · ⚙️ задача · план — [plan.md](plan.md) · редактор — [T128](../T128--guide-editor-v1/report.md) · вибори — [T154](../T154-Q--agent-guide-choices.md)

## Зроблено

- Агент читає і править сторінки методички через те саме API, що й редактор на сайті.
- Вхід агента — токен у заголовку `Authorization: Bearer …`.
- Токени живуть в `.env` сервера: `AGENT_TOKENS=claude:<токен>,codex:<токен>`.
  - Імʼя перед двокрапкою — автор правки: в базі `claude@agent`, на сайті «claude».
  - Порожній `AGENT_TOKENS` — входу для агентів нема; на сервері так і є до твого кроку.
- Правка агента нічим не відрізняється від твоєї:
  - рядок в історії `/method/history` з diff і відкатом;
  - нотатка «що змінив» → рядок у чернетці «Що змінилось»;
  - сторінку тим часом змінили на сайті → `409`, правка не лягає поверх чужої.
- Скрипт `bin/guide` — сторінка як файл:
  - `bin/guide ls` — список сторінок;
  - `bin/guide pull [slug…]` — сторінки у `.guide/<ціль>/<slug>.md`, без slug — усі;
  - `bin/guide push <slug> -m "що змінив" [-s "Розділ"]` — правка на сайт;
  - `-t prod` — сервер, без `-t` — дев.

## Як це виглядає в роботі

- Ти в чаті: «у лабі 2 перепиши абзац про файли».
- Агент: `bin/guide pull lab2` → правка файла → `bin/guide push lab2 -m "переписав абзац про файли" -s "Файли"`.
- На сайті: новий текст, в історії — автор «claude», у чернетці «Що змінилось» — рядок із нотаткою.
- Не сподобалось — «відкат» в історії, як для будь-якої правки.

## Чому токен і API

| | Токен + API (зроблено) | Секретний вхід із cookie | Браузер агента | MCP-сервер | Прямий запис у базу |
|---|---|---|---|---|---|
| Автор в історії | агент | агент | ти | агент | `import` |
| Дістає до сервера | так | так | так | так | ні, лише локальна база |
| Що відкриває | лише методичку | усе, що бачить адмін | усе, що бачиш ти | що опишеш | усе |
| Новий код | ~25 рядків бека + скрипт | вхід, окремий акаунт, cookie в скрипті | нема | окремий сервер і його деплой | нема |
| Швидкість правки | секунди | секунди | хвилини, кліки по сторінці | секунди | секунди |
| Перевірка версії (`rev`) | так | так | так | так | ні |

- MCP потрібен, коли агент не має термінала: чат у телефоні чи в браузері. Claude Code і Codex термінал мають, їм досить `curl` або скрипта.
- MCP-сервер усе одно ходив би в це саме API з цим самим токеном — його можна додати потім, нічого не переробляючи.
- Секретний вхід дав би агентові повну адмінську сесію: студенти, пошти, Telegram. Для правки текстів це зайве.

## Що токен відкриває

| Ручка | Агент |
|---|---|
| `GET /api/guide` — список | так |
| `GET /api/guide/<slug>` — сторінка, і чернетка «Що змінилось» | так |
| `GET /api/guide/history` | так |
| `PUT /api/guide/<slug>` | так |
| `POST /api/guide/changes/publish` — публікація «Що змінилось» | ні |
| студенти, активність, каталог, «Моя гра», знахідки | ні |

- Найгірше при витоку токена — зіпсовані тексти методички; кожна правка є в історії й відкочується.
- Публікацію «Що змінилось» лишено тобі: що оголошувати студентам, вирішує людина.

## Правила

- Агент не має рядка в `users`: його нема серед студентів, у лічильниках і в «Люди».
- Увійти агентом через Google чи cookie неможливо — лише токеном.
- Кожен виклик агента лягає в `activity` (`kind=api`, `user=claude@agent`, IP, user-agent): чужий IP там — знак, що токен витік.
- У стрічці `/activity` правки агентів сховані разом із викладацькими, «і викладачі» їх показує.
- Хибний токен — `401`, сліду в `activity` не лишає.
- Токен зі сміттям замість імені чи з порожнім значенням (`claude:`) не відкриває нічого.

## Скрипт `bin/guide`

- Файл сторінки: перший рядок `# Заголовок`, порожній рядок, текст — як у `data/guide/*.md`.
- `.guide/.env` — адреси й токени цілей: `DEV_URL`, `DEV_TOKEN`, `PROD_URL`, `PROD_TOKEN`; нова ціль — нова пара рядків.
- `.guide/<ціль>/.taken/<slug>.json` — сторінка, якою вона прийшла із сайту; її `rev` іде назад із `push`.
- `pull` поверх файла з невідправленими правками їх не губить: файл стає `<slug>.mine.md`.
- `.guide/` — у `.gitignore`.
- Залежностей нема: стандартна бібліотека Python.

## Файли

- `app/api/config.py` — `agent_tokens` і `agents`: токен → пошта агента.
- `app/api/deps.py` — `agent()` і `editor_user`: адмін або агент.
- `app/api/routes/guide.py` — чотири ручки на `editor_user`; публікація лишилась на `admin_user`.
- `app/api/main.py` — слід викликів агента.
- `app/api/routes/activity.py` — агенти сховані разом із викладачами.
- `app/api/tests/smoke_agent.py` — новий, 20 перевірок.
- `bin/guide` — новий.
- `app/api/.env.example`, `app/README.md`, `.gitignore`.

## Перевірено

- `smoke_agent.py` **20/20**:
  - без токена, хибний, порожній, не `Bearer` → `401`;
  - правка: `rev` росте, автор «claude», другий агент — «codex»; стара версія → `409`;
  - історія з нотаткою, рядок у чернетці;
  - студенти, активність, знахідки, «Моя гра», публікація — `401`;
  - агента нема в `users`; слід у `activity` є;
  - сесії адміна й студента працюють, як раніше;
  - `AGENT_TOKENS` порожній → токен не діє.
- Решта смоуків зелені: разом 12 файлів, 310 перевірок.
- Скрипт наскрізно, на окремому API (порт 8031, база `python_labs_smoke`):
  - `ls`, `pull` двох сторінок, правка файла, `push` → `rev 0 → 1 · claude`;
  - повторний `push` без змін → «без змін», нової версії нема;
  - правка на сайті після `pull` → `push` дає `409`; `pull` відклав мої правки у `score.mine.md`;
  - нема сторінки → `404`; нема токена цілі → зрозумілий текст.
- Дев-сервер (8030): `bin/guide ls` показав 12 сторінок.
- Смоук-базу після прогонів видалено, окремий API зупинено.

## Не перевірено

- На сервері: коду там ще нема, токена теж.
- Правку в дев-базі не робив — лише читання списку.
- У браузері `/method/history` з рядком агента не відкривав: фронт не мінявся, імʼя автора приходить з API так само, як твоє.

## Хвости

- У дев-базі зʼявилось кілька рядків `activity` від `claude@agent` — слід перевірки `bin/guide ls`.
- `app/api/.env` отримав рядок `AGENT_TOKENS=claude:…`, токен згенеровано на місці; той самий — у `.guide/.env`.
- Дев-сервер перечитав `.env` після `touch app/api/config.py` — вміст файла не мінявся.
- Codex: другий токен в `AGENT_TOKENS` сервер уже розуміє; `bin/guide` бере токен із `.guide/.env`, один на ціль — для Codex знадобиться своя ціль (`CODEX_URL`, `CODEX_TOKEN` → `-t codex`) або перемикач агента в скрипті.
- Текст `409` написаний для браузера («в іншій вкладці») — агентові він теж зрозумілий, окремого не робив.
- Знімок `data/guide/*.md` у git знімається з локальної бази (`guide_io.py export`); правда про тексти — на сервері. `bin/guide -t prod pull` дає той самий формат файлів — вибір у [T154](../T154-Q--agent-guide-choices.md) Q4.

## Крок для сервера

- Згенерувати токен: `openssl rand -hex 32`.
- Env сервера (1Password → `shared/env`): `AGENT_TOKENS=claude:<токен>`.
- Локально: той самий токен у `.guide/.env`, рядок `PROD_TOKEN=`.
- Деплой із перезапуском сайту; бота перезапускати не треба.
- Перевірка: `bin/guide -t prod ls`.
