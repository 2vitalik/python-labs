Запит (чат, 2026-09-28): «Чи можеш ти зробити якийсь механізм, через який би ти міг зручно редагувати дані на сайті? Маю на увазі методичку. Може якийсь системний акаунт для тебе як для ШІ. Типу якщо я тебе попрошу зробити зміни, то твої зміни запишуться в історію не від мене, а від тебе. І ти можеш редагувати ті сторінки. Як це краще зробити? Просто звичайне API використовувати? Просто спеціальний секретний вхід для тебе? Думаю ніякі MCP тут не потрібні, так? Просто доступ до сайту. До методички. До сторінок методички.»

## Як є

- Методичку правлять на сайті: `PUT /api/guide/<slug>` із `rev`, нотаткою й розділом; кожна правка лягає в `history` з поштою автора.
- Вхід один — Google, сесія в cookie; ручки методички — лише адміну.
- Агент може правити тільки в обхід: браузером під сесією Vitalik (в історії — Vitalik) або `guide_io.py import` у локальну базу (автор `import`, до сервера не дістає).

## Рішення

- Звичайне API, та сама ручка `PUT`, що й у редактора на сайті.
- Вхід агента — токен у заголовку `Authorization: Bearer …`; токени — в `.env` сервера, `AGENT_TOKENS=claude:…,codex:…`.
- Імʼя перед двокрапкою — автор в історії: `claude@agent` → на сайті «claude».
- Токен відкриває лише читання й правку методички; студенти, активність, каталог, публікація «Що змінилось» — закриті.
- Рядка в `users` агент не має.
- На боці агента — `bin/guide`: сторінка стає файлом, правка — звичайна правка файла.
- MCP не потрібен. Порівняння варіантів — у [звіті](report.md).
