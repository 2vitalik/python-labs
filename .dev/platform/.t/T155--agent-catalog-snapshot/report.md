# T155 · Агент: каталог і знімок сайту в git — звіт

`2026-09-28` · ⚙️ задача · план — [plan.md](plan.md) · перша частина — [T153](../T153--agent-guide-access/report.md) · вибори — [T154](../T154-Q--agent-guide-choices.md)

## Зроблено

- Агент читає і править каталог: картки ігор і завдань, разом із чернетками.
- Знімок у git знімається із сайту, а не з локальної бази.
- Правка агента на сервері закінчується знімком: `data/` оновлюється сама, лишається закомітити.
- Скрипти без `-t` ходять на сервер; дев — `-t dev`.
- Робоча тека скриптів — `.site/` (була `.guide/`): у ній тепер не лише методичка.

## Знімок у git (Q4)

- Питання було саме про це: звідки брати те, що лежить у `data/guide/` і `data/catalog/`.
- Тепер джерело — сервер:
  - `bin/guide snap` — усі сторінки методички → `data/guide/*.md`;
  - `bin/catalog snap` — каталог → `data/catalog/games.yaml` і `tasks.yaml`.
- Після `push` на сервер знімок робиться сам — і моя правка, і все, що ти за цей час змінив на сайті, видно в `git diff`.
- Формат файлів той самий, що й раніше: історія в git не ламається.

| | Історія на сайті (Mongo) | Знімок у git |
|---|---|---|
| Що зберігає | кожну правку: хто, коли, diff, нотатка | стан на момент знімка |
| Відкат | кнопкою на `/method/history` | `git checkout` файла → `import` або правка через скрипт |
| Переживе втрату бази | ні | так |
| Правки між знімками | усі | лише підсумок |

- Знімок не замінює бекап бази: студентів, заявок і скриншотів у ньому нема.
- Перший знімок із сервера дасть великий diff — локальна база й сервер розійшлись. Це разова річ.
- Локальний `export` лишився для дев-бази; комітити його результат більше не треба.

## Каталог (Q5)

| Ручка | Агент |
|---|---|
| `GET /api/tasks`, `GET /api/games` — з чернетками й архівом | так |
| `POST`, `PUT` картки завдання чи гри | так |
| `GET /api/catalog/snapshot` — каталог у YAML | так |
| студенти, активність, «Моя гра», знахідки, публікація «Що змінилось» | ні |

- Правка картки лягає в `history` від імені агента — як і правка з форми на сайті.
- Картку перевіряє той самий код, що й форму: невідома зона, монетка чи статус → `422`.
- Видаляти картки агент не може: такої ручки нема й для адміна; непотрібне — `status: "archived"`.
- Слоти параметрів (`slots`) скрипт не править: їх не править і форма на сайті.

## Скрипти

- `bin/guide [-t dev] ls | pull [slug…] | push <slug> -m "що змінив" [-s "Розділ"] | snap`
- `bin/catalog [-t dev] ls tasks|games [текст] | pull | push [tasks/<slug> …] | snap`
- Файл картки — `.site/<ціль>/tasks/<slug>.md` або `games/<slug>.md`:

```
title: "Черга"
zone: "entities"
subzone: "combat"
tags: []
coin: "tin"
status: "draft"
order: 20

Опис картки — Markdown.
```

- Рядок шапки — `поле: значення в JSON`; після порожнього рядка — опис.
- Slug — імʼя файла.
- `push` без імен відправляє всі змінені картки.
- Нова картка — новий файл, і лише коли її названо: `bin/catalog push tasks/<slug>`.
- Картку змінили на сайті після `pull` → `push` відмовляє; `pull` відкладає мої правки в `<slug>.mine.md`.
- `snap --to <тека>` — знімок не в `data/`, а куди скажеш.

## Перевірено

- `smoke_agent.py` **29/29**; нові перевірки:
  - агент додає картку, бачить чернетки, гість — ні;
  - правка картки другим агентом, в історії — обидва імені й diff;
  - погана картка → `422`; ігри — так само;
  - знімок: обидва файли, картки в них; гостю `401`, студентові `403`.
- Решта смоуків зелені: разом 12 файлів, 320 перевірок.
- Скрипти наскрізно, на окремому API (порт 8031, база `python_labs_smoke`, каталог залито з `data/catalog/`):
  - `pull` — 209 завдань і 17 ігор; одразу `push` — «нема змінених карток»;
  - правка поля картки й опису гри → `push` відправив обидві;
  - нова картка з файла → «створено», повторно → «без змін»;
  - знімок після правок відрізняється від `data/catalog/` рівно цими трьома правками; знімок методички збігся з `data/guide/` повністю;
  - картку змінили на сайті → `push` відмовив, `pull` відклав правки в `.mine.md`;
  - нема файла, значення не JSON → зрозумілий текст;
  - `push` на сервер закінчується знімком — перевірено з тестовим API в ролі сервера, знімок ішов у тимчасову теку.
- Дев-сервер (8030): `bin/catalog -t dev ls games maze`, `bin/guide -t dev ls` — відповідають.
- Смоук-базу видалено, окремий API зупинено, `data/` не змінювалась.

## Не перевірено

- На сервері: коду й токена там ще нема.
- Правок у дев-базі не робив — лише читання.
- У браузері нічого не відкривав: фронт не мінявся.

## Хвости

- При витоку токена тепер можна зіпсувати ще й картки каталогу. Кожна правка є в `history`; кнопки відкату для карток на сайті нема — відновлення через знімок у git.
- `.guide/.env` переїхав у `.site/.env`, токен дев-бази той самий.
- Дев-сервер перечитав код після `touch app/api/config.py`.
- Приклади в іграх ([T151](../T151-P--examples-in-games.md)) додадуть у гру поле `examples`: скрипт покаже його рядком шапки без змін у коді; довгий Markdown в одному рядку JSON правити незручно — тоді поле варто винести в тіло файла.
- Codex: сервер розуміє другий токен; скрипти беруть один токен на ціль — для Codex своя ціль у `.site/.env` (`CODEX_URL`, `CODEX_TOKEN` → `-t codex`), але знімок після `push` робиться лише для цілі `prod`.

## Кроки для сервера

- Згенерувати токен: `openssl rand -hex 32`.
- Env сервера: `AGENT_TOKENS=claude:<токен>`.
- Локально: той самий токен у `.site/.env`, рядок `PROD_TOKEN=`.
- Push і деплой із перезапуском сайту; бота перезапускати не треба.
- Перевірка: `bin/guide ls`.
- Перший знімок: `bin/guide snap` і `bin/catalog snap` → переглянути `git diff data/` → коміт.
