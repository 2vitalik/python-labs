# T114 · Сторінка входу з поверненням на цільову сторінку — звіт

`2026-09-20` · ⚙️ задача · план — [plan.md](plan.md)

Зроблено за планом; смоуки: `tests/smoke_auth.py` **16/16** (новий), `smoke_games.py` **70/70** (гість тепер 401); `npm run build` чистий. Клік-тест на живих дев-серверах — див. «Перевірка» внизу.

## Як працює

Гість відкриває `/students/vasya` (лінк із бота) → guard → `/login?next=/students/vasya` → «Потрібен вхід · Сторінка `/students/vasya` відкриється після входу з поштою @nure.ua» → «Увійти з Google» = `/api/auth/login?next=/students/vasya` → бекенд кладе `next` у сесію → Google → `/api/auth/callback` дістає `next` із сесії → редирект на `/students/vasya`. Dev-вхід — так само, без Google.

Стани `/login` (одна сторінка, гілки за `user`):
- гість — «Потрібен вхід» + кнопки (шлях показується, якщо він не `/`);
- `pending` — «Доступ ще не відкрито. Ти в списку…» + «На головну»;
- студент на адмінській — «Лише для викладача» + «На головну»;
- хто вже має доступ — guard одразу веде на `next` (сторінка не рендериться).

Помилки — алерт над текстом: `domain` («лише @nure.ua»), `verify`, `oauth` (скасував у Google або застарів state — раніше це був 500 і алерт 💥 адміну), `session` («Сесія завершилась»). `next` через помилку не губиться — кнопка веде туди ж.

## Захист від open redirect

`?next=` приймає лише шлях свого сайту: починається з `/`, другий символ не `/` і не `\` (`//evil.com` браузер читає як інший хост). Перевірка на обох кінцях — `safe_path()` у `routes/auth.py` і `safeNext()` у `user.js`; інакше `/`.

## Код

- `deps.py` — `allow(user, ok)`: 401 без сесії, 403 не та роль (було 403 на все).
- `routes/auth.py` — `login(next)` → сесія; `callback` → `session.pop("next")`, `try OAuthError`; `to_login(error, next)`; `dev_login(next)`; `safe_path()`.
- `app/vue/src/pages/LoginPage.vue` — нова; `router.js` — маршрут `/login` + guard (`/login` для того, хто вже має доступ → `next`; чужий → `/login?next=to.fullPath`); `user.js` — `safeNext()`; `NavBar.vue` — кнопки входу з `?next=route.fullPath`; `HomePage.vue` — без алерту `?error=`; `api.js` — 401 → `/login?error=session&next=<поточна>`.
- `tests/smoke_auth.py` — `safe_path` ×6, 401/403, dev-login з `next`/чужим/без, logout.

## Нюанси

- `/login` у меню не потрібен: гість бачить лише «Увійти з Google», який тепер несе поточну сторінку; на `/login?next=/x` кнопка навбара веде через `/login?next=/x` → guard → `/x`.
- Сесія — кукі Starlette на 14 днів, продовжується кожною відповіддю; `session` побачать хіба після «Вийти» в іншій вкладці.
- Помилка входу з домашньої (`next=/`) показується на `/login` без шляху.
- Замок API (T105 Q1) не чіпався: студент і далі може смикнути `/api/students` напряму; змінився лише код відповіді гостю.

## Перевірка

Наживо через Vite-проксі (`127.0.0.1:5030`, бекенд перезавантажився сам) curl-ом:
- `/api/auth/dev-login?next=/students/vasya%3Ftab%3Dgame` → `307 http://127.0.0.1:5030/students/vasya?tab=game` (кукі сесії поставлено, `/api/me` віддає Dev User);
- гість `/api/students` → **401**; `?next=https://evil.com` → `307 http://127.0.0.1:5030/`; SPA `/login?next=…` → 200.

Що клікнути: лінк із бота на `/students/<nick>` у свіжому профілі браузера → `/login?next=…` → «Увійти з Google» → назад на студента; те саме з Dev-вхід; студентським акаунтом відкрити `/students` → «Лише для викладача»; «Вийти» у другій вкладці, потім зберегти профіль у першій → `/login?error=session&next=/profile`.

Клік-тест у Chrome (розширення підключили тієї ж сесії, свіжий профіль без кукі):
- гість → `/students/vasya` → `/login?next=/students/vasya`, «Потрібен вхід · Сторінка `/students/vasya` відкриється після входу…» + дві кнопки ✅
- «Dev-вхід» там (dev-юзер зі статусом `student`) → лишається на `/login?next=…`, «Лише для викладача» + «На головну» ✅
- студент відкриває `/login?next=/profile` → guard одразу на `/profile`, сторінка не блимає ✅
- «Вийти» → гість на `/profile` → `/login?next=/profile` → «Dev-вхід» → `/profile` ✅
- сесію скинуто у фоні, `putProfile()` з чистою формою → 401 → `/login?error=session&next=%2Fprofile`, алерт «Сесія завершилась. Увійди знову.» ✅
- **нюанс:** те саме з незбереженими правками — `location.assign` упирається в `beforeunload` форми (`useForm`), Chrome питає «піти без збереження?»; «лишитись» = сторінка з помилкою «Потрібен вхід» біля кнопки, текст можна скопіювати і ввійти кнопкою навбара (вона несе `next=/profile`). Свідомо не чіпав: випадок рідкий (сесія 14 днів, ковзна), а редирект без питання зʼїв би правки мовчки.

Не перевірено наживо лише сам Google-вхід із `/login?next=` (потрібен реальний акаунт) — бекенд-логіка та сама, що в dev-login, плюс `session.pop("next")` у колбеку.
