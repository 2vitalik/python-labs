## Рамки

- Поведінка сайту python не міняється: ті самі адреси, відповіді API, тексти бота, вигляд сторінок.
- Деплой не міняється: `app/api` лишається текою проєкту, `main:app` і `python -m bot` — на місці; маніфест у vps-infra не чіпаємо.
- `sites/ods/` не чіпаємо.
- Пілот: у ядро йде те, що не знає про ігри. Змішане лишається в сайті, доки не знадобиться вдруге (правило 2 з T163).

## Рішення

- **Залежність іде в один бік:** сайт імпортує ядро, ядро про сайт не знає. Відмінності сайт передає параметром.
- **Бекенд:** пакет `core` у `core/api/`, сайт бере його залежністю за шляхом, editable.
  - імпорти ядра — `from core.deps import …`; власні модулі сайту лишаються пласкими: `from models.game import …`;
  - `create_app(routers, models)` збирає застосунок; роутери сайту йдуть першими;
  - `Settings` і один екземпляр `settings` — у ядрі; сталі сайту (назва, база, тека методички) — у `app/api/site.env` в git, секрети — в `.env`;
  - бот: `core.bot`, у сайті — `bot/__main__.py` і `game_alerts.py`; види алертів `claim` і `game` сайт додає сам.
- **Фронт:** `core/ui/`, alias `@core` у Vite на вихідні файли.
  - реєстри сайту — `src/site.js` (назва, меню, розділи методички) і `src/router.js` (усі маршрути явним списком);
  - `start(site, router)` з ядра запускає застосунок.
- **Смоуки** лишаються в `app/api/tests/`: більшість перевіряє платформу разом з іграми.
