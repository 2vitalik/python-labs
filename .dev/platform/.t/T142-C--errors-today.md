# T142 · 404, 500 і куди йдуть помилки: як є і що можна

`2026-09-27` · 🔆 clarification

Контекст:
- питання Vitalik у чаті: «на будь-які дивні URL сторінка відповідає просто пустою? не 404? … чи є в нас красива 500 сторінка? чи помилки кудись відправляються-зберігаються?»;
- перевірено наживо: `curl` по деву (5030 / 8030) і проду `python.labs.in.ua`, 404-сторінка — в браузері;
- поведінку 500 знято пробою з тією самою обвʼязкою, що в `main.py` (обробник `Exception` + middleware + сесії), без бази;
- вибори — [T143](T143-Q--errors-choices.md).

## 1. Невідомий URL

- **Було.** Не «404 без тексту», а `200` з порожньою сторінкою:
  - на будь-який шлях поза `/api/*` сервер віддає `200` + `index.html` — у деві Vite, у проді Caddy (`try_files {path} /index.html`, шаблон [caddy-spa](../../../../../My/vps-infra/vv/templates/caddy-spa.caddy));
  - у `router.js` не було маршруту «все інше» → `RouterView` нічого не малював: меню і порожньо під ним.
- `/api/<невідоме>` — справжній `404` + `{"detail":"Not Found"}` від FastAPI, і в деві, і в проді.
- **Зроблено 2026-09-27:** маршрут `/:pathMatch(.*)*` → `pages/NotFoundPage.vue` — «404 · Такої сторінки нема», адреса, кнопка «На головну»; публічний, як домашня.
- HTTP-статус лишається `200` («soft 404») — норма для SPA: сервер не знає маршрутів. Справжній `404` = список маршрутів у Caddy, синхронний із `router.js`; для закритого сайту без пошуковиків не варте супроводу.
- Перегляд 404 залогіненим пишеться в `activity` (`kind=view` зі шляхом), як будь-яка сторінка → биті посилання видно постфактум.
- **Не чіпав** — сторінки з параметром, де «нема» показує сама сторінка (усі зараз лише адміну):

| URL | Що на екрані |
|---|---|
| `/labs/99` | «Такої сторінки нема.» — але те саме й на 500, і коли API лежить |
| `/games/<нема>` | «Гру не знайдено або каталог ще вантажиться…» |
| `/students/<нема>` | «Гра ще не створена або сторінка недоступна.» |
| `/students/<нема>/edit` | порожньо — помилку ніхто не ловить |

## 2. «500»: що бачить людина, коли щось ламається

Сторінки помилки нема. Поломок чотири, і виглядають вони по-різному:

| Що зламалось | Відповідь сервера | Що на екрані |
|---|---|---|
| виняток у коді API | `500` + `{"detail":"Internal Server Error"}` | як пощастить зі сторінкою, див. нижче |
| API лежить (рестарт при деплої, падіння) | Caddy: `502` з порожнім тілом на `/api/*`; статика жива | сайт вважає людину **гостем** |
| помилка в JS під час рендеру | — | шматок сторінки не малюється, слід лише в консолі браузера |
| лежить Caddy або VPS | — | помилка браузера; з нашого боку нічого |

- **Виняток у коді API** — три поведінки:
  - форми (профіль, гра, картки, знахідки) — червоний alert з англійським «Internal Server Error»;
  - сторінки, що ловлять помилку мовчки, кажуть неправду: `GuidePage` — «Такої сторінки нема», `StudentsPage` — «недоступно», `StudentGamePage` — «гра ще не створена»;
  - решта (домашня адміна, `GamePage` і каталог, `StudentEditPage`) — порожньо або вічне «вантажиться».
- **API лежить:**
  - `getMe()` падає на розборі порожньої відповіді → `user` лишається `null` → меню без пунктів, закриті сторінки ведуть на «Потрібен вхід»;
  - кнопка «Увійти з Google» веде на `/api/auth/login` → порожня сторінка 502;
  - у формах текст помилки — від розбору JSON («Unexpected end of JSON input»).
- Глобального обробника у фронті нема: ні `app.config.errorHandler`, ні `unhandledrejection`.

## 3. Куди йдуть помилки

| Джерело | Telegram | База | Лог |
|---|---|---|---|
| API: необроблений виняток | алерт `error` 💥 | лише текст алерту в `messages` | повний traceback у journald |
| API: 4xx | ні (свідомо, T113) | `activity` `kind=api` зі `status` | рядок access-логу |
| бот: виняток у хендлері | алерт `error` «💥 Бот · …» | текст алерту в `messages` | traceback у journald |
| фронт: JS-помилки, невдалі запити | ні | ні | консоль браузера студента |
| Caddy 502 / 504 | ні | ні | лог Caddy |

- **Алерт `error`** ([T113](../../tgbot/.t/T113--bot-alerts-2/report.md), `bot/errors.py`): метод і шлях, нік, тип і перший рядок винятку, останній кадр нашого коду. Іде в чат чи гілку, привʼязану `/here error`, інакше особисто адмінам. Мовчить, коли порожній `TG_BOT_TOKEN` або вид вимкнено `/mute error`.
- **У базі** помилка є лише як надісланий алерт: `messages`, `dir=out`, `kind=error`. Повного traceback, тіла запиту й параметрів нема.
- **У `activity` рядка зі статусом 500 нема:** виняток пролітає крізь middleware `footprint` як виняток, а не як відповідь (перевірено пробою) — запит, що впав, у сліді студента не видно.
- **Повний traceback** — stderr uvicorn → journald на vv3: `sudo journalctl -u python-labs-web` (бот — `python-labs-bot`); живе до ротації журналу, шукати — руками.
- **Помилки фронту не бачить ніхто**, доки студент сам не напише.

## 4. Що можна зробити

| | Що | Розмір |
|---|---|---|
| A | людський текст замість «Internal Server Error» і помилок JSON: одне місце в `api.js` для 5xx, не-JSON і мережі | S |
| B | екран помилки в SPA: `errorHandler` + `unhandledrejection` → «Щось пішло не так» + «Оновити» замість порожньої сторінки | S–M |
| C | «API лежить» ≠ «ти гість»: `getMe()` розрізняє «не залогінений» і «сервер не відповів» → банер «Сайт тимчасово недоступний» | S |
| D | помилки фронту → `POST /api/errors` → алерт «💥 Сайт · /шлях · нік» (з лімітом частоти) | M |
| E | колекція `errors`: повний traceback, запит, користувач — для API, бота і фронту; заодно рядок `status=500` в `activity` | S–M |
| F | сторінки з параметром показують ту саму 404, коли API відповів 404, і екран помилки — коли 5xx | S |
| G | сторінка 502 від Caddy (`handle_errors` у шаблоні vps-infra) — для переходів на `/api/auth/*`, коли API лежить | S, vps-infra |
| H | Sentry чи аналог: SDK для FastAPI і Vue, групування, source maps | S, зовнішній сервіс |

- **Рекомендую:** A + B + C + F одним пакетом фронту, потім E + D.
- G — потім: після C лишається тільки кнопка входу під час рестарту, секунди на деплой.
- H — ні: дані студентів у третьої сторони і ще одна залежність, а на масштабі курсу свою колекцію з алертом читати простіше.
