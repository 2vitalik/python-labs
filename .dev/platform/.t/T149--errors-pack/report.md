# T149 · Помилки: екран у фронті, 404 з параметром, колекція errors, помилки фронту в бота — звіт

`2026-09-27` · ⚙️ задача · план — [plan.md](plan.md) · стан до задачі — [T142](../T142-C--errors-today.md) · вибори — [T143](../T143-Q--errors-choices.md)

## Зроблено

**Тексти помилок (A):**

| Що сталось | Що бачить людина |
|---|---|
| виняток у коді API (5xx) | «Щось пішло не так на сервері. Викладач уже знає — спробуй ще раз трохи згодом.» |
| API не відповідає, нема мережі | «Сайт тимчасово недоступний. Спробуй ще раз за хвилину.» |
| 403 / 404 без свого тексту | «Нема доступу.» / «Не знайдено.» |
| 4xx зі своїм текстом | текст від API, як і раніше |

- У формах ці тексти стають поруч із кнопкою, введене лишається.

**Блок «Щось пішло не так» (B):**

- Зʼявляється над сторінкою на будь-яку помилку, яку ніхто не зловив: у рендері, в обробнику кліку, у таймері, у промісі.
- Сторінка під ним лишається — форма не губить введене.
- Прилипає до верху вікна; кнопки «Оновити» і ✕; перехід на іншу сторінку прибирає його сам.
- Збій в одному компоненті більше не зупиняє решту сайту: меню й переходи працюють далі.

**Банер «Сайт тимчасово недоступний» (C):**

- API мовчить, і невідомо, хто дивиться → на сторінці лише банер; адреса лишається, «Потрібен вхід» не зʼявляється, кнопки входу в меню сховані.
- API замовк посеред роботи → банер над відкритою сторінкою, сторінка на місці.
- Банер сам пробує API раз на 5 с. Хто був залогінений — банер зникає; решті сторінка перезавантажується.
- Збій самого `/api/me` (наприклад, лежить база) теж дає банер, а не сайт гостя.

**404 на сторінках із параметром (F):**

| URL | Було | Тепер |
|---|---|---|
| `/labs/99` | «Такої сторінки нема.» — і на 500 теж | 404 |
| `/games/<нема>` | «Гру не знайдено або каталог ще вантажиться…» | 404 |
| `/games/<нема>/edit`, `/tasks/<нема>/edit` | порожня форма нової картки | 404 |
| `/students/<нема>` | «Гра ще не створена або сторінка недоступна.» | 404 |
| `/students/<нік>` без гри | те саме | «Гра ще не створена.» |
| `/students/<нема>/edit` | порожньо | 404 |
| будь-яка з них на 5xx | як на 404 або порожньо | блок «Щось пішло не так» |

- Назва вкладки на 404 — «Такої сторінки нема».
- `/students`, `/my/game`, `/ideas` на збій більше не кажуть «увійди з поштою @nure.ua».

**Колекція `errors` (E):**

- Кожна необроблена помилка API, бота і фронту — окремий документ.
- API: тип і текст, повний traceback, метод, шлях із query, користувач, браузер, IP.
- Бот: тип і текст, traceback, тип апдейта, хто писав (якщо привʼязаний).
- Фронт: текст, стек, сторінка, компонент і що він робив, користувач, браузер, IP.
- Під час «Очима студента» помилка пишеться на того, хто увійшов.
- Рядок `status=500` в `activity` є з [T146](../T146--activity-page/report.md).

**Помилки фронту в бота (D):**

- `POST /api/errors` — приймає і від гостей.
- Алерт виду `error`: «💥 Сайт · /сторінка · нік», ❗ текст, 📍 компонент.
- Той самий текст помилки алертить раз на 10 хв; у базу лягає кожен звіт.
- Ліміт — 5 звітів на хвилину з однієї IP, далі 429 без запису.
- Браузер шле кожен текст раз на завантаження сторінки і не більше пʼяти різних.
- Помилки API фронт не пересилає — їх API записує сам.

**Від себе:**

- Чіп «💥 Помилки» на `/activity`: рядок із джерелом (сайт · API · бот), traceback розгортається кліком.
- Кнопки входу в меню сховані, поки API мовчить.

## Як влаштовано

- `http.js` — одне місце для відповіді API: помилка несе `status` (`0` — відповіді нема), прапорець `down` ставить і знімає кожен запит.
- `problem.js` — `report()` для всього незловленого; `problem`: `lost` → сторінка 404 замість відкритої, `broken` → блок над нею.
- `main.js` — `app.config.errorHandler`, `error`, `unhandledrejection`.
- Сторінки помилку завантаження не ловлять — вона сама доходить до `report()`.
- `GET /api/students/<нік>/game`: нема студента → 404, студент без гри → `{student, game: null}`.
- `bot/errors.py` — `keep()`: документ в `errors`, потім алерт; для API — після відповіді клієнту.

## Не перевірено

- Наживо з Telegram: алерт «💥 Сайт» — лише на заглушці бота.
- На сервері за Caddy: порожня відповідь 502 → банер. У деві те саме віддає проксі Vite.
- Справжня помилка рендеру в зібраному фронті: `report()` викликано з компонентом напряму, у збірці перевірено лише наявність імен компонентів.

## Хвости

- Деплой: перезапустити і сайт, і бота — `errors` пишуть обидва процеси.
- Стек помилки фронту на сервері — з мініфікованого файла (`index-….js:1:23456`); шукати за компонентом і сторінкою. Source maps — окреме рішення.
- 📍 в алерті зібраного фронту — імʼя компонента і посилання на довідник Vue замість слів «render function».
- Тіло запиту, що впав, в `errors` не пишеться: обробник 500 його вже не бачить.
- Помилки викладача у стрічці сховані, як і решта його рядків, — вмикає «і викладачі».
- «Вийти» під час простою API веде на порожню сторінку 502 — варіант G із T142, vps-infra.
- Валідація pydantic (422 зі списком) показується як «Помилка 422» — полів із такими обмеженнями у формах зараз нема.
