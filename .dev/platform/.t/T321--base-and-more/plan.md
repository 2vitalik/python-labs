## Як працюємо

- Код — в окремому робочому дереві на гілці `min-set` (поза Dropbox, у скретчпаді сесії): у спільному дереві ті самі файли править сесія T318, а збірку зі спільного дерева ламає будь-чий проміжний стан.
- Доки (`.dev`) — у спільному дереві, комітами за шляхами.
- Наприкінці: `min-set` переноситься на свіжий `ods`, збірка й смоуки, далі `ods` просто доганяє гілку.
- Три агенти Opus паралельно, кожен зі своїми файлами: бекенд · сторінка гри · каталог. Потім — мій перегляд диффів, стенд (API 8036, Vite 5036, Chrome 9338, база `python_labs_stand4`), QA.

## Контракт

### Дані

- `Task.core: bool = False` — картка в основі; у `api()`.
- `Claim.why: str = ""` — пояснення студента до картки за запитом; у `api()`.
- `Game.extras: list[str] = []` — увімкнені можливості; у `api()`.
- `data/catalog/core.yaml` — категорія → підкатегорія → `[slug, …]` у порядку каталогу; заголовки сімей не пишуться.
- Налаштування сайту `game.closed` (`core.models.pref`) — список закритих можливостей; нема запису — `["map", "moments"]`.

### Можливості — ідентифікатори

`stats` · `mechanics` · `phases` · `tables` · `elements` · `field` · `levels` · `map` · `moments` · `logic` · `interface` · `support` · `cards` · `looks` · `etalon`

Місце картки за типом: `stat` → `stats` · `mechanic` → `mechanics` · `element` → `elements` · `fieldopt`, `field` → `field` · `level` → `levels` · `game` за категорією: `interface` → `interface`, `support` → `support`, `code` → основа, решта → `logic` · `window`, `role`, `rule` → основа.

### API

| Маршрут | Хто | Що |
|---|---|---|
| `GET /api/vocab` | усі | замість `depth` — `features: {all: […], closed: […], free: bool}`; `free` — викладач: закрите його не обмежує |
| `PUT /api/my/game/extras` `{extras: […]}` | власник гри | зберігає увімкнене; невідомі — 422; закрите студентові не додається; повертає гру |
| `PUT /api/features` `{closed: […]}` | викладач | список закритих; повертає `{closed}` |
| `GET /api/tasks` | усі | у картки є `core` |
| `PUT /api/tasks/{id}` | викладач, агент | `core` у тілі; нема поля — лишається як є |
| `POST /api/my/claims`, `PUT …/{id}` | власник гри | поле `why`; картка не в основі й не викладач / пісочниця → `why` від 20 знаків, інакше 422 |
| паспорт гри (`coins`) | — | `claimed` — картки основи й зараховане; `accepted` — як було; нове `asked` — що чекає відкриття картки |
| `GET /api/asks` | викладач, агент | `[{task: {…}, games: n, claims: [{id, nick, name, game, test, why, where, anchor, auto, params, note, link, shots, status, verdict, created_at}]}]`, найчастіші зверху; без еталонів і пісочниць |
| `PUT /api/asks/{claim}` `{verdict?, status?, task?}` | викладач, агент | відповідь, повернення чи зарахування, перенесення на іншу картку того самого типу |

Скрипти: `catalog_io.py export | import` знають `core.yaml`; `catalog_io.py core` — застосувати лише `core.yaml` (для сервера: решту карток не чіпає); `bin/catalog asks | open <slug>… | reply <id> -m … [--return] [--to <slug>]`.

### Фронт — спільне

- `ed.has(id)` — можливість видно (основа, увімкнено, є дані, або читач); `ed.offers(id)` — її можна пропонувати цьому користувачеві (не закрита); `ed.turn(id, on)` — увімкнути / вимкнути й зберегти. `ed.simple` зникає.
- `features.js` — реєстр можливостей, `homeOf(task)`, `dataOf(…)`.
- `asked.js` — `isCore(task)`, `asked(task)`, `needsWhy(task)`, `whyOk(text)`, `WHY_MIN`; `WhyField.vue` — поле пояснення.
