## Схема (крос-проєктна; реєстр живе в `dev-md-rules/DEV.md`)

- Проєкт №N → API (FastAPI) `8000+10·N`, фронт (Vite) `5000+10·N`: суфікс однаковий, «8 — бек, 5 — фронт», памʼятати треба лише номер проєкту.
- Десятка проєкту (80N1–80N9, 50N1–50N9) — запас під додаткові сервіси (+1, +2…): воркер, websocket, docs.
- Номери: 1 s-labs (ex u-labs) · 2 langlabs · **3 python-labs** · 4 vector-labs · 5 wiktionary · 6 telegram-watch; новий проєкт бере наступний вільний і дописується в реєстр.
- Не займаємо: №0 (8000 — Docker Desktop, 5000/7000 — macOS AirPlay) і №8 (8080 — чужі дефолти); 5173 лишається нічиїм — дефолт Vite тепер означає «проєкт не сконфігуровано».
- Порти фіксуються явно, щоб конфлікт був помилкою, а не тихим зсувом: Vite — `strictPort: true` (інакше мовчки бере +1 і непомітно ламає OAuth/закладки/proxy), uvicorn — явний `--port` (при зайнятому порту падає одразу — це якраз добре).
- БД окремих портів не потребують: спільний mongod на 27017, розділення — `DB_NAME` (у нас уже так).
- Бонус для деплою: на сервері кожен застосунок біндиться на свій `127.0.0.1:80N0` за реверс-проксі — локальні й серверні порти збігаються один в один.

## Що змінено тут (№3: API 8030, фронт 5030)

- `app/vue/vite.config.js`: `port: 5030` + `strictPort: true`, proxy `/api` → `http://127.0.0.1:8030`.
- `app/README.md`: `fastapi dev --port 8030`, адреси 8030/5030, `--port` в Uvicorn options PyCharm-конфігурації.
- Робоча адреса в деві тепер — **http://localhost:5030**.

## ⚠️ Переглядає [T43](T43-C--gcp-oauth-setup.md) крок 5: додати нові redirect URI в GCP

Google-вхід у деві запрацює на нових портах після додавання URI (≈2 хв):

1. console.cloud.google.com з акаунта **2vitalik@gmail.com**; у селекторі проєктів угорі обрати `nure-labs`.
2. ☰ → **APIs & Services → Credentials** → блок **OAuth 2.0 Client IDs** → клік по імені `nure-labs-web`.
3. Секція **Authorized redirect URIs** → **+ Add URI** → додати два:
   - `http://localhost:5030/api/auth/callback`
   - `http://localhost:8030/api/auth/callback`
4. **Save**. Старі URI з 5173/8000 можна одразу видалити або лишити на перехідний час — вони не заважають.
5. Зміни інколи підхоплюються не миттєво (до кількох хвилин). Dev-вхід (`FAKE_USER_EMAIL`) від GCP не залежить і працює одразу.
