## Що таке masonry

«Кладка» (як цегляна): блоки різної висоти розкладаються по колонках так, щоб колонки були максимально рівними — без «дірок» під короткими блоками. Класика — Pinterest. Ключова відмінність від CSS multicol: **розкладку контролюємо ми**, а не браузер, тому можна зробити її стабільною.

## Чому multicol стрибав

1. Браузер **балансує колонки за фактичною висотою**: розгорнув картку → висота блока змінилась → браузер перерозподілив усі блоки → те, що ти читав, поїхало в іншу колонку.
2. `break-inside: avoid` заважає різати групи, але тоді браузер лишає **великі пустоти** знизу колонок (він оптимізує «не різати», а не «щільно»).
3. Порядок «вниз-потім-вправо» плутає, коли блоки стрибають.

## Що зроблено тепер (MasonryGroups.vue, ~55 рядків, без залежностей)

- N колонок = ширина контейнера / 320px (ResizeObserver, на телефоні — 1);
- групи-підзони розкладаються **жадібно в найкоротшу колонку**; висота групи оцінюється як `2 + кількість карток` — колонки виходять майже рівні;
- оцінка **не залежить від розгорнутості карток** → розгортання лише росте вниз у своїй колонці, **нічого не перестрибує** — головний фікс;
- компроміс: оцінка грубша за реальний рендер (дворядкові назви, довгі описи) — ідеальної рівності низу не буде, але пустот класу multicol нема.

## Ландшафт підходів (якщо захочемо ще)

- **CSS multicol** — 1 рядок CSS; нестабільний при динамічній висоті. Відкинуто ([T72](T72-B--catalog-columns.md) → цей досвід).
- **CSS grid auto-fill** — стабільний порядок зліва-направо, але кожна група з нового рядка → порожні клітинки, довша сторінка.
- **JS greedy per-item** (кожна картка окремо, не група) — щільніше, але губиться цілісність підзон; наш вибір — greedy per-group.
- **Бібліотеки (Masonry.js, Muuri)** — міряють реальні піксельні висоти + анімують перекладання; гарно, але залежність + знову «переїзди» блоків при зміні висоти. Проти правил проєкту.
- **Справжній CSS masonry** (`grid-template-rows: masonry`, новий `item-flow`) — майбутнє без JS взагалі; поки лише за прапорцями браузерів. Коли доїде — наш компонент зноситься до кількох рядків CSS.
- **Віртуалізація** (рендер лише видимого) — знадобиться хіба після тисяч карток.

Якщо жадібна оцінка почне помітно брехати (групи з дуже довгими описами), апгрейд — міряти реальні висоти груп після рендера і перекладати лише на resize (не на розгортання). Це +20 рядків, тримаю в кишені.
