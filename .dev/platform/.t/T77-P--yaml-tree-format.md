## Формат (пропозиція)

Файл `tasks.yaml` стає деревом; завдання — **один рядок** `slug: "рядок"` з міні-граматикою:

```
Назва [монетка×N] (ігри, через кому) #тег #тег !статус 🔁N — опис
```

- `[…]` — монетка: емодзі (`[🥉]`) або слово (`[bronze]`) — парсяться обидва; `×N` — amount, якщо не 1;
- `(…)` — slug-и ігор; нема дужок = універсальне;
- `#…` — теги (`#algo` = ⭐);
- `!draft` / `!archived` — статус; **без маркера = active** (виняток: поки каталог у чернетках, писати `!draft` доведеться часто — після ревізії активація зробить файл чистішим);
- `🔁` = без ліміту повторів, `🔁N` = до N разів; нема = одноразове;
- `— …` — опис (усе після довгого тире до кінця рядка);
- **порядок рядків = order** (пишеться з кроком 10 при export, тож ручні вставки без перенумерації).

Приклад (реальний шматок зони entities):

```yaml
entities:
  combat:
    - basic-shot: "Постріл уперед [📎] (battle-city)"
    - shoot-modes: "Режими стрільби (battle-city) !draft — сімʼя: вперед / черга / дріб / cooldown"
      variants:
        - shoot-forward: "Вперед [📎]"
        - shoot-burst: "Черга [📎]"
    - projectile-collision: "Зіткнення снарядів [📎] — анігіляція чи проліт"
  move:
    - chase-bfs: "Пошук шляху BFS/A* [🥇] #algo"
```

- Сімʼя — той самий рядок картки + вкладений `variants` з такими ж міні-рядками (тільки назва+монетка).
- Fallback: якщо завданню треба багаторядковий опис — звичайний YAML-словник повних полів поруч із рядковими (парсер розрізняє за типом значення). Тож формат не глухий кут.
- `games.yaml` не чіпаємо — там 17 записів з довгими описами, плоска форма доречна.

## Чому так

- Оком читається як каталог: дерево + рядок на завдання; діф у git — теж рядок на зміну.
- Однозначний парсинг: кожен маркер має свій символ-делімітер, назва — усе до першого маркера; емодзі монеток унікальні.
- Slug лишається ключем upsert-у — перейменування назв безпечні, як і зараз.

## Реалізація (після твого «ок» у [T78](T78-Q--catalog-ui2.md) Q3)

`catalog_io.py`: export пише дерево (зона→підзона→рядки, компакт-рендер маркерів), import парсить обидві форми (рядок і словник) → ті самі upsert-и. Розмір: ~60 рядків замість теперішніх ~30. Старий плоский файл зникає при першому export.
