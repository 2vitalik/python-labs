## Чому Mongo міняє все рівняння

- Головна цінність Django з [T21](T21-B--tech-stack.md) — адмінка з коробки, а вона стоїть на Django ORM, який працює **лише з SQL**. Django + MongoDB — насильство над фреймворком: сторонні адаптери (djongo, mongoengine) ламають адмінку, міграції й половину батарейок.
- Тож вилка насправді не «Django чи FastAPI», а «SQL чи Mongo»: SQL → Django має сенс; Mongo → FastAPI — природний вибір, без жодного компромісу.
- «Дуже хочу Mongo» в солопроєкті — легітимний технічний аргумент: мотивація й задоволення від інструменту — реальний ресурс. Застереження [T21](T21-B--tech-stack.md) (звʼязки, агрегації) лишаються чинними, але обсяг даних крихітний (десятки студентів × сотні записів) — aggregation pipeline це витримає, хай і багатослівніше за SQL.

## Пропозиція стеку (нова редакція)

- **FastAPI + MongoDB (Beanie ODM) + Vue 3 + Bootstrap 5** — цілісний стек без внутрішніх суперечностей.
- **Beanie** — async ODM поверх Pydantic: документи описуються як типізовані класи, валідація з коробки — це дисципліна схеми, якої Mongo сам не дає.
- **Authlib** — OAuth-клієнт для Google (стандарт де-факто в FastAPI-світі).
- **Сесія — підписана cookie** (Starlette SessionMiddleware), без JWT: для одного бекенда JWT — зайва складність без виграшу.
- Що втрачаємо без Django і чим компенсуємо:
  - адмінка → у мікро-MVP не потрібна; дані дивитись/правити — MongoDB Compass; коли дозріє потреба — starlette-admin (має Mongo-бекенди) або власні екрани;
  - міграції → у Mongo їх нема за визначенням; каркас тримають Beanie-моделі;
  - готова авторизація → Authlib + ~50 рядків свого коду, одноразово.

## Форма мікро-MVP: два шляхи

- **a) Одразу Vue 3 SPA + FastAPI як API (рекомендую):** цільова архітектура з першого дня, нічого не викидається потім. FastAPI віддає збірку SPA статикою (один origin — без CORS у проді); дев — Vite dev server з proxy на бекенд. OAuth-редиректи ходять через бекенд; фронт лише питає `/api/me`.
- **b) FastAPI + Jinja2 + Bootstrap, без SPA:** менше рухомих частин зараз, але з появою кабінету студента цей шар викидається. Виграє кілька днів сьогодні — програє їх при черзі 1.

## Що ти міг не врахувати (навіть для цієї малої задачі)

- **Google Cloud обвʼязка:** потрібен GCP-проєкт → OAuth consent screen → client id/secret; redirect URI прописуються руками (localhost для дев, домен для проду).
- **Consent screen буде типу «External»** — ти не адмін Workspace nure.ua. Для скоупів openid/email/profile верифікація Google не потрібна, але в режимі Testing діє ліміт 100 тест-користувачів → перед запуском на студентів натиснути «Publish».
- **`hd=nure.ua` — лише підказка** вікну вибору акаунта, не захист. Реальний фільтр — перевірка клейму `hd` (і `email_verified`) в ID-токені на бекенді; інакше обмеження обходиться.
- **Твій власний вхід:** 2vitalik@gmail.com — не nure.ua. Потрібен allowlist адмінських email повз доменний фільтр (один рядок конфігу) — інакше сам у систему не зайдеш.
- **HTTPS обовʼязковий для проду:** Google приймає http-redirect лише на localhost → перший же деплой тягне домен + сертифікат (Caddy видає сам).
- **Три стани користувача варто закласти одразу:** анонім (публічні сторінки) → залогінений без доступу («доступ надає викладач») → допущений студент. Навіть якщо зараз усі сторінки — заглушки, поле `status`/`role` у документі користувача — це і є майбутня модель «доступ лише моїм групам», коштує один рядок.
- **Секрети:** client secret і ключ сесії — тільки `.env` (git-ignored) + `.env.example` у репо.
- **Mongo в проді:** MongoDB Atlas free tier (M0, 512 MB) — нуль DevOps; альтернатива — свій mongod у docker на VPS. Для дев — docker compose локально.
- **Код-стайл як артефакт:** принцип «лаконічний, максимально зрозумілий код, ніби писав сам Vitalik» зафіксуємо в `CLAUDE.md` кореня репо при старті задачі — він же впливає на вибір бібліотек (менше магії, менше шарів абстракцій).

## Ескіз обсягу мікро-MVP

- Бекенд: ~4 невеликі файли (app, config, auth-роути, модель User), орієнтовно 150–200 рядків.
- Фронт: Vue-каркас — шапка, Home-заглушка, стан «увійшов/не увійшов», ~5 файлів.
- Після відповідей на [T40](T40-Q--auth-mvp-questions.md) — задача-тека з `plan.md`.
