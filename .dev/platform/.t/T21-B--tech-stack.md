## Бекенд: Django проти FastAPI

- **Django** (рекомендую): головний аргумент — **адмінка з коробки**. Ця система — на 80% CRUD над каталогами (завдання, монетки, зауваження, студенти, групи, слоти) з одним привілейованим користувачем — тобою. Django admin дає тобі робочий інтерфейс редагування ВСЬОГО з першого дня, ще до того, як зʼявиться перший Vue-екран. Плюс: ORM з міграціями, авторизація, батарейки. API для Vue — DRF або django-ninja (FastAPI-подібний синтаксис усередині Django).
- **FastAPI**: чистіший async і сучасний API-шар, але адмінку, авторизацію, міграції збираєш руками з бібліотек — для солопроєкту це місяці «клею», які Django дає безкоштовно. Async-переваги тут не потрібні (навантаження — десятки студентів, не тисячі RPS).
- Висновок: різниця не смакова, а структурна — Django економить найдефіцитніший ресурс проєкту (твій час на «внутрішні» інтерфейси).

## БД: PostgreSQL проти MongoDB

- Твій аргумент за Mongo — «дані ієрархічні, не табличні». Але подивись на сутності: студенти, групи, семестри, завдання, заявки, монетки, захисти, слоти, зауваження — це **класичні звʼязки** (хто→що→коли), тобто якраз реляційна матерія: «всі незакриті зауваження по студентах групи X», «сума монеток по категоріях» — SQL-запити одним рядком.
- Ієрархічне/гнучке (структура завдання, вимоги до звіту, конфіг генератора варіантів) — прекрасно живе в **JSONB-полях Postgres**: гнучкість документа всередині реляційного каркасу. Postgres дає обидва світи; Mongo — тільки один, і тоді звʼязки й агрегації стають болем.
- Плюс: Django ORM «рідний» для Postgres, JSONB підтримується з коробки. **Рекомендую PostgreSQL.** (Для мінімізації DevOps на старті можна навіть SQLite → Postgres при деплої, Django це дозволяє.)

## Фронтенд і збірка

- **Vue 3** — вирішено тобою, підтримую: SPA для кабінетів студента/викладача + Django API.
- Нюанс: не поспішати переносити ВСЕ у Vue — твої внутрішні екрани можуть довго жити в Django admin; Vue — насамперед для студентського кабінету (каталог, звіт, прогрес, слоти).

## Інфраструктура

- VPS: docker compose (django + postgres + nginx + бот + воркер), HTTPS через caddy/letsencrypt.
- Фонові задачі (кло­нування репо, ШІ-перевірки, нотифікації): на старті — django-командами з cron/простим воркером; Celery — лише коли реально знадобиться.
- ШІ-перевірки — через Claude API (agent SDK) на VPS; ключі й ліміти — окрема тема.

## Підсумок пропозиції

- Django + django-ninja/DRF · PostgreSQL (+JSONB) · Vue 3 · aiogram-бот · docker compose на VPS.
