## Термінологія

- **Work** («робота») — гра студента: модель коротка, не плутається з каталожною `Game`. UA в UI: «Моя гра» (своя) і «Роботи» (галерея).
- Обʼєкти v1 — **вікно** і **меню** ([T84](../../reports/.t/T84-Q--game-objects-questions.md) Q2a); сутності/рівні — після сесії механік.

## Моделі (Mongo/Beanie)

- **`Work`** (`works`): `owner` (email, unique — одна гра, T89 Q1a) · `title` · `base_game` (slug каталожної гри) або `base_custom` (текст своєї основи; T89 Q3a) · `description` (md) · `created_at`.
- **`WorkObject`** (`work_objects`): `work` · `kind` (`window`/`menu`) · `title` (студентська назва) · `task` (для вікна — slug картки-типу з тегом `window`) · `description` · `screenshots` (список файлів) · `window` (для меню — id вікна-хоста, опційно) · `items` (для меню — `{title, window: obj-id, task: slug, note}`; обидві цілі порожні = текстовий пункт — [T84](../../reports/.t/T84-Q--game-objects-questions.md) Q4a) · `order` · `created_at`.
- **`Claim`** (`claims`): `work` · `task` (slug) · `object` (id обʼєкта; `""` = заявка рівня гри) · `note` · `link` (GitHub; нормалізація в коміт-пін — окрема фаза) · `status` (`claimed`; життєвий цикл виросте з [T10](../../reports/.t/T10-Q--reports-open-questions.md)) · `created_at`. Дубль (work, task, object) — заборонений.
- Історія — наявні `record/record_new` + новий дрібний `record_delete` (у студентів зʼявляється DELETE, якого в каталозі не було).

## Правила v1 (рекомендації в межах прийнятого)

- **Створення вікна = авто-заявка** картки-типу на цьому обʼєкті; чіпи елементів і функції — теж заявки (чіп → `object`=вікно, функція → рівень гри). Тип вікна після створення не міняється (видалити й створити заново — дешевше за міграцію заявок).
- **Екземпляри без ліміту:** скільки завгодно вікон одного типу (два end-screen: перемога і поразка); звʼязку кількості заявок із `max_count`/цінами рахуватиме зарахування (grading) — v1 монетки суто довідкові ([T84](../../reports/.t/T84-Q--game-objects-questions.md) Q7a).
- **Видимість типів = правила каталогу:** студент бачить лише `active`-типи → ⚠️ Vitalik: активувати `window`-картки після ревізії, інакше в дропдауні лише 4 класичні.
- **Видалення:** обʼєкт видаляється разом зі своїми заявками і файлами; посилання на видалене вікно зачищаються з меню. Заявок «зараховано» ще не існує, тому захист від видалення зарахованого — разом із життєвим циклом.
- **Пункти меню без формальних заявок:** лічильник «N пунктів × 🌱» на паспорті довідково; картка-🔁 «пункт меню» — разом із монетною математикою.

## Скриншоти

- Файли: `app/api/uploads/<work-id>/<uuid>.<ext>` (git-ignored), роздача `StaticFiles` на `/api/uploads`; ліміт 8 МБ; типи png/jpg/webp/gif (gif уже покриває «динаміку» з [T84](../../reports/.t/T84-Q--game-objects-questions.md) Q5a — окремого поля не треба, це той самий аплоад).
- URL непублічний лише практично (uuid не вгадується); справжня авторизація роздачі — не в v1.
- Дата скриншота = дата файла-запису (принцип «не протухає» — [T09](../../reports/.t/T09-C--reports-concept.md)).

## API (`/api/works`, три файли роутів ≤ ~90 рядків)

- `works.py`: `GET ""` — галерея (усі залогінені, T89 Q2a: + власник, група, лічильники, обкладинка) · `GET /my` · `POST ""` (одна на власника, 409) · `PUT /my` · `GET /{id}` — паспорт: work + власник + обʼєкти + заявки, збагачені картками каталогу (назва/монетка — щоб чернеткові картки рендерились глядачам).
- `work_objects.py`: `POST` (вікно з валідацією типу / меню) · `PUT /{id}` · `DELETE /{id}` · `POST|DELETE /{id}/screenshot`.
- `work_claims.py`: `POST` (дедуп) · `PUT /{id}` (note/link) · `DELETE /{id}`.

## Сторінки (етап C, наступна сесія)

- `/my-game` — редактор: створення (назва + основа з `active`-ігор або своя), вікна-картки (тип + назва + drag-скриншот + чіпи елементів + автопідказки функцій статичною мапою пар: volume-control→sound-volume, music-toggle→background-music…), меню з пунктами-діями.
- `/works` — галерея робіт; `/works/:id` — паспорт (галерея вікон, меню, заявки, монетки за типами без зведення). NavBar: «Моя гра» + «Роботи».
- Граф переходів — етап D (дані для нього вже збираються через `items.window`).
