## Принципи

- Колекція = сутність; звʼязки — просте посилання `user_id`/`task_id` (ObjectId), без спроб зробити з Mongo реляційку.
- **Історія — одна колекція на всіх** ([T57](T57-B--history-storage.md)): будь-яка майбутня сутність отримує аудит безкоштовно через той самий хелпер.
- Все, що за природою є нарахуванням/подією (монетки, відвідування), — **append-only журнал**: не «поточне значення», а записи, з яких значення рахується; це історичність задарма і формули поверх.
- Довідники (каталог завдань, ігри) редагуються рідко і тільки викладачем — теж через історію, нічого особливого не треба.

## Ескіз колекцій (майбутнє, зараз не створюються)

- `users` — студенти й викладач: профіль ([T56](T56-P--profile-pages-design.md)), група, привʼязки GitHub/Telegram.
- `tasks` — канонічний каталог завдань (зони/категорії/ігри — з міграції wiki, [T37](../../tasks/.t/T37-Q--taxonomy-questions.md)).
- `reports` — заявки «зробив завдання»: студент, завдання, лінки на GitHub (файл/коміт), скріншоти, статус життєвого циклу ([T10](../../reports/.t/T10-Q--reports-open-questions.md)).
- `defenses` — захисти: дата, студенти, результати по кожному.
- `remarks` — зауваження: студент (звіт/захист), текст, статус виправлення, відповіді-статуси студента.
- `coins` — журнал нарахувань монеток (за що, скільки, коли); оцінки й формули рахуються поверх ([grading](../../grading/README.md)).
- `surveys` + `answers` — опитування через бота: питання, варіанти, відповіді студентів (бажана оцінка — теж сюди).
- `attendance` — відвідування/статуси по датах, якщо знадобиться окремо від захистів ([journal](../../journal/README.md)).
- `history` — журнал усіх змін ([T57](T57-B--history-storage.md)).
- Група — v1 просто рядок у `users`; окрема колекція `groups` — лише якщо в групи зʼявляться власні атрибути (курс, рік, розклад).

## Зараз

- Створюються лише `users` (розширення) + `history`; решта — коли дійде черга відповідних вузлів.
