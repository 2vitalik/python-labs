## Моделі (Beanie, `app/api/models/`)

```python
class Game(Document):                    # collection "games"
    slug: str            # unique index, EN-kebab
    title: str           # UA
    icon: str = ""       # emoji
    klass: str = ""      # avatar | cursor | figure | puzzle ("class" зарезервоване)
    axes: dict = {}      # {field, time, opponent, info, random, goal} — рядки-підписи
    summary: str = ""    # один рядок для картки галереї
    description: str = ""  # markdown: ядро, варіації, джерела
    status: str = "draft"  # draft | active | archived
    order: int = 0
```

```python
class Variant(BaseModel):                # елемент сімʼї всередині Task
    slug: str; title: str
    coin: str = ""; amount: float = 1

class Task(Document):                    # collection "tasks"
    slug: str            # unique index
    title: str           # UA
    description: str = ""  # markdown: що зробити + «що я перевіряю»
    zone: str; subzone: str  # дім, ключі з zones.py (дзеркало _map.md)
    tags: list[str] = [] # механіки/сутності + "algo" (⭐)
    games: list[str] = []  # slugs; [] = універсальне
    coin: str = ""       # wood | tin | bronze | silver | gold (довідково, T66)
    amount: float = 1
    max_count: int = 1   # 1 = одноразове · N = стільки разів · 0 = без ліміту (рівні)
    variants: list[Variant] = []  # сімʼя; порожньо = просте завдання
    status: str = "draft"
    order: int = 0       # ручний порядок усередині підзони
```

- **Повторюваність** — `max_count`: «додатковий рівень» = 0 (кожен рівень зараховується), «алгоритм» = 1 (один раз) — рівно твоя вимога з [T65](../../.rounds/.t/T65-R--catalog-round-readback.md).
- **Що свідомо НЕ додаю зараз** (Mongo дозволяє додати поля будь-коли без міграцій): `owner`/`base_slug` для ігор студентів, лічильники статистики, множник якості ([T06](../../tasks/.t/T06-Q--tasks-open-questions.md) Q4), окреме поле критеріїв (поки секція в description), поле пропозицій. Модель їм не заважає — вони доростуть у своїх чергах.
- `zones.py` — константа `{zone: {title, subzones: {…}}}`, ~30 рядків; віддається фронту як є.

## API (`app/api/routes/`)

- `GET /api/zones` — константа таксономії.
- `GET /api/games` · `GET /api/tasks` — весь каталог одним махом (клієнт тримає в памʼяті, [T67](T67-B--catalog-ui.md)); студент бачить `active`, адмін — усе.
- `POST /api/games` + `PUT /api/games/{id}` (і так само для tasks) — адмін; через `record_new()`/`record()` — історія правок каталогу задарма. DELETE нема — є статус `archived` ([T66](T66-B--catalog-storage.md)).
- Скрипти поруч з api: `catalog_io.py` — export/import YAML ↔ Mongo (upsert по slug; він же — сид).

## Фронт (Vue, за ідіомою профілю)

- Сторінки: `TasksPage` (дерево+стрічка+пошук, [T67](T67-B--catalog-ui.md) A) · `GamesPage` (галерея) · `GamePage` (опис + «завдання цієї гри») · `GameEditPage` / `TaskEditPage` (адмін-форми в картках-групах, як `StudentEditPage`).
- Компоненти: `ZoneTree` · `TaskCard` (рядок + акордеон-розгортання) · `CoinBadge` (🪵⚪🥉🥈🥇 ×amount) · `SearchChips` (пошук + чіпи, стан у query URL).
- Стор — за зразком `user.js`: модульний `catalog.js` (`ref` + `loadCatalog()`), без Pinia.
- Markdown-рендер описів — додаю легку залежність `marked` (безальтернативно писати свій рендер — гірше).
- NavBar: пункти «Ігри» і «Завдання» для активних користувачів (pending, як і раніше, бачить лише «чекайте підтвердження»).

## Сид (стартове наповнення)

- Джерело — **wiki-ядро, не сирий v3**: 17 ігор з `data/wiki/games/` (осі з шапки, опис із «Ядро»+«Варіації»; девʼятка → `active`, решта → `draft`) + ~150 курованих пунктів зон `data/wiki/tasks/*.md` → картки-чернетки (`draft`): дім із заголовка підзони, теги гри/⭐ з маркерів, вкладені пункти-сімʼї → `variants`.
- Ціни: проставляю орієнтовно я (звіряючись із медіанами v3, де назви матчаться; ⭐ → золото) — **усе як чернетка, правиш в адмінці**; це «щоб виглядало живим», не фінальні цифри.
- Повна міграція 2130 рядків v3 → канонічні картки — окремий крок за [T37](../../tasks/.t/T37-Q--taxonomy-questions.md) Q4, не заважає v1: сид дає скелет, міграція потім доллє деталі й історичні ціни.

## Межі v1 (свідомо за бортом)

- Звіти/вибір завдань студентом, монетна математика й підсумки — [reports](../../reports/README.md)/[grading](../../grading/README.md), свої черги.
- Свої ігри студентів (копія + адаптація) і пропозиції завдань — модель готова прийняти (додамо `owner`/`base_slug`/статус `proposed`), UI — наступні раунди.
- Секції «мінімум / добре / на 5» в іграх — після рішень grading (це, по суті, ворота [T07](../../grading/.t/T07-C--coins-system.md)).
- Spec-фрагменти на картках ([T34](../../games/.t/T34-P--game-spec-model.md)) — після відповіді на сам T34.
- Лічильники «брали/зарахували», рекалібрація цін — потребують звітів.

## Про що ти міг не подумати (фіксую, щоб не загубилось)

- **Стабільність ідентичності**: звіти майбутнього посилаються на `task_id` (ObjectId) — перейменування і зміна slug безпечні; slug — лише для URL/export.
- **Снапшот ціни в звіті** ([T05](../../tasks/.t/T05-C--task-catalog-concept.md)): у v1 нічого не робимо, але саме тому ціна на картці — «поточна», а зарахована — колись зафіксується в звіті.
- **Виправлення дому**: правка zone/subzone у картки — звичайний PUT, історія в `history`; дерево перебудовується само — таксономічні «переїзди» дешеві, страх зробити «не ту» категорію знімається.
- **Шерні лінки з фільтрами** ([T67](T67-B--catalog-ui.md)) — це вже готовий механізм «завдання тижня»: кинув групі лінк на вибірку.
- Кириличні слаги в пошуку/export: слаги EN, назви UA — пошук іде по обох.
