# T150 · Активність: Telegram-рядки до привʼязки — за студентом — звіт

`2026-09-27` · ⚙️ задача · план — [plan.md](plan.md) · сторінка — [T146](../T146--activity-page/report.md)

## Зроблено

- Рядок Telegram без пошти тепер підписується людиною, чий це Telegram id **зараз** — під час читання, база не міняється.
- Стрічка `/activity`:
  - повідомлення у форумі, реакції, вступи в групу, написане боту до привʼязки — з імʼям студента замість «`@нік`»;
  - відповіді бота в ще не привʼязаний чат — теж за студентом;
  - нотатки `/note` про непривʼязаного — за студентом (поле `tg_id` для цього й лежало).
- Одна людина (`?user=<нік>`): до її рядків додались форум, реакції, членство й нотатки з часу до привʼязки.
- «Люди»: лічильник 💬, стовпчики за 14 днів і «востаннє» рахують і ці рядки.
- «і викладачі» вимкнено → рядки викладача з часу до його привʼязки теж сховані.
- Майбутні рядки привʼязаного студента бот підписує сам у момент запису — як і раніше.
- Фронт не мінявся: API віддає вже підписані рядки.

## Чому під час читання, а не записом у базу

| | Під час читання (зроблено) | Запис у базу при привʼязці |
|---|---|---|
| Правда про звʼязок | одна — `users.tg_chat_id` | дві: профіль і копія пошти в кожному рядку |
| Минулі рядки | підписані одразу, без міграції | разовий прохід по базі на сервері |
| Привʼязали не той акаунт | відвʼязав — рядки знову нічиї | чужі рядки лишаються підписаними; що саме дописано — вже не відрізнити |
| Журнал | лишається таким, яким записаний | факт «на той момент не був привʼязаний» губиться |
| Хто пише | ніхто | бот (привʼязка) і сайт (відвʼязка) мали б правити ті самі рядки |
| Ціна | три місця читання знають про Telegram id | читання без змін |
| Швидкість | карта `id → пошта` зі списку студентів, який сторінка й так читає | однаково |

- Надійніше — читання: нічого не можна зіпсувати, будь-яка помилка у привʼязці виправляється сама.
- Запис у базу знадобиться, лише коли рядків стане так багато, що фільтр за людиною гальмуватиме; індекс `from_id` це відсуває далеко.

## Правила

- Пошта, записана в рядку, має перевагу над теперішньою привʼязкою: це факт на момент події.
  - Студент перепривʼязав бота на інший акаунт → рядки зі старого акаунта, написані під час привʼязки, лишаються його.
- Чий рядок: нотатка — `tg_id`; вхідне — `from_id`; вихідне — `chat_id`. Так само людину обирає бот під час запису (`bot/log.py`).
- Незнайомець лишається незнайомцем, доки його id нема в жодному профілі.

## Файли

- `app/api/activity_link.py` — новий: `links()` — карта `id → пошта`, `tg_id()` — чий рядок, `unlinked()` — фільтри Mongo для рядків без пошти.
- `app/api/activity_feed.py` — підпис рядка, фільтр однієї людини, фільтр «без викладачів».
- `app/api/activity_people.py` — групування ще й за `from_id`.
- `app/api/routes/activity.py` — передає карту.
- `app/api/models/message.py` — індекс `from_id`; коментарі в `message.py` і `note.py`.
- `app/api/tests/smoke_activity.py` — 7 нових перевірок.

## Перевірено

- `smoke_activity.py` **34/34**; 5 із 7 нових перевірок падають на коді до задачі.
  - форум, реакція, відповідь бота й нотатка до привʼязки — за студентом;
  - пошта в рядку має перевагу; незнайомець лишається; рядок викладача схований і зʼявляється з «і викладачі»;
  - стрічка однієї людини: усе її, нічого чужого; стрічка іншої людини не змінилась;

  - відвʼязка → знову незнайомець; у базі жоден рядок не отримав пошти.
- Решта смоуків — усі 10 зелені (разом 11 файлів, 290 перевірок).
- Смоук-базу `python_labs_smoke` після прогону видалено.

## Не перевірено

- У браузері сторінку не відкривав: фронт не мінявся, перевірка — на рівні API.
- На живих даних: у дев-базі нема жодного рядка без пошти від привʼязаного акаунта (33 повідомлення, привʼязаний один акаунт) — різницю буде видно на сервері, коли студенти писатимуть у форум до привʼязки.

## Хвости

- Дев-сервер API перезапустився сам від зміни файлів і створив індекс `messages.from_id` у дев-базі — це єдина зміна в ній.
- Деплой: перезапустити сайт — індекс на сервері створиться на старті; бота перезапускати не обовʼязково, його код не мінявся.
- Відвʼязав бота → рядки з часу до першої привʼязки знову нічиї, а написані під час привʼязки лишаються підписаними. Повна історія привʼязок є в `history` (зміни `tg_chat_id`) — читати її звідти варто, лише якщо це заважатиме.
- Алерти `msg` від незнайомців (`events`) лишаються без людини: у події нема Telegram id, лише текст. Чіп «🔔 Алерти» вимкнений за замовчуванням, те саме повідомлення є рядком Telegram — уже з імʼям.
- Рядки `deleted` (видалення в особистому чаті) лишаються без імені: Telegram не каже, хто видалив; у стрічці однієї людини вони є.
