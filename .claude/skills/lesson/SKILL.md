# /lesson — транскрипти занять

Тека заняття:

```
<тека>/
├── raw/            # сирі транскрипти: один сервіс = один файл, назва = сервіс (zoom.txt, whisper.txt, tana.txt, plaud.txt, …)
├── prep/           # результат prep.py: zoom і plaud по рядку на фрагмент із годинниковим часом
├── meta.yml        # необовʼязково: course, lesson, kind, date, title, teacher, roster (імʼя в Zoom → як писати)
├── context.md      # необовʼязково: нотатки викладача для конспекту — на що звернути увагу, що витягнути
├── transcript.md   # результат merge
├── notes.md        # результат merge: зсув годинників, безіменні мовці, розбіжності, [?]
└── summary.md      # результат summary
```

Теки занять — поза git: у транскриптах імена студентів.

Важку роботу робить субагент на Opus (`Agent`: `subagent_type: general-purpose`, `model: opus`): він читає всі сирі файли цілком і пише результат частинами, дописуючи у файл розділ за розділом; я готую завдання і перевіряю результат. Якщо я сам Opus — роблю сам, без субагента.

## merge

1. Підготовка: `python3 prep.py <тека>/raw` — Zoom і Plaud по рядку на фрагмент із годинником у `prep/`, зсув Plaud, мовці Zoom; для решти — `wc -w`, перші 30 рядків, вигляд міток; `meta.yml`, якщо є. Дата заняття в сирих файлах зазвичай відсутня — спитати користувача, не вгадувати.
2. Субагенту: шляхи `prep/zoom.txt`, `prep/plaud.txt` і сирих файлів без часу, зсув із кроку 1, зміст `meta.yml`, і вказівка виконати [merge.md](merge.md) і [glossary.md](glossary.md) дослівно: `transcript.md` — розділами, дописуючи у файл; потім `notes.md`. Нагадати: імена Whisper не брати; факти лише з Plaud не брати; дату не вигадувати.
3. Перевірка: `python3 check.py <тека>/transcript.md --raw <тека>/raw` — граматика рядків, частка слів (80–100 %), мовці проти Zoom, порядок часу, час розділів; вибірково три вікна (початок, середина, кінець) звірити з `prep/` і сирими файлами.
4. Звіт користувачу: статистика з `check.py`, головне з `notes.md`, що треба вирішити людині (безіменні мовці, `[?]`, дата).

## summary

Субагенту: `transcript.md`, `context.md` (якщо є) і [summary.md](summary.md). Перевірити: «Теми» дзеркалять `##` транскрипту; у конспекті нема нічого, чого нема в транскрипті.

## check

`python3 check.py <тека>/transcript.md [--raw <тека>/raw]` — статистика і рядки поза граматикою; код виходу 1, якщо такі є.

## Сайт: `bin/lesson`

Тека заняття на сайті — `data/transcripts/<slug>/`, slug = вид + номер (`pz1`, `lab2`, `lec3`, `cons1`, `x1`); для іншого сайту тека задається `LESSONS_DIR=…`. Цикл: `bin/lesson [-t dev] pull <slug>` (сайт → тека: `meta.yml` з `roster` із профілів студентів, сирі файли в `raw/`, наявні тексти) → `/lesson merge` і `/lesson summary` → `bin/lesson push <slug> -m "…"` (тексти й `meta.yml` на сайт, нові сирі файли — теж) → перегляд на `/lessons/<slug>` → `bin/lesson publish <slug>`. Нове заняття — `bin/lesson new <slug> --title … --date … --time … --groups A,B`; файли для студентів — `bin/lesson attach <slug> <файл…>`. Невідомих мовців викладач привʼязує до студентів на сторінці заняття («хто це?») — наступний `pull` принесе їх у `roster`.

Відвідування — `bin/zoom pull <slug> [--meeting <id|uuid>] [--sources]` (T222): учасники зустрічі Zoom → блок «👥 Були» на сторінці заняття; `--sources` докладає хмарний транскрипт як `raw/zoom.vtt`, чат як `raw/chat.txt` і посилання на запис — наступний `bin/lesson pull` принесе їх у теку.

## Куди це йде далі

Ті самі `merge.md` і `summary.md` — промпти для серверної обробки на сайті (вузол `.dev/lessons/`); skill — локальний спосіб робити те саме через Claude Code за підпискою, поки серверної обробки нема.
