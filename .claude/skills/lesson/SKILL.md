# /lesson — транскрипти занять

Тека заняття:

```
<тека>/
├── raw/            # сирі транскрипти: один сервіс = один файл (zoom.txt, zoom-cc.txt, wispr.txt, tana.txt, plaud.txt, chat.txt, …)
├── prep/           # результат prep.py: джерела з часом по рядку на фрагмент із годинником
├── meta.yml        # date, title, time, parts (частини дня за шматками запису), teacher, roster (імʼя в Zoom → як писати)
├── pieces.yml      # шматки запису на диску й до якої частини кожен належить — для bin/lesson video
├── context.md      # необовʼязково: нотатки викладача для конспекту — на що звернути увагу, що витягнути
├── transcript.md   # результат merge — спільна частина заняття
├── parts/          # тексти приватних частин: <key>.transcript.md, <key>.summary.md
├── notes.md        # результат merge: що покривало кожне джерело, що відрізано, зсув годинників, безіменні мовці, [?]
├── summary.md      # результат summary: короткий конспект
└── report.md       # результат summary: докладний звіт для тих, хто не був
```

Теки занять — поза git: у транскриптах імена студентів.

Важку роботу робить субагент на Opus (`Agent`: `subagent_type: general-purpose`, `model: opus`): він читає всі сирі файли цілком і пише результат частинами, дописуючи у файл розділ за розділом; я готую завдання і перевіряю результат. Якщо я сам Opus — роблю сам, без субагента.

## merge

1. Підготовка: `python3 prep.py <тека>/raw` — кожне джерело з часом по рядку на фрагмент у `prep/`, його проміжок і прогалини, зсув Plaud, мовці; для решти — `wc -w`, перші 30 рядків, вигляд міток; `meta.yml`. Дата заняття-дня — у `meta.yml`; коли її там нема — спитати користувача, не вгадувати.
2. Субагенту: шляхи файлів із `prep/` і сирих без часу, вивід `prep.py` (карта покриття), зміст `meta.yml` (частини!), і вказівка виконати [merge.md](merge.md) і [glossary.md](glossary.md) дослівно: `transcript.md` — розділами, дописуючи у файл; приватні частини — у `parts/<key>.transcript.md`; назви, види й нотатки частин — у `meta.yml`; потім `notes.md`. Нагадати: імена Whisper і Wispr не брати; факти лише з Plaud не брати; перерви й усе поза заняттям відрізати; дату не вигадувати.
3. Перевірка: `python3 check.py <тека>/transcript.md --raw <тека>/raw` — граматика рядків, частка слів, мовці проти Zoom, порядок часу, час розділів; вибірково три вікна (початок, середина, кінець) звірити з `prep/` і сирими файлами; у `meta.yml` кожна частина має назву, у приватних частин нічого нема в `transcript.md`.
4. Звіт користувачу: статистика з `check.py`, головне з `notes.md`, що треба вирішити людині (безіменні мовці, `[?]`, «схоже на індивідуальний захист», чого бракувало в джерелах).

## summary

Субагенту: `transcript.md`, `context.md` (якщо є) і [summary.md](summary.md) — обидва виходи: `summary.md` і `report.md`. Перевірити: «Теми» і розділи звіту дзеркалять `##` транскрипту; ніде нема нічого, чого нема в транскрипті; з приватних частин — нічого.

## check

`python3 check.py <тека>/transcript.md [--raw <тека>/raw]` — статистика і рядки поза граматикою; код виходу 1, якщо такі є.

## Сайт: `bin/lesson`

Заняття на сайті — день: адреса `/lessons/2026-11-10`, тека `data/transcripts/2026-11-10/` (друге заняття того ж дня — з міткою: `2026-11-10-cpo`; старі адреси `pz1` ще відкриваються); для іншого сайту тека задається `LESSONS_DIR=…`.

Після пари все потрібне вже лежить на Mac викладача:

1. `bin/lesson scan [--topic Python]` — теки запису Zoom (`~/Documents/Zoom`) проти сайту: що ще не зібрано, що є в кожній.
2. `bin/lesson [-t dev] collect <дата> [--topic "Python Labs"]` — чернетка заняття: частини за шматками запису з годинниковим часом, сирі джерела в `raw/` (`zoom.txt` — транскрипт, збережений у зустрічі; `zoom-cc.txt` — субтитри всього запису; `chat.txt`; `wispr.txt` — зустрічі Wispr Flow за цей час), `pieces.yml`. Tana й Plaud кладуться в `raw/` руками, поки нема їхнього забору.
3. `/lesson merge` і `/lesson summary` у цій теці.
4. `bin/lesson push <дата> -m "…"` — тексти, `meta.yml` з частинами, тексти приватних частин на сайт → перегляд на `/lessons/<дата>` → `bin/lesson publish <дата>`.
5. `bin/lesson video <дата> [--dry]` — шматки запису на Google Drive і в Telegram, посилання — у частини заняття; налаштування — `~/.config/python-labs/video.env` (опис у `bin/lessonvideo.py`).

Ще: `bin/lesson pull <slug>` (сайт → тека: `meta.yml` з `roster` із профілів студентів, сирі файли, наявні тексти), `bin/lesson new <дата> --title …`, файли для студентів — `bin/lesson attach <slug> <файл…>`. Невідомих мовців викладач привʼязує до студентів на сторінці заняття («хто це?») — наступний `pull` принесе їх у `roster`.

Відвідування: `bin/zoom csv <slug> <звіт.csv>` — звіт учасників, який викладач сам експортує на сайті Zoom (Reports → Meeting and webinar history → число учасників → Export, без «Show unique users»), адміністратор не потрібен; `bin/zoom pull <slug> [--meeting <id|uuid>] [--sources]` — те саме через API, коли є ключі (T222).

## Куди це йде далі

Ті самі `merge.md` і `summary.md` — промпти для серверної обробки на сайті (вузол `.dev/lessons/`, T334); skill — локальний спосіб робити те саме через Claude Code за підпискою, поки серверної обробки нема.
