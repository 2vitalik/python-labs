# data/catalog — git-знімок каталогу ігор і завдань

**Джерело правди — MongoDB** (колекції `games`, `tasks`); ці YAML — знімок для diff-ревізії, бекапу і масових правок (рішення: `.dev/platform/.t/T66-B--catalog-storage.md`, T69 Q1c).

- `games.yaml` · `tasks.yaml` — по одному запису на картку; порожні поля опущені.
- Тексти з кількох рядків (опис, приклади) — literal-блоком `|`: поле-клітинки читається у файлі так само, як у тексті ([T160](../../.dev/platform/.t/T160--examples-in-games/report.md)).
- `examples` у грі — приклади ігрових ситуацій: Markdown методички з блоками ` ```field `; на сайті — розділ сторінки гри.
- Обмін: з `app/api/` — `uv run python catalog_io.py export` (Mongo → YAML) та `... import` (YAML → Mongo, upsert по `slug`).
- **З 2026-09-28 знімок у git — із сервера** ([T155](../../.dev/platform/.t/T155--agent-catalog-snapshot/report.md)): `bin/catalog snap` пише сюди каталог із сайту (той самий формат, YAML віддає `GET /api/catalog/snapshot`); після правки агента на сервері це робиться само. Локальний `export` — для дев-бази, його результат не комітимо.
- **З 2026-10-13 чернеток у каталозі нема** ([T213](../../.dev/platform/.t/T213--guide-open-catalog/report.md)): 8 ігор і 135 тасків стали `active` на сервері через `bin/catalog`, каталог відкритий усім; `draft` лишається для нових карток.
- **Чернетка = «ще не переглянута», а не «погана»** ([T275](../../.dev/platform/.t/T275--game-desc-v4/report.md), 2026-11-10): після T213 кожна картка, яку писав агент, ставала ✍️ до перегляду, і їх набралось 108; ревізія активувала 100, чернетками лишились ті, де неясно, що зараховувати, чи спірна ціна (причина кожної — у `catalog/drafts.yaml` задачі). Чернетку бачить лише викладач; студент не може її заявити.
- **Картки лаб** — підкатегорія «Завдання лаб» (`code/labs`): сімʼя на кожну лабу (`lab1`…`lab5`), діти — вимоги її сторінки; картки лаби з інших категорій мають тег `labN` (пошук `lab2` на `/tasks`).
- Сид = перший import; далі оперативні правки — веб-адмінка, пачкові — правка YAML + import.
- Зони/підзони — константа `app/api/zones.py` (дзеркало `data/wiki/tasks/_map.md`); нові ключі спершу туди.
- **Тип картки** (T270): `kind` — що це і де живе заявка (`zones.KINDS`: role · stat · mechanic · rule · fieldopt · field · level · window · element · game); не вказано — тип підзони (третій елемент підзони в `zones.py`), картка з тегом `#window` — тип вікна. В однорядковому записі — `@kind` після ігор: `🥉 Штовхання [sokoban] @rule — …`. Заготовка правила з самих слів (без аргументів) їде в тому ж токені: `@rule(contact?free>push)` — `КОЛИ?ЯКЩО>ТО`, кілька умов чи ефектів через `+` (`@rule(input?free+state>move+counter)`), з типом підзони — без нього: `@(all_gone>win)`; заготовка з аргументами чи `not` — лише словником (`rule: {when, cond, then}`). Розбір — `taskline.py` (`blank()`, `unblank()`, `plain()`).
- Картка з `icon`, `opt` (що вона означає в описі гри: ключ типу сутності, ключ параметра, `властивість:значення` поля), `rule` (заготовка правила `{when, cond, then}`) чи `slots` пишеться словником, як картки з багаторядковим описом.
- `aliases.yaml` — `slug: [назви]` (українські й будь-які, старий формат) або `slug: {uk: […], ru: […], en: […]}`; export пише словник лише картці, що має ru чи en.
- `import --prune` — картки, яких нема в `tasks.yaml`, ідуть в архів (список друкується); без `--prune` import їх не чіпає.
