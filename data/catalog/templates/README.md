# Еталонні описи базових ігор (Д4)

Один файл — одна гра-основа каталогу (`<slug>.yaml`, slug як у `games.yaml`). Це «меню» для студента: кнопка «Почати з еталона» у «Моїй грі» додає поле, сутності, вікна з меню, правила й заявки в його гру (`app/api/templates.py`), далі він викреслює й додає своє. Мова — словники `app/api/models/vocab.py` (тригери, умови, ефекти, властивості поля й рівня) і картки `tasks.yaml`: типи сутностей, параметри й варіанти властивостей поля — теж картки (типи `role` · `stat` · `fieldopt`, їхній `opt` — те, що пишеться тут).

## Формат

```yaml
field:                      # властивості поля за vocab.FIELD (усе необовʼязкове); варіанти — opt карток fieldopt у зоні «Поле»
  topology: square          # square | hex | graph | iso | layers | 1d | 3d | nested
  view: top-down            # top-down | side | first-person
  time: [turn]              # кілька одразу: turn | realtime | static | programmed | wego | rhythm
  control: [direct, click-cell]   # кілька одразу: direct | indirect | click-cell | drag-piece | swipe-all | drag-path | mark | programmed
  gravity: down             # down | up | per-type | toward-center; нема гравітації — не пиши
  wrap: true                # замкнене поле: вийшов за край — зʼявився з протилежного боку
  size: "28×31"             # розмір за замовчуванням, текст
  layers: [підлога, обʼєкти]
entities:
  - title: Пакмен           # назва — ключ: правила посилаються на неї; у грі студента збіг назви = та сама сутність
    role: player            # тип — opt картки типу сутності (підзона «Типи сутностей»)
    icon: "😮"              # своя іконка, необовʼязково; порожньо — іконка типу
    description: "Жовте коло, їсть точки"
    stats: [{key: lives, value: "3"}, {key: швидкість привида, value: "2", unit: "кл/тік"}]   # key — opt картки параметра (назва й одиниця — з картки) або своє слово; двічі той самий — помилка
    states: [звичайний, посилений]       # стани; переходи — правилами set_state / state
    claims: [move-4dir]     # механіки (картки типу mechanic); з параметрами — {slug: spawn-schedule, params: {every: 20}}
rules:
  - when: {kind: contact, a: Пакмен, b: Точка}          # сутності — за назвою; також "*" (будь-хто), а в cond/then — "@a", "@b", "@both"
    cond: [{kind: state, a: "@b", s: переляк, not: true}]   # необовʼязково; not: true — заперечення
    then: [{kind: disappear, a: "@b"}, {kind: score, n: 10}]
    note: "за бажанням"
    claims: [collect-all]   # картки типу rule, які це правило реалізує
windows:
  - title: Гра
    task: game-screen       # картка типу «тип вікна»
    claims: [status-panel]  # елементи вікна (картки типу element: HUD, налаштування, меню)
    items:                  # пункти меню цього вікна (необовʼязково)
      - {title: Грати, window: Гра}        # → вікно за назвою
      - {title: Гучність, task: volume-control}   # → картка
      - {title: Вихід}
levels:                     # рівні гри (необовʼязково)
  - title: Рівні 1–10
    description: "Класичні лабіринти"
    mode: file              # hand (вручну) | file (з файла) | generated (згенерований) | endless (нескінченний)
    count: "10"             # скільки таких, текст
    size: "28×31"
    gravity: down           # будь-яка властивість поля — перекриває загальну на цих рівнях
    stats: [{key: складність, value: "3"}]   # свої параметри рівня, вільні
    claims: [level-from-txt]   # картки типу level
claims: [fog-of-war, save-game]   # картки гри загалом: field → на поле, level і game — без привʼязки, інше ляже в «📥 Чернетки»
```

Тип картки (`kind`) каже, де живе її заявка: `mechanic` — на сутності, `element` — на вікні, `rule` — на правилі, `level` — на рівні або в `claims`, `field` — у `claims` (ляже на поле), `game` — у `claims`. Типи `role`, `stat`, `fieldopt` і «тип вікна» заявками не пишуться: вони обираються як тип сутності, параметр, властивість поля, тип вікна — заявку сайт робить сам. Тип картки — у `tasks.yaml` (`@kind` в однорядковому записі або `kind:`), інакше — за підзоною (`app/api/zones.py`).

## Правила написання

- Лише слова зі словників: `kind` тригера — ключ `TRIGGERS`, умови — `CONDITIONS`, ефекти — `EFFECTS`; аргументи — за `args` відповідного слова (назви й типи). Не лягає — `{kind: custom, text: "…"}` одним реченням.
- Сутності в правилах — назвами з `entities`; підлога/стихія (лід, вода) — теж сутності з роллю `terrain`/`hazard`, бо тригер `enter(a, b)` чекає дві сутності.
- Картки — лише наявні slug-и з `tasks.yaml` (активні й чернетки); вигаданих не писати. Параметри (`params`) — за `slots` картки.
- Картка — туди, куди каже її тип (вище); не туди — імпорт її пропустить (`skipped` з причиною), а на рівні гри механіка, елемент чи правило ляже студентові в «📥 Чернетки». Механіка спільна для кількох сутностей (ходи фігур, розстановка рослин) — на одній, найпоказовішій: картка рахує монетку не більше `max_count` разів на гру.
- Обсяг: 4–10 сутностей, 8–20 правил, 3–6 вікон, 5–15 заявок — те, що справді є в класичній версії гри, без фан-розширень; це стартове меню, не енциклопедія.
- Джерела: файл гри в `data/ludopedia/games/`, опис і приклади в `data/catalog/games.yaml`, нотатки `data/wiki/games/`.
- Перевірка: імпорт у смоуку (`tests/smoke_games.py`) має пройти без `skipped` — помилкове слово чи картка потраплять у список пропущеного. До імпорту — `validate.py <файл>` (команда в його шапці): слова, картки, тип кожної картки проти місця, де вона записана, типи сутностей і варіанти властивостей поля проти карток каталогу.
