# Демо-студенти

Вигадані тестові студенти з описаними іграми — щоб у деві бачити «Мою гру» заповненою, не клацаючи самому.

```
cd app/api && uv run python demo_io.py seed [імʼя…]   # створити наново (усіх або названих)
cd app/api && uv run python demo_io.py drop [імʼя…]   # прибрати
```

Лише дев: без `FAKE_USER_EMAIL` скрипт не працює. `seed` щоразу прибирає студента з грою і створює наново — наклацане в його грі зникає.

Файл `<імʼя>.yaml` → студент `demo.<імʼя>@nure.ua` з прапорцем «тестовий», група `ПЗПІ-25-0`. Зайти — 👁 у його рядку на `/students` (повний запис); паспорт очима викладача — `/students/demo.<імʼя>`.

| файл | основа | що показує |
|---|---|---|
| `new` | — | гри ще нема: форма створення |
| `empty` | Змійка | гра щойно створена: «Почати з еталона», підказки |
| `etalon` | Сокобан | еталон як є — базова версія без свого: картки на правилах, рівні з файла й із редактора |
| `sketch` | Лабіринт | початок руками: мало всього, підказки, 📥 чернетки (картки правил без правила, елемент без вікна), картки без обовʼязкового параметра |
| `tanks` | Танчики | усе на максимум: 23 сутності, 15 вікон з графом, скриншоти, вердикти ✓ і ↩ |
| `chess` | Шахи | фігурна покрокова: ШІ з глибиною, тор, перетягування; вердикти на картках еталонних правил, етюди й задачі в рівнях; майже все зараховано |
| `sudoku` | Паперові пазли | предикати обмежень, корона; рівень на кожен тип пазла (у слізерлінка поле — граф), пазл дня; викладач ще не дивився |
| `pvz` | Рослини проти зомбі | економіка й хвилі, ізометрія; денні й нічні рівні різного розміру, нескінченний; більшість повернуто |
| `rogue` | своя | без еталона: гекси, 12 фаз, 12 станів, згенеровані поверхи, усі зони каталогу |
| `tiles` | 2048 | хід рухає все поле: гравітація, вид збоку, шаблони й каскади |

## Формат

Як в еталонів ([README](../catalog/templates/README.md)), і ще:

- `student` — прізвище, імʼя, група; `game` — `title`, `base_game` або `base_custom`, `description`, `phases`. Без `game` — студент без гри.
- `etalon: true` — спершу еталон основи, потім своє з файла. Сутність, вікно чи рівень з назвою еталонного — те саме: додаються лише картки (тип, іконка, параметри з файла не діють); `items` вікна замінюють еталонне меню.
- Правило, що слово в слово (КОЛИ · ЯКЩО · ТО) збігається з еталонним, зливається з ним — так вердикт вішають на картку еталонного правила: повторити правило з цією карткою в `claims`.
- `field` замінює еталонне поле цілком (і картки на ньому); у ньому ще `description` і `claims` — картки на полі.
- Картка — туди, куди каже її тип, як в еталонів: правило — у `rules[].claims`, рівень — у `levels[].claims` або в `claims`, поле — у `field.claims`. Тип сутності, параметр і властивість поля заявляються самі, без вердикту. Правило, механіка чи елемент у верхніх `claims` лягають у «📥 Чернетки» — так навмисно лише в `sketch`.
- Картка в `claims` (поля, сутності, вікна, рівня, правила чи гри) може нести `note`, `link`, `status` (`accepted` · `returned`) і `verdict` — слово викладача.
- `shots` у полі, сутності, вікні чи рівні — скриншоти: ASCII-мапа, символ — клітинка свого кольору (`app/api/demo_shots.py`).

Перевірка — сам `seed`: слово чи картка, яких нема у словниках і каталозі, потрапляють у «пропущено».
