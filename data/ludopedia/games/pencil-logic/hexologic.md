# Hexologic — Какуро на гексах: точки 1–3 у клітинах, суми вздовж трьох осей

## Суть
Поле — фігура з гексів; на краях стоять стрілки з числами. Гравець клацає по гексу, перебираючи 1 → 2 → 3 → порожньо точок, і має заповнити всі гекси так, щоб сума точок уздовж кожної лінії, на яку вказує стрілка, дорівнювала числу. Ядро — Kakuro без заборони повторів, але з трьома напрямками ліній замість двох. Кожна з шести зон додає новий тип гекса (фіксований, звʼязаний, «сумуючий», знаки порівняння), тож тримається на «відкритті нового правила» — звідси `also: thinky`.

## Поле і час
- Гексова сітка довільної форми (не обовʼязково суцільна); лінії — прогони гексів у трьох осях (шести напрямках стрілок).
- Стрілка-підказка на кінці лінії: ціле число суми; не кожна лінія має стрілку.
- Статичний пазл без часу; виняток — спецрівні в кінці зон з таймером.
- Шари: гекс (тип) + значення (0–3 точки або фіксоване число).

## Сутності
| Сутність | Роль | Параметри | Поведінка |
|---|---|---|---|
| Порожній гекс | mark | значення 0–3 точки | клік перебирає 1 → 2 → 3 → порожньо; рівень не здається, поки є порожні |
| Фіксований гекс | static | число, може бути > 3 | значення задане й не змінюється, входить у суми ліній |
| Звʼязаний гекс | mark | колір обведення | зміна одного ставить те саме значення всім гексам того ж кольору |
| Багатоколірний гекс | mark | список гексів-джерел | його значення = сума точок у гексах указаних кольорів (?) |
| Гекс-знак `=` | static | — | гекси з двох боків мають бути рівні (балансування) (?) |
| Гекси-знаки `<` / `>` | static | — | значення з одного боку менше/більше, ніж з іншого |
| Стрілка-підказка | zone | число N, напрямок | лінія гексів за стрілкою повинна мати суму N; в easy-режимі зеленіє, коли сума правильна |

## Правила (КОЛИ → ЯКЩО → ТО)
- КОЛИ `input(hex)` → ЯКЩО не фіксований → ТО `set_value(hex, (v+1) mod 4)`, `custom: «перебір 1→2→3→порожньо»`, `sound(chime)`.
- КОЛИ `input(hex)` → ЯКЩО фіксований або знак → ТО `block`.
- КОЛИ `after(set_value(hex))` → ЯКЩО `same(hex, other, outline_color)` → ТО `set_value(other, v)` — звʼязані гекси копіюють значення.
- КОЛИ `after(set_value(any))` → ЯКЩО гекс багатоколірний залежить від змінених → ТО `custom: «перерахувати суму джерел»` (?).
- КОЛИ `after(set_value(hex))` → ЯКЩО `sum(line, N)` і `mode(easy)` → ТО `custom: «стрілка лінії зеленіє»`.
- КОЛИ `after(set_value(hex))` → ЯКЩО `mode(hard)` → ТО жодної підсвітки: гравець перевіряє суми сам.
- КОЛИ `all_constraints_met` → ЯКЩО `count(empty_hex, ==, 0)` → ТО `win`, `sound(level_done)`, `next_level`.
- Обмеження: `sum(line, N)` для кожної стрілки; `custom: «ліва частина = права»` для знака `=`; `custom: «ліва < права»` / `«ліва > права»` для знаків порівняння.
- КОЛИ спецрівень і `timer(remaining, ==, 0)` → ТО `custom: «спецрівень не зараховано»` (?).
- Перемога: усі гекси заповнені й усі суми та співвідношення виконані. Поразки нема (крім таймера спецрівнів (?)). Рахунку нема.

## Керування і ввід
- Клік/тап по гексу циклічно змінює кількість точок; на Switch — кнопка Y (у ручному режимі тап).
- Пробувати можна скільки завгодно: помилка не карається, значення просто перебирається далі.

## Вікна, меню, HUD
- `main-menu` → хаб: рівні однією довгою вертикальною стрічкою знизу вгору, від туторіалу (`level-select`); оглядачі скаржаться на навігацію.
- `game-screen`: поле, стрілки-підказки (зеленіють у easy як `conflict-highlight` навпаки), без лічильників.
- `difficulty-select` / перемикач easy ↔ hard (?) де саме — невідомо.
- `settings-window`: звук/музика (?).
- Переходи: хаб → рівень → (розвʼязано) → наступний рівень у стрічці; кінець зони → 3 спецрівні.

## Фічі поза полем
- `levels-sequential` + `level-unlock`: рівні проходяться по порядку; 6 зон, кожна вводить нову механіку.
- Спецрівні: по 3 в кінці кожної зони, більші й складніші; за оглядом Switch — з таймером.
- `difficulty-presets`: easy (зелені стрілки) і hard (без підсвітки, ті самі пазли).
- Випадково згенеровані рівні поза кампанією.
- Музика, що нашаровує інструменти в міру розвʼязання частин пазла; дзвіночок на кожну точку.
- `achievements` (Steam).

## Варіації й родичі
- Сімʼя: [kakuro](kakuro.md) (суми в прогонах, без повторів), [sudoku](sudoku.md), Killer sudoku; гексові пазли — Hexcells (дедукція на гексах, `hidden-deduction`), Sumplete (`word-number`, суми рядків через викреслення).
- **Осі варіацій**: напрямки ліній — 2 (Kakuro) / 3 (гекси); діапазон значень — 1–9 без повторів / 1–3 з повторами; типи клітин — лише вільні / фіксовані / звʼязані / похідні (сума інших) / знаки порівняння; підсвітка — миттєва / лише в кінці / нема.

## Цікавинки для курсу
- Гексова сітка з трьома осями ліній і стрілками-сумами: індексація ліній в осьових координатах — 🥉.
- Клік-перебір 0→1→2→3→0 + перевірка суми кожної лінії — 🌱.
- Звʼязані гекси (зміна одного змінює всі того ж кольору) — 📎.
- Похідний гекс = сума інших гексів (залежності між клітинами) — 🥉.
- Генератор рівнів із перевіркою єдиності розвʼязку — 🥇 (є випадкові рівні; унікальність не підтверджено).
- Easy/hard як вмикач підсвітки виконаних обмежень — 🌱.

## Непевне
- (?) Кількість рівнів залежить від версії: 75 (60 + 15) у ранніх оглядах, «90+» на Steam, 90 + 21 за досягненнями, «110+» у Xbox Store (з пошукового переказу).
- (?) Багатоколірний гекс: «поєднує точки інших гексів» — ймовірно, його значення = сума гексів відповідних кольорів, але точне правило не перевірено.
- (?) Знак `=`: «балансування гексів з двох боків» — що саме порівнюється (сусіди чи суми груп) — не перевірено.
- (?) Таймер спецрівнів згадано лише в огляді Switch 2018; у PC-огляді 2022 його не названо.
- (?) Чи гарантується єдиність розвʼязку і як працює генератор випадкових рівнів.
- Клас: гра радше `pencil-logic` (розмітка за обмеженнями), ніж `thinky` — покладено в `pencil-logic/` з `also: [thinky]`, як просив куратор.
