# Gyromite — професор не стрибає: червоні й сині ворота-стовпи підіймає справжній робот R.O.B., кладучи гіроскоп на кнопку пульта

## Суть
Бічний клітинний платформер-пазл, що постачався з роботом R.O.B.: професор Гектор у Game A має зібрати весь динаміт у лабораторії до кінця часу, а шлях перекривають червоні й сині ворота-стовпи. Ворота рухає не гравець напряму, а **фізичний робот**: гравець натискає Start, екран синіє, і наступна команда пульта (вгору/вниз/вліво/вправо, відкрити/закрити руки) іде роботу; той переносить гіроскоп на лоток, де лежить другий пульт, і гіро тисне кнопку A чи B — ворота свого кольору опускаються. Обидва кольори разом потребують розкрученого гіро, що стоїть сам. Game B — непрямий режим: Гектор-сновида йде праворуч сам, а гравець через робота відкриває й закриває йому шлях.

## Поле і час
- Бічна квадратна сітка лабораторії; у Game A екран скролить убік, відкриваючи інші бомби; на паузі хрестовиною можна оглянути всю сцену.
- Час — реальний: таймер фази, Smick рухаються, робот фізично виконує команду кілька секунд, поки гра йде далі.
- Шари: стіни й підлога · мотузки (вертикальний рух) · ворота-стовпи двох кольорів (рухомий шар, кілька клітин заввишки) · сутності (професори, Smick, динаміт, редиски) · у Game B — тунелі, ями зі Smick, стрілки.
- Поза екраном — «друге поле»: робот, два гіро, спінер, червоний і синій лотки з пультом 2.

## Правила (КОЛИ → ЯКЩО → ТО)
- КОЛИ `input(left|right)` (чорний екран) → ЯКЩО `free(next)` → ТО `move(hector, dir)`; закриті ворота → `block`.
- КОЛИ `input(up|down)` → ЯКЩО `cell(here, rope)` → ТО `move(hector, dir)`; стрибка нема — динаміт знизу береться, спустившись на нього мотузкою.
- КОЛИ `enter(hector, dynamite)` → ТО `pickup`, `score(100)`, `counter(dynamite_left, -1)`.
- КОЛИ `counter(dynamite_left, =, 0)` → ТО `win`, `score(+time_left)`, `next_level`.
- КОЛИ `input(start)` → ТО `custom: «фон синіє: наступна команда пульта 1 надсилається роботу, після передачі фон знову чорний»`.
- КОЛИ `input(dir|A|B)` (синій екран) → ТО `custom: «R.O.B. виконує одну команду: руки вгору/вниз, поворот уліво/вправо, A — розкрити, B — стиснути»`.
- КОЛИ `custom: «гіро лежить на синьому лотку»` → ТО `set_state(blue_gates, lowered)`; КОЛИ `custom: «гіро знято з лотка»` → ТО `clear_state(blue_gates, lowered)` (?); так само для червоних.
- КОЛИ `custom: «потрібні обидва кольори»` → ЯКЩО `state(gyro, spinning)` → ТО `custom: «одне розкручене гіро стоїть на лотку саме, руки робота вільні для другого»`.
- КОЛИ `input(A|B)` (чорний екран) → ЯКЩО `occupied(here, turnip)` → ТО `pickup(hector, turnip)`; ЯКЩО `has(hector, turnip)` → ТО `place(hector, turnip)`.
- КОЛИ `adjacent(smick, turnip)` → ТО `set_state(smick, eating)` — не нападає на професора (?).
- КОЛИ `contact(hector, smick)` → ЯКЩО `not state(smick, eating)` → ТО `lives(-1)`, `respawn(hector, phase_start)` (?).
- КОЛИ `custom: «ворота зсунулись на клітину зі Smick»` → ТО `disappear(smick)`, `score(500)`.
- КОЛИ `counter(time_left, =, 0)` → ТО `lives(-1)`.
- КОЛИ `counter(professors, =, 0)` → ТО `game_over`, `window(main-menu)`.
- КОЛИ `input(select)` → ТО `custom: «пауза; хрестовина гортає всю сцену»`; КОЛИ `input(start)` на паузі → ТО `game_over`, `window(main-menu)`.
- Game B: КОЛИ `tick` → ТО `move(hector, right)`; ЯКЩО `occupied(next, closed_gate)` → ТО `custom: «крокує на місці»`.
- Game B: КОЛИ `enter(hector, rope)` → ТО `custom: «вилазить нагору й зістрибує праворуч»`.
- Game B: КОЛИ `enter(hector, arrow)` → ТО `custom: «мусить піти в напрямку стрілки, інакше — в яму»`; КОЛИ `custom: «обігнав стрілку»` → ТО `score(100)`.
- Game B: КОЛИ `enter(hector, hole)` → ТО `lives(-1)` (Smick кусає); КОЛИ `reach(hector, right_tunnel)` → ТО `next_level`.
- Game B: КОЛИ `custom: «пройдено всі 25 фаз»` → ТО `speed(hector, +1)`, `custom: «курси йдуть по колу»`.
- Перемога: Game A — увесь динаміт фази зібрано; Game B — професор дійшов до правого тунелю. · Поразка: укус Smick або кінець часу забирає професора; три втрачені — кінець гри. · Рахунок: динаміт +100, роздавлений Smick +500, бонус за залишок часу; у Game B — +100 за кожну обігнану стрілку і +500 за Smick.

## Керування і ввід
- Пульт 1: Select — вибір режиму в меню, пауза в грі; Start — старт, у Game A — перемикання «керую професором / шлю команду роботу»; хрестовина — професор (чорний екран) або робот (синій); A/B — розкрити/стиснути руки робота або взяти/покласти редиску.
- Game B: хрестовина й A/B завжди керують роботом напряму, без Start.
- Пульт 2 лежить у лотку робота кнопками A і B до важелів; натискає їх гіро, а не людина.
- R.O.B. «бачить» екран: команди передаються шістьма видами спалахів; потрібен ЕПТ-телевізор, режим Test калібрує голову робота на екран.

## Вікна, меню, HUD
- `main-menu` (select mode menu): Test · Direct · Game A 1P · Game A 2P · Game B; кнопки A/B обирають стартову фазу.
- `custom-window` Test — калібрування робота: тестовий спалах має засвітити його червоний індикатор.
- `custom-window` Direct — тренування: команди пульта одразу йдуть роботу, без гри.
- `game-screen` — лабораторія; колір тла як `mode-toggle`: чорний — керую професором, синій — передача роботу; HUD — `score`, `timer-countdown`, номер фази «R=01» (`level-number`), `lives` професорів (?).
- `pause-menu` — без пунктів: пауза з оглядом сцени хрестовиною; Start — вихід у меню.
- Переходи: main-menu → (Select/A/B) → game-screen → (динаміт зібрано / тунель) → наступна фаза → … → (3 професори втрачено) → main-menu.

## Фічі поза полем
- `level-select`: стартова фаза з меню; Game A — 40 фаз, Game B — 25 фаз від R=01, далі коло з прискоренням.
- `hotseat`: Game A на двох — Гектор і Вектор по черзі на одному пульті.
- `physical-peripheral`: фізичний робот і гіро — «повільний» ввід із затримкою, що сам є частиною складності; без робота гру проходять, тиснучи кнопки пульта 2 рукою (?).
- Пауза з оглядом усієї сцени; нема збереження, паролів, редактора.

## Варіації й родичі
- Famicom: «Robot Gyro» у наборі Gyro Set (13.08.1985); NES: у Deluxe Set з R.O.B. (1985), згодом окремим картриджем; парний набір — Stack-Up / Robot Block.
- Родичі: Lemmings (непрямий режим — веди того, хто йде сам; Game B), Lode Runner (мотузки, клітинна лабораторія), Mario vs. Donkey Kong (кольорові перемикачі блоків), Door Door (вороги в пастках), Troddlers (керування середовищем замість героя).
- Осі варіацій:
  - **хто рухає перешкоди**: сам аватар / кнопка на полі / окремий канал вводу з затримкою (робот R.O.B.).
  - **керування героєм**: пряме (Game A) / герой іде сам, гравець змінює лише середовище (Game B).
  - **кольорові групи**: усі ворота кольору разом / окремі важелі.

## Цікавинки для курсу
- Два канали одного пульта: режим «аватар» і режим «команда роботу» з індикацією кольором тла — 📎.
- Ворота-групи за кольором, що тримаються опущеними, поки «натиснута» кнопка (стан-утримання, а не перемикач) — 🌱.
- Ворота, що давлять ворога при русі, + очки — 📎 (перевірка перетину рухомого стовпа з сутністю).
- Сновида Game B: детермінований автомат руху (йти праворуч, мотузка → нагору → стрибок праворуч, закрито → крокувати на місці, стрілка → повернути) — 🥉.
- Приманка-редиска: ворог міняє ціль з гравця на предмет — 📎.
- Затримка команди (команда виконується через N тіків, поки світ рухається) як модель «повільного робота» — 🥉.
- Розвʼязувач Game B (симуляція сновиди з розкладом відкриття воріт) — 🥇.

## Непевне
- (?) Чи ворота повертаються, щойно гіро зняли з лотка (мануал: потрібне розкручене гіро, щоб тримати двоє воріт, — отже, утримання), і чи всі ворота кольору рухаються разом; у деяких фазах ворота можуть бути «опущені» за замовчуванням.
- (?) Чи можуть ворота розчавити самого професора; чи професор падає з висоти без шкоди.
- (?) Як Smick поводиться біля редиски (стоїть і їсть / тимчасово) і як рухається без неї.
- (?) Де відроджується професор після втрати (початок фази чи місце смерті); тривалість таймера фази.
- (?) Проходження без робота кнопками пульта 2 — поширена практика, у мануалі не описано.
