# Laser Reflection — сховай дзеркала й чорні діри на сітці для суперника, а потім наввипередки розгадай чужу коробку лише за довжинами й кольорами променів

## Суть
Цифрова гра Board Game Arena (у панелі — «Reflection») на 1–6 гравців. Кожен отримує **однаковий набір обʼєктів** (дзеркала, іноді чорні діри) і ставить їх на свою сітку — це пазл для інших. Потім пазли роздаються по колу: розвʼязувач бачить лише клітини з числами по краю — кожна «стріляє» лазером усередину, а число й колір кажуть, скільки клітин пройшов промінь і чим скінчився його шлях. Хто швидше розставить обʼєкти так, щоб **усі** промені збіглися з підказками, той отримує більше очок. Ядро — обернена задача трасування, як у [Black Box](black-box.md), але з довжиною шляху замість точки виходу.

## Поле і час
- Квадратна сітка з рамкою числових клітин по краю; розмір (?).
- Дві фази раунду: **побудова** (кожен розставляє свій набір без обмеження часу, «ready») і **розвʼязання** (одночасно, на час: перемагає швидкість).
- Поле під час розвʼязання статичне (`time: static`); темп задає лише годинник розвʼязання для рахунку.
- Розвʼязувач не бачить розставлених обʼєктів суперника — лише краєві підказки й власні пробні розстановки.

## Сутності
| Сутність | Роль | Параметри | Поведінка |
|---|---|---|---|
| Числова клітина краю | mark | число + колір | випускає лазер усередину поля перпендикулярно краю; число = скільки клітин промінь перетнув до виходу з поля |
| Зелена клітина | mark | число | промінь виходить через іншу зелену клітину з тим самим числом (пара) |
| Жовта клітина | mark | число | промінь відбивається від пласкої поверхні й повертається у свою ж клітину |
| Сіра клітина | mark | число | промінь закінчується в чорній дірі через N клітин |
| Кутове дзеркало | object | / або \ | відхиляє промінь під прямим кутом; найчастіший обʼєкт |
| Подвійне дзеркало | object | горизонтальне / вертикальне | пласкими гранями відбиває промінь назад; паралельний промінь проходить між гранями без змін |
| Квадратне дзеркало | object | 4 грані | відбиває промінь назад з будь-якого боку |
| Чорна діра | hazard | лише з опцією | поглинає промінь — шлях закінчується |
| Світловий портал | terrain | завжди пара; лише з опцією | промінь, що увійшов в один, виходить з іншого; гравці їх не ставлять |
| Лазер | projectile | напрямок | трасується від числової клітини до виходу / повернення / поглинання |
| Набір обʼєктів | supply | однаковий для всіх, випадковий на партію | усі обʼєкти мають бути розставлені |

## Правила (КОЛИ → ЯКЩО → ТО)
- Сетап: КОЛИ `game_start` → ТО `custom: «випадково обрати набір обʼєктів, однаковий для всіх гравців»`.
- Побудова: КОЛИ `input(place, object, cell)` → ЯКЩО `free(cell)` → ТО `place(player, object)`.
- КОЛИ `input(ready)` → ЯКЩО `count(tray_objects, =, 0)` (усі обʼєкти на полі) → ТО `set_state(player, ready)`.
- КОЛИ `custom: «усі гравці ready»` → ТО `custom: «кожен отримує пазл іншого гравця: видно лише числа й кольори краю»`, `timer(start)`.
- Трасування: КОЛИ `enter(laser, angled_mirror)` → ТО `custom: «промінь повертає на 90° за нахилом дзеркала»`.
- КОЛИ `enter(laser, square_mirror)` → ТО `bounce(laser)` (назад).
- КОЛИ `enter(laser, double_mirror)` → ЯКЩО `moving(laser, across_faces)` → ТО `bounce(laser)`; ЯКЩО `moving(laser, along_faces)` → ТО `custom: «проходить між гранями без змін»`.
- КОЛИ `enter(laser, black_hole)` → ТО `disappear(laser)` (шлях закінчено — сіра підказка).
- КОЛИ `enter(laser, warp)` → ТО `teleport(laser, other_warp)`.
- КОЛИ `edge(laser)` → ТО `custom: «довжина шляху й тип завершення (інша клітина / своя / поглинання) — підказка цієї клітини»`.
- Перевірка розвʼязувача: КОЛИ `constraint_broken(edge_clue)` → ТО `mark(edge_cell, red_outline)`.
- КОЛИ `all_constraints_met` → ТО `custom: «пазл розвʼязано, час зафіксовано»` — зараховується будь-яка розстановка, що задовольняє всі промені.
- КОЛИ `input(give_up)` → ТО `custom: «пазл не зараховано; гравець чекає кінця раунду»`.
- КОЛИ `custom: «усі розвʼязали або здались»` → ТО `custom: «наступний раунд — пазл наступного гравця»`.
- Рахунок: КОЛИ `custom: «пазл розвʼязано»` → ТО `score(+n)` за місцем за швидкістю (найшвидший — найбільше).
- КОЛИ `game_over` → ТО `win` гравцю з найбільшими очками; нічия → менший сумарний час.
- Соло: КОЛИ `custom: «пазл провалено»` → ЯКЩО `counter(hearts, >, 0)` → ТО `counter(hearts, -1)`; інакше `lose`. КОЛИ `counter(solved, =, 3|6|10)` (за складністю) → ТО `win`.
- Перемога: найбільше очок за швидкі розвʼязки · Поразка (соло): серця скінчились · Рахунок: місце за часом у кожному раунді.

## Керування і ввід
- Побудова: перетягнути / клацнути обʼєкт із лотка й поставити в клітину; переставляти вільно до «ready» (деталі UI (?)).
- Розвʼязання: та сама розстановка своїм набором на чужому пазлі; червона рамка на числовій клітині миттєво показує, що її промінь поки не збігається.
- Кнопка «здатися» — у будь-який момент.

## Вікна, меню, HUD
- `match-setup` (BGA): кількість гравців, опції — з чорними дірами й порталами чи без, соло-складність.
- `construction-screen` (custom-window): своя сітка, `object-tray` з набором, кнопка ready.
- `game-screen` (розвʼязання): чужа сітка з `edge-clue` по периметру, лоток, `conflict-highlight` червоних рамок, `timer-elapsed`, кнопка give up, панель гравців із прогресом.
- `end-screen`: очки за раунди, сумарний час; соло — пройдено / серця.
- `help-window`: довідка BGA з фізикою променя.
- Переходи: match-setup → construction-screen → (усі ready) game-screen → наступний раунд … → end-screen.

## Фічі поза полем
- `custom-rules`: увімкнути чорні діри й портали.
- Соло-режим: 3 / 6 / 10 пазлів за складністю, старт з одним серцем (один дозволений провал), на середній і важкій можна заробити ще одне серце.
- `online-multiplayer` BGA (реальний час), `auto-check` через червоні рамки.

## Варіації й родичі
- [Black Box](black-box.md) — та сама обернена задача променів, але відповідь — точка виходу/поглинання, а не довжина; [Triangulation](triangulation.md) — дедукція прихованого за вимірюваннями.
- Лазерні пазли з видимими дзеркалами: Deflektor, Khet, Chromatron (сімʼя `connect-rotate`); Orapa Space (?) — настолка з прихованими планетами й лазером, не перевірено.
- **Осі варіацій**: підказка «довжина / точка виходу / колір»; хто ставить пазл «суперник / генератор»; перевірка «будь-яке сумісне / рівно авторське»; обʼєкти «дзеркала / + поглиначі / + портали».

## Цікавинки для курсу
- Трасування променя по сітці з кутовими, подвійними й квадратними дзеркалами, порталами й чорними дірами → (довжина, тип завершення) для кожної краєвої клітини — 🥉.
- Генерація підказок з розстановки гравця — той самий трасувальник, запущений з усіх клітин краю — 📎.
- Живий валідатор розвʼязку (червоні рамки) — 📎.
- Розвʼязувач: перебір розстановок набору з відсіканням за частково трасованими променями — 🥇.
- Перевірка унікальності пазла, який склала людина (скільки розстановок дають ті самі підказки) — 🥇.
- Раундова структура «побудуй — обміняйся — розвʼяжи на швидкість» з рейтингом за часом — 📎.

## Пропозиції до словників
- `+effect:trace_ray` — протрасувати промінь від клітини до завершення (Black Box, Laser Reflection).
- `+effect:deflect` — промінь змінює напрям на 90° від кутового дзеркала (не `bounce`, що розвертає назад).
- `+trigger:all_ready` — усі гравці завершили фазу підготовки.
- `+cond:ray_consistent` — промінь з клітини краю дає саме ту довжину й тип завершення, що в підказці.
- `+role:mirror` — обʼєкт, що змінює напрям променя (кутовий / подвійний / квадратний).
- `+ui:edge-clue` — число + колір на клітині рамки поля.
- `+ui:object-tray` — лоток обʼєктів, які ще треба розставити.
- `+window:construction-screen` — екран побудови власного пазла для суперників.
- `+feature:give-up` — здатися на поточному пазлі без виходу з партії.

## Непевне
- (?) Розмір сітки, кількість обʼєктів у наборі й кількість раундів (ймовірно, по раунду на пазл кожного суперника) — у джерелах нема.
- (?) Чи всі клітини рамки мають підказки, чи лише частина; чи світлові портали видимі розвʼязувачу.
- (?) Як саме нараховуються очки за місце (шкала) і що вважається провалом у соло (здача чи ліміт часу).
- (?) Чи існує фізична настолка — BGA видавця не вказує; `platforms` — лише web.
- (?) Як число рахує клітини для жовтої клітини (шлях туди й назад цілком) — з формулювання «скільки клітин перетнув до виходу».
