# Entombed — нескінченний лабіринт росте знизу з таблиці «5 сусідів → стіна?», а екран штовхає тебе вниз крізь зомбі

## Суть
Археолог спускається нескінченним дзеркально-симетричним лабіринтом, що безперервно прокручується вгору: кого винесло за верхній край — гине. Лабіринт не зберігається в памʼяті — кожен новий ряд генерується на льоту: для кожної клітини беруться 5 уже відомих сусідів (2 ліворуч у цьому ряду, 3 над нею) і за таблицею з 32 записів обирається «стіна / прохід / випадково». Така генерація інколи дає глухі кути без виходу — тому є **make-break**: заряд, що ламає або ставить стіну. Гра відома радше алгоритмом, ніж геймплеєм: його реверс-інжиніринг став предметом трьох наукових статей.

## Поле і час
- Ширина: ігрове поле Atari 2600 (playfield) — 20 біт на половину рядка; 4 біти — постійна бічна стіна, решта 16 — 8 згенерованих клітин, кожна подвоєна. Друга половина — дзеркальне відображення (вертикальна вісь симетрії), тож лабіринт має 16 клітин ширини між бічними стінами.
- Кожен «ряд лабіринту» займає кілька рядків екрана; лабіринт = 60 рядів = 5 секцій (одиниця рахунку).
- Real-time: поле повзе вгору постійно (вимушена прокрутка); видно лише вікно, нові ряди відкриваються знизу.
- Генерація використовує спільний з рештою гри PRNG, тож лабіринт щоразу інший.

## Сутності
| Сутність | Роль | Параметри | Поведінка |
|---|---|---|---|
| Археолог (1–2) | player | 3 життя (квадратики вгорі) | 4 напрямки; кнопка + напрям — make-break |
| Стіна лабіринту | static | біт ряду, дзеркальна пара | непрохідна; ставиться/ламається make-break на обох половинах одночасно |
| Бічна стіна | static | 4 біти з кожного боку | завжди є; з неї беруться стартові біти контексту |
| Блимаючий блок (make-break) | pickup | — | дотик дає 2 (перемикач A) або 3 (перемикач B) заряди |
| Заряд make-break | resource | старт — 1 | витрачається на злам або постановку однієї стіни |
| Зомбі синій | enemy | — | рухається лише коридорами; дотик — смерть |
| Зомбі помаранчевий | enemy | — | проходить крізь стіни; дотик — смерть |
| Верхній край екрана | hazard | рухається разом з прокруткою | археолога, якого винесло за край, — смерть |

## Правила (КОЛИ → ЯКЩО → ТО)
- КОЛИ `timer(scroll)` → ТО `shift(all, up)`.
- КОЛИ `custom: «знизу відкривається новий ряд»` → ТО `custom: «згенерувати 8 клітин зліва направо за таблицею»` (пропозиція `+trigger:row_revealed`):
  - для клітини X контекст — `a, b` (дві клітини ліворуч у новому ряду) і `c, d, e` (три над X у попередньому ряду); 5 біт → один з 32 записів таблиці → `wall` / `open` / `custom: «випадковий біт PRNG»`;
  - для першої клітини `a = 1`, `b = 0` (бічна стіна), `c` — випадковий біт; для восьмої `e` лежало б за віссю симетрії (= `d`), тож замість нього — випадковий біт;
  - вікно контексту зсувається на 1 вправо після кожної клітини; кожен біт подвоюється, ряд дзеркалиться на праву половину.
- КОЛИ `custom: «ряд згенеровано»` → ЯКЩО `custom: «останні 11 рядів мають 0 у крайньому лівому стовпці»` або `custom: «останні 7 біт центрального стовпця збігаються з 9-м від кінця»` → ТО `custom: «обнулити весь або частину останнього ряду»` (постобробка, ламає повторювані візерунки).
- КОЛИ `input(dir)` → ЯКЩО `free(cell_in_dir)` → ТО `move(player, dir)`; інакше `block`.
- КОЛИ `input(fire+dir)` → ЯКЩО `counter(make_breaks, >, 0)` → ТО `set_cell(cell_in_dir, open|wall)` (стіна → прохід, прохід → стіна) і так само для дзеркальної клітини, `counter(make_breaks, -1)`.
- КОЛИ `contact(player, blinking_block)` → ТО `pickup`, `counter(make_breaks, +2)` (перемикач складності A) або `+3` (B).
- КОЛИ `edge(player)` (верхній край) → ТО `lose` (−1 життя).
- КОЛИ `contact(player, zombie)` → ТО `lose` (−1 життя).
- Зомбі щотік: синій — `custom: «рух лише коридорами»`; КОЛИ `state_on(zombie, orange)` → ТО `custom: «проходить крізь стіни»`.
- КОЛИ `custom: «пройдено секцію лабіринту»` → ЯКЩО `mode(game_1)` → ТО `score(+1)`.
- КОЛИ `custom: «у Game 2 живий лише один археолог»` → ТО `win` для нього (рахунку нема).
- КОЛИ `counter(lives, ==, 0)` → ТО `game_over`.
- Перемога: нема (1P — виживання на дистанцію); 2P — останній живий. · Поразка: 3 життя втрачено. · Рахунок: кількість пройдених секцій (5 на лабіринт).

## Керування і ввід
- Джойстик — 4 напрямки руху.
- Кнопка, утримана під час руху, — make-break у напрямку руху: зламати стіну (вибратись з тупика) або поставити (відгородитись від зомбі).
- Перемикачі консолі: Difficulty A/B — 2 чи 3 заряди з блимаючого блоку; Game 1 / Game 2 — 1 чи 2 гравці.

- `game-screen` — прокручуваний лабіринт; HUD: `lives` (квадратики вгорі ліворуч / праворуч для кожного гравця), `score` (секції) внизу праворуч.
- `mode-select` — через перемикач консолі (Game 1 / Game 2), без окремого екрана (?).

## Фічі поза полем
- `mode-versus` / `mode-coop` в одному режимі Game 2: обидва в одному лабіринті одночасно; можна змагатися (загородити суперника, забрати його make-break) або допомагати (відкрити прохід, відвести зомбі).
- `difficulty-presets` — фізичні перемикачі A/B.
- Нема збережень, рекордів, паузи.

## Варіації й родичі
- Алгоритм: за спогадами Paul Allen Newell, генератор «нескінченного лабіринту, що завжди має розвʼязок» придумали в барі й параметризували за складністю; у фінальній грі розвʼязність не гарантована — тому make-break. Mächler & Naccache (2021) пояснюють таблицю й узагальнюють на 3D.
- Родичі за ідеєю «поле генерується рядами»: Eller's algorithm (розвʼязні лабіринти по одному ряду), Crossy Road (нескінченні смуги), Devil World і 10000000 (рухоме поле вбиває).
- Осі варіацій:
  - **генерація**: збережена мапа / повний лабіринт DFS / ряд за рядом з локального контексту (Entombed, Eller) / клітинний автомат;
  - **гарантія проходу**: гарантована (Eller) / ні, але є «ремонт» гравцем (make-break) / ні;
  - **прокрутка**: камера за гравцем / вимушена, край убиває (Entombed) / поле рухає ворог (Devil World).

## Цікавинки для курсу
- Генератор ряду з таблиці 5 сусідів → {стіна, прохід, випадково}: точне відтворення за таблицею зі статті — 🥉; дослідження властивостей таблиці (частка тупиків, Karnaugh-карта) — 👑.
- Перевірка, чи новий ряд досяжний зверху (BFS по вікну) і порівняння з Eller — 🥇.
- Дзеркальне поле, де одна правка міняє обидві половини, — 🌱.
- Make-break як обмежений ресурс «ремонту» лабіринту з напрямним вводом (кнопка + напрям) — 📎.
- Вимушена прокрутка з «краєм смерті» — 🌱.
- Постобробка проти повторюваних візерунків (детектор шаблону в останніх N рядах) — 📎.
- Детермінований PRNG: той самий seed → той самий лабіринт (порівняння з оригіналом, як у статті) — 📎.
