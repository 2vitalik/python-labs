# Suikyo — сокобан збоку, де світ над водою і під водою має протилежну гравітацію

## Суть
Вид збоку на рівень, поділений горизонтальною лінією водяної поверхні: зверху «небо», знизу «вода». У небі все падає вниз, під водою все спливає вгору — нижня половина працює як дзеркало верхньої. Гравець ходить ліворуч/праворуч, штовхає ящики й **пірнає** крізь поверхню (↓ з неба, ↑ з води), опиняючись у дзеркальній половині з протилежною гравітацією. Ядро — дві «гравітаційні зони» на одному полі і спеціальні червоні ящики, що пірнають разом із гравцем.

## Поле і час
- Квадратна сітка, вид збоку; рівень на один екран. Поле — дві зони: `sky` (гравітація вниз) і `wat` (гравітація вгору), між ними — ряд поверхні (`mirror`, здебільшого суцільний разом зі стіною).
- Шари клітини: фон зони (небо/вода) + стіна або обʼєкт (гравець, ящик) + службові позначки (дріт, ціль, чекпойнт).
- Покроково: тік = один ввід; після руху в тому ж тіку відпрацьовують «late»-правила — падіння/спливання, смерть на поверхні, перемальовування. Анімація пірнання і проїзду по дроту йде серією підтіків (`again`) без вводу.
- Повна інформація, випадковості нема.

## Сутності
| Сутність | Роль | Параметри | Поведінка |
|---|---|---|---|
| Гравець | player | зона: небо / вода (спрайт змінюється) | ←/→ — крок; у небі падає вниз, у воді спливає вгору, доки нема опори; ↓/↑ — пірнає крізь поверхню |
| Ящик неба (білий) | object | 1×1 | штовхається вбік; падає вниз, доки під ним порожньо |
| Ящик води (темний) | object | 1×1 | штовхається вбік; спливає вгору, доки над ним порожньо |
| Червоний ящик (S) | object | небо або вода | як звичайний, але пірнає крізь поверхню разом із гравцем і змінює зону (небо ↔ вода) |
| Широкий ящик | object | кілька клітин у ряд (ліва/середня/права частини) | рухається й падає/спливає як жорстке ціле; тримається, якщо опора хоча б під однією частиною (?) |
| Звʼязаний ящик (L) | object | пара: ящик неба над ящиком води в одному стовпці, між ними намальований звʼязок | кожен падає/спливає за своєю зоною; звʼязок перемальовується щотіку (точна механіка — у «Непевне») |
| Мертвий ящик | object | — | ящик, що потрапив у клітину поверхні; інертний, лишається там |
| Поверхня (дзеркало) | hazard | ряд між зонами | гравець у клітині дзеркала гине; ящик у ній стає мертвим; пірнання проходить крізь неї |
| Стіна неба / води / поверхні | static | 3 види | непрохідні; стіна поверхні тримає і те, що падає, і те, що спливає |
| Ціль | gate | стоїть на дроті | гравець, що став на ціль, зникає з неї й їде дротом |
| Дріт | terrain | ланцюг клітин від цілі до кінця | везе гравця по клітинці за підтік до `wireEnd` |
| Кінець дроту | static | — | точка, де гравець виходить з дроту; знімається після проїзду |
| Чекпойнт | static | на дроті | проїзд через нього ставить гравця туди й записує точку |
| Фінальна брама | gate | лише на фінальній картинці | гравець ступає — брама зникає (кінець гри) |

## Правила (КОЛИ → ЯКЩО → ТО)
- КОЛИ `input(left|right)` → ЯКЩО `free(cell_ahead)` → ТО `move(player, dir)`; ЯКЩО `occupied(cell_ahead, crate)` → ТО `push(crate)`; стіна — `block`.
- КОЛИ `after(move)` → ЯКЩО `state(a, sky)` і `free(cell_below)` → ТО `fall(a)` (гравець, ящики неба, червоні ящики неба).
- КОЛИ `after(move)` → ЯКЩО `state(a, water)` і `free(cell_above)` → ТО `custom: «спливти вгору на клітину»` (дзеркальне `fall`).
- КОЛИ `after(move)` → ЯКЩО широкий ящик → ТО `custom: «падає/спливає всіма частинами разом, лише якщо вільно під кожною»` (?).
- КОЛИ `input(down)` → ЯКЩО `state(player, sky)` і `free(landing_cell)` → ТО `custom: «пірнути: пройти крізь поверхню в першу вільну клітину води»`, `set_state(player, water)`.
- КОЛИ `input(up)` → ЯКЩО `state(player, water)` → ТО `custom: «пірнути вгору в першу вільну клітину неба»`, `set_state(player, sky)`.
- КОЛИ `after(custom: «пірнання гравця»)` → ЯКЩО `count(red_crate_same_zone, >, 0)` → ТО `custom: «червоні ящики пірнають теж»`, `transform(red_crate_other_zone)`: небесний червоний стає водяним і навпаки (?).
- КОЛИ `input(down|up)` → ЯКЩО `occupied(landing_cell, wall|crate|player)` → ТО `block`.
- КОЛИ `enter(player, mirror)` → ТО `custom: «гравець гине»`, `sound(death)`; рестарт рівня не автоматичний — лише `undo`/`restart`.
- КОЛИ `enter(crate, mirror)` → ТО `transform(dead_crate)`, `sound(death)`.
- КОЛИ `contact(player, goal)` → ЯКЩО ціль на дроті → ТО `disappear_b`, `custom: «гравець їде дротом по клітинці за підтік до кінця»`.
- КОЛИ `enter(player, checkpoint)` під час проїзду дротом → ТО `move(player, checkpoint)`, `checkpoint`.
- КОЛИ `reach(player, wireEnd)` → ТО `custom: «кінець дроту знімається, гравець виходить»`.
- КОЛИ `contact(player, finalgate)` → ТО `disappear_b`.
- КОЛИ `all_gone(goal)` і `all_gone(wireEnd)` і `all_gone(finalgate)` → ТО `win`, `next_level`.
- КОЛИ `input(Z)` → ТО `undo(1)`; КОЛИ `input(R)` → ТО `restart`.
- Перемога: на полі не лишилось цілей, кінців дроту й фінальної брами. Поразка: формально нема — гравець «мертвий» стоїть у дзеркалі, доки не зробиш undo/restart. Рахунку нема.

## Керування і ввід
- ← / → — крок і поштовх; ↓ (з неба) / ↑ (з води) — пірнути крізь поверхню.
- Z — undo (необмежений, стандарт PuzzleScript), R — рестарт рівня, X — старт/дія в меню, M — вимкнути звук.
- Стрибка нема: вертикальний рух дають лише гравітація зон і пірнання.

## Вікна, меню, HUD
- `main-menu` (титул PuzzleScript): New Game / Continue, вибір рівня; автор попереджає, що вибір рівня працює з багом і краще починати з New Game.
- `game-screen`: поле на весь екран, без HUD; між секціями — текстові повідомлення (`message`), напр. про джем і кількість рівнів.
- `end-screen`: «congratulations!» після фінальної брами.
- Переходи: main-menu → game-screen → (усі цілі) → наступний рівень → … → фінальна картинка з брамою → end-screen.

## Фічі поза полем
- `undo` ∞, `restart-level`.
- `levels-sequential`: Tutorial → Box-1…6 → Rbox-1…10 (червоні ящики) → Bbox-1…5; збереження фіксує лише факт проходження рівня (`save-progress`).
- `checkpoint` — на дротах усередині рівня.
- Звукові ефекти (смерть, проходження), `sound-toggle` (M).

## Цікавинки для курсу
- Дві гравітаційні зони на одному полі (вниз над поверхнею, вгору під нею) — 🥉: `fall` з напрямком, що залежить від зони клітини.
- Пірнання: пошук першої вільної клітини по той бік поверхні з перевіркою блоку — 📎.
- Червоні ящики, що пірнають разом із гравцем і змінюють зону — 🥉 (одночасний рух кількох сутностей одним вводом).
- Широкий ящик як жорстке тіло, що падає цілим — 🥈 (опора хоча б під однією частиною, рух групи).
- Проїзд гравця по дроту з чекпойнтами як анімація без вводу — 📎.
- Порядок «рух → late-правила гравітації → перевірка смерті» в одному тіку — 🥉 (класична пастка порядку оновлення).

- `+effect:dive` — пройти крізь межу зон у першу вільну клітину по той бік, змінивши зону/стан (Suikyo).

## Непевне
- (?) Червоні ящики: правило `[down Player sky][CrateAS no mirror]` у PuzzleScript матчить будь-який червоний ящик на полі, тож пірнають, імовірно, всі червоні ящики зони разом із гравцем — висновок з переказу коду, не з гри.
- (?) Звʼязані ящики (L): за переказом коду вони рухаються незалежно, а звʼязок лише малюється; у коді є посилання на невизначене ім'я, тож задум автора неясний.
- (?) Чи штовхає гравець ланцюжок ящиків і чи може піднятися на сходинку — у переказі не підтверджено.
- (?) Умова опори широкого ящика (під кожною частиною чи під будь-якою).
- (?) Окремі клітини дзеркала без стіни — «діри» в поверхні, куди можна впасти й загинути; так випливає з легенди (`$` = дзеркало, `-` = стіна + дзеркало).
- (?) Рік: сторінка дат не має; гіст створено 2023-06-30, девлоги — липень 2023, тож 2023, а не 2025 з черги.
- (?) У коді 25 карт, у грі заявлено 21 рівень — різниця, імовірно, навчальні карти й картинки.
