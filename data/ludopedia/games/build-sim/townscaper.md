# Townscaper — клікни, і блок сам вирішить, чим стати: дім, арка, сходи чи сад

## Суть
Гравець лише додає або прибирає кольоровий блок у клітині нерівної квадової сітки посеред безкрайнього моря. Що саме вийде з блока — стіна з вікнами, дах, арка над проходом, сходи, балкон, сад у дворику, будиночок на палях — вирішує процедурний генератор за **контекстом сусідів**. Цілі, очок і програшу нема: автор (Oskar Stålberg) сам називає її «більше іграшкою, ніж грою». Для корпусу — чистий приклад «розміщення з контекстними правилами» і нерегулярної сітки.

## Поле і час
- Поле — велика **спотворена сітка чотирикутників** у нескінченному морі: базова гексагональна сітка ділиться на трикутники/квади, потім точки «релаксуються» (зсуваються), і кожна клітина — неправильний чотирикутник. Суміжність — по ребрах квада (зазвичай 4 сусіди, біля «вузлів» гексагона — інші кількості) (?).
- Поле **3D-стовпцеве**: кожна клітина — стовпчик рівнів; блок ставиться на воду (рівень 0) або поверх/збоку від наявного. Стан поля — множина зайнятих комірок (клітина × висота) + колір кожної.
- Геометрія будується не по клітинах, а по **кутах**: кожен кут сітки дивиться на 8 сусідніх комірок (2 рівні × 4 кути) і обирає меш-фрагмент — як marching cubes.
- Часу як механіки нема: кожна дія миттєво перераховує околицю; декор (вікна, кущі, птахи) «доростає» з невеликою затримкою, що росте з розміром споруди.
- Камера вільна (обертання, зум, нахил) (?); туман/межі поля — нема видимої межі, лише кінець сітки (?).

## Сутності
| Сутність | Роль | Параметри | Поведінка |
|---|---|---|---|
| Блок (комірка) | tile | колір, висота | зайнята/порожня; більше нічого не зберігає — увесь вигляд виводиться з сусідів |
| Вода | terrain | — | рівень 0; блок на воді стає будинком із причалом/островом |
| Кут сітки | static | 8 бітів зайнятості навколо | обирає модуль (стіна, кут, дах, арка, порожнеча) за маскою сусідів |
| Стіна з вікнами | object | колір блока | грань між зайнятою і порожньою комірками; вікна вирізаються по ній |
| Дах | object | колір | верх стовпця, над яким порожньо; форма даху — за обрисом групи |
| Арка / прохід | object | — | зайнята комірка над порожньою між двома опорами |
| Палі / опори | object | — | зайнята комірка над порожнечею без бічних опор — «місто на ходулях» |
| Сходи | object | — | перепад висоти між сусідніми плоскими ділянками |
| Сад / дворик | zone | — | плоска ділянка, з усіх боків замкнена стінами (рецепт) |
| Низька огорожа між ділянками | object | — | на кутах будинків або на межі різних кольорів |
| Балкон, комин, лава, кущ, ліхтар | object | — | дрібний декор, обирається за типом грані/кута |
| Птахи, метелики | neutral | — | прості агенти: «чіпляються» до ближніх обʼєктів, кружляють, реагують на геометрію |

## Правила (КОЛИ → ЯКЩО → ТО)
- КОЛИ `input(click, cell)` на воді → ТО `set_cell(cell, block[color])` на рівні 0.
- КОЛИ `input(click, face_of_block)` → ТО `set_cell(neighbor_cell_in_face_dir, block[color])` (згори — новий поверх, збоку — сусідня клітина на тій самій висоті).
- КОЛИ `input(remove, block)` → ТО `set_cell(cell, empty)`.
- КОЛИ `after(set_cell)` → ТО для кожного кута в околиці: `custom: «перерахувати модуль за 8-бітною маскою зайнятості сусідніх комірок»` (dual-grid / marching cubes).
- КОЛИ `after(set_cell)` → ТО `custom: «WFC: для кожної комірки звузити множину допустимих модулів, доки сусідні модулі сумісні за гранями»`; рецепти мають пріоритет над загальними патернами; невдача — «тиха» (лишається спрощений модуль, напр. нескріплена опора).
- КОЛИ комірка зайнята ЯКЩО `cell(below, empty) and cell(left, occupied) and cell(right, occupied)` → ТО модуль «арка» (?).
- КОЛИ комірка зайнята ЯКЩО `cell(below, empty)` і бічних опор нема → ТО `custom: «палі до води»`.
- КОЛИ дві сусідні плоскі ділянки ЯКЩО різниця висот = 1 → ТО `custom: «сходи»` (?).
- КОЛИ `pattern(region_closed)` плоскої ділянки → ТО `custom: «сад»`: садові модулі мають край лише «біля стіни», тож сад виникає тільки в замкненому дворику.
- КОЛИ на куті будинку ЯКЩО `not same(a, b, color)` → ТО `custom: «низька стінка між ділянками»`.
- КОЛИ `after(set_cell)` → ТО `custom: «декор: вікна, комини, кущі, лави»` з затримкою.
- Перемоги/поразки нема. Рахунку нема.

## Варіації й родичі
- Bad North (той самий автор): WFC на звичайній квадратній сітці — для генерації островів, а не для відповіді на клік.
- Брати по ідеї «місцеві правила вирішують тайл»: автотайлінг у 2D-рушіях (бітмаска 4/8 сусідів), Dorfromantik (край до краю), Islanders, Tiny Glade.
- Осі варіацій: **сітка** — квадрат / гекс / нерегулярні квади; **де живе правило** — у клітині (автотайл 4-біт) / у куті (dual grid, 8 біт у 3D) / у WFC-солвері з глобальною сумісністю; **хто ініціює** — гравець ставить блок vs генератор сам будує.

## Цікавинки для курсу
- Автотайл за 4-бітною маскою сусідів (стіна/кут/торець) на квадратній сітці в консолі — 🥉: один словник 16 символів, а поле «оживає».
- Dual grid: правило в кутах, 8 бітів у 3D (256 випадків, із симетріями менше) — 🥈.
- WFC як солвер сумісності модулів (звуження множин + пропагація + відкат) — 🥇: класичний алгоритм, гарно ділиться на кроки.
- Генерація нерівної квадової сітки: гекс → трикутники → злиття в квади → релаксація — 🥇 (геометрія + граф суміжності).
- Рецепт «сад лише в замкненому дворику» — 🥉: flood fill по плоскій ділянці з перевіркою, що межа — стіни.
- Колір як другий шар правила (межа кольорів → огорожа) — 📎.

## Пропозиції до словників
- `+trigger:input` — клік/тап по грані; `+trigger:after` — каскад перерахунку після `set_cell`.
- `+cond:adjacent_count` / `+cond:cell` — маска зайнятості сусідів визначає модуль; `+cond:same` — однаковість кольору сусідів.
- `+effect:set_cell` — додати/прибрати блок; `+effect:autotile` — обрати модуль клітини за маскою сусідів (зараз `custom`).
- `+role:tile` (блок), `+role:neutral` (птахи), `+role:zone` (сад).
- `+ui:element-picker` (палітра кольорів), `+ui:undo-button`.
- `+feature:mode-sandbox`, `+feature:share-code` (місто рядком), `+feature:photo-mode` — фото-режим зі світлом і камерою (нове).
- `+axis:field=irregular-quad` — нерегулярна квадова сітка (зараз лише `graph`); `+axis:goal=none` — іграшка без мети (зараз довелося ставити `state`).
- `+card:context-tile-rules` — див. вище.

- (?) Точні умови арки, сходів, балкона й паль — виведено з опису «залежно від розташування блоків»; джерела не дають правил явно.

- (?) Керування (права кнопка = прибрати, перефарбування кліком), undo/redo, фото-режим, збереження й обмін містом рядком — з памʼяті, не перевірено на сторінці.
