# Piet — програма-картина: вказівник переходить між кольоровими блоками, а команду задає зміна відтінку і яскравості

## Суть
Piet — езотерична мова David Morgan-Mar, де програма — растрове зображення, схоже на абстракції Піта Мондріана (назва — на його честь). Вказівник рухається від одного суцільного кольорового блоку до сусіднього, і **команду визначає не колір, а різниця кольорів**: скільки кроків по колу відтінків і по колу яскравості між блоком, з якого вийшли, і блоком, куди ввійшли.

Дані — один стек цілих; число потрапляє в стек як **площа** (кількість коделів) блоку, з якого вийшли. Для корпусу це «Befunge з кольорів»: потік керування задає геометрія плям, а «рівень» — це картинка.

## Поле і час
- Поле — прямокутна сітка коделів (кодел — «піксель коду»; картинку часто збільшують, і кодел займає кілька пікселів).
- Колірний блок — звʼязна за 4 сусідами група коделів одного кольору (діагональ не рахується); форма будь-яка, з дірками.
- 20 кольорів: 6 відтінків по колу (червоний → жовтий → зелений → блакитний → синій → пурпуровий → червоний) × 3 яскравості по колу (світлий → звичайний → темний → світлий) + білий і чорний поза колами.
- Інші кольори — на розсуд реалізації (зазвичай як білий, іноді як чорний); край зображення діє як чорний.
- Час `programmed`: тік = перехід з поточного блоку в сусідній і виконання команди переходу. Старт — у блоці з лівим верхнім коделом; DP дивиться праворуч, CC — ліворуч.

## Сутності
| Сутність | Роль | Параметри | Поведінка |
|---|---|---|---|
| Вказівник напрямку (DP) | player | → ↓ ← ↑ | у який бік шукати вихід з блоку |
| Вибирач кодела (CC) | player | ліворуч / праворуч відносно DP | серед коделів крайнього ребра обирає крайній у свій бік |
| Кольоровий блок | terrain | відтінок 0–5, яскравість 0–2, площа n | перехід з нього — команда за різницею кольорів; n — значення для push |
| Білий блок | terrain | — | прохід без команди: вказівник ковзає прямо |
| Чорний блок / край | static | — | непрохідний; змушує перемикати CC і повертати DP |
| Інший колір | terrain | — | як білий або чорний — залежно від реалізації |
| Стек | supply | цілі, довжина й величина необмежені (ідея) | push / pop; команди, яким бракує значень, ігноруються |
| Перехід між блоками | conduit | Δвідтінок 0–5 × Δяскравість 0–2 | одна з 17 команд таблиці (0/0 — нічого) |

Таблиця команд (Δвідтінок — кроків уперед по колу відтінків; Δяскравість — кроків «темніше» по колу):

| Δвідтінок \ Δяскравість | 0 | 1 | 2 |
|---|---|---|---|
| 0 | — | push | pop |
| 1 | add | subtract | multiply |
| 2 | divide | mod | not |
| 3 | greater | pointer | switch |
| 4 | duplicate | roll | in(number) |
| 5 | in(char) | out(number) | out(char) |

## Правила (КОЛИ → ЯКЩО → ТО)
- КОЛИ `tick` → ТО `custom: «знайти ребро блоку, найдальше в бік DP; на ньому — кодел, найдальший у бік CC»`, `move(dp, next_block)`.
- КОЛИ `exec(transition)` → ЯКЩО `custom: «обидва блоки кольорові»` → ТО `custom: «команда з таблиці за Δвідтінком і Δяскравістю, рахуючи вперед по колах»`.
- КОЛИ `blocked(dp)` → ЯКЩО `custom: «попередня спроба повертала DP або це перша спроба»` → ТО `custom: «перемкнути CC і спробувати знову»`.
- КОЛИ `blocked(dp)` → ЯКЩО `custom: «попередня спроба перемикала CC»` → ТО `rotate(dp, 90)` — на крок за годинниковою, і знову спроба.
- КОЛИ `counter(attempts, ==, 8)` → ТО `custom: «кінець програми»` — єдиний спосіб завершитись.
- КОЛИ `enter(dp, white)` → ТО `slide(dp, dir)` прямо до кольорового блоку; команда не виконується, тож білим міняють колір без операції.
- КОЛИ `custom: «упор під час ковзання по білому»` → ТО `custom: «перемкнути CC, повернути DP на 90° за годинниковою й ковзати знову з того самого білого кодела»`.
- КОЛИ `repetition` → ЯКЩО `custom: «маршрут по білому повторився»` → ТО `custom: «кінець програми»`.
- КОЛИ `exec(push)` → ТО `custom: «push площі блоку, з якого вийшли»` — значення блоку саме в стек не кладеться.
- КОЛИ `exec(pop)` → ТО `custom: «викинути вершину»`.
- КОЛИ `exec(add|subtract|multiply|divide|mod)` → ТО `custom: «зняти верхнє a і друге b, покласти b ∘ a»`.
- КОЛИ `exec(mod)` → ТО `custom: «знак результату як у дільника: −1 mod 3 = 2»`.
- КОЛИ `exec(divide|mod)` → ЯКЩО `custom: «дільник 0»` → ТО `custom: «на розсуд реалізації; автор радить ігнорувати»`.
- КОЛИ `exec(not)` → ТО `custom: «push 1, якщо вершина 0, інакше push 0»`.
- КОЛИ `exec(greater)` → ТО `custom: «push 1, якщо друге зверху більше за верхнє, інакше 0»`.
- КОЛИ `exec(pointer)` → ТО `rotate(dp, 90 × pop)` — за годинниковою; відʼємне — проти.
- КОЛИ `exec(switch)` → ТО `custom: «перемкнути CC стільки разів, скільки модуль знятого значення»`.
- КОЛИ `exec(duplicate)` → ТО `custom: «покласти копію вершини»`.
- КОЛИ `exec(roll)` → ТО `custom: «зняти кількість прокруток, потім глибину; прокрутити верхні значення на цю глибину»`.
- КОЛИ `exec(roll)` → ЯКЩО `custom: «глибина відʼємна»` → ТО `custom: «команду ігнорувати»`.
- КОЛИ `exec(in)` → ТО `custom: «прочитати число або символ (код Unicode) і покласти в стек»`.
- КОЛИ `exec(out)` → ТО `custom: «pop і вивести як число або як символ»`.
- КОЛИ `custom: «команді бракує значень у стеку»` → ТО `custom: «ігнорувати й виконувати далі»`.
- Перемоги й поразки нема: результат — вивід програми. Нуль і відʼємні числа блоком не закодуєш — їх обчислюють операторами.

## Керування і ввід
- Програміст малює зображення в будь-якому растровому редакторі або в спеціальному (npietedit на Tcl/Tk, онлайн-IDE); колір кожного наступного блоку обирають за потрібною командою відносно попереднього.
- Запуск — інтерпретатором (npiet читає PPM, PNG, GIF; є трасування); у візуальних IDE — крок / біг, підсвітка блоку, стек (?).
- Під час виконання — лише ввід для `in(number)` і `in(char)`.

## Вікна, меню, HUD
(цифрова версія — типова Piet-IDE (?))
- `editor-window`: полотно коделів, палітра 20 кольорів таблицею 6×3 + білий і чорний, підказка «який колір дасть команду X після поточного», розмір кодела.
- `game-screen` виконання: підсвічений поточний блок (`instruction-highlight`), стрілки DP і CC, `stack-view`, вивід; `step-button`, `speed-slider`, `restart-button`.
- Консоль виводу з полем вводу для `in`.
- Переходи: малювання → Run / Step → (8 невдалих спроб) кінець → назад у редактор.

## Фічі поза полем
- `step-mode` і `speed-control` — у візуальних IDE; npiet — текстове трасування (приклад для програми «Hi»).
- `export-import`: програма — звичайний PNG / GIF / PPM, ділитися можна як картинкою.
- Генератори коду: ascii-piet (текст → Piet), npiet-foogol (мова foogol → Piet, «далеко не завершений»).
- Спільнота: Hello World (анімований GIF), truth-machine, 99 Bottles of Beer, FizzBuzz з генератора, інтерпретатор Brainfuck на Piet (доказ повноти за Тюрінгом), геокеш-головоломка.

## Варіації й родичі
- [Befunge](befunge.md) — та сама ідея «програма на 2D-сітці зі стеком», але символи-інструкції замість різниці кольорів і стрілки замість DP / CC.
- **Hexagony** (Martin Ender, 2015): код розкладено правильним шестикутником (доповнення `.` до центрованого гексагонального числа 1, 7, 19, 37…); 6 вказівників у кутах, активний один, `[` `]` `#` перемикають.
- У Hexagony вихід за край веде на протилежний край, у кутах — розгалуження за знаком поточної памʼяті; памʼять — нескінченна гекс-сітка, значення лежать на **ребрах**, дзеркала `/ \ _ |` відбивають вказівник.
- Варіанти Piet за esolangs: Piet++, 🅿🅸🅴🆃, Pietfood, pgmpiet (не відкривав).
- Родичі в корпусі: [Opus Magnum](opus-magnum.md) і [SpaceChem](spacechem.md) (інструкції лежать на полі), [Turing Tumble](turing-tumble.md) (фізична «картина-програма»), [Kara](kara.md).
- **Осі варіацій**: чим кодується команда (символ / колір / різниця кольорів) · звідки число (цифра / площа блоку) · сітка (квадратна / гекс) · вказівників (1 / 6) · памʼять (стек / ребра гекс-сітки / саме поле) · як завершитись (`@` / 8 невдалих спроб).
