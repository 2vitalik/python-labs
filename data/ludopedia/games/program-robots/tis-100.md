# TIS-100 — паралельний асемблер на сітці вузлів 4×3, які спілкуються лише через блокувальні порти із сусідами

## Суть
Гравець «лагодить» вигаданий компʼютер TIS-100: це сітка з 12 крихітних процесорів-вузлів, кожен зі своєю програмою до 15 рядків асемблера й одним регістром-акумулятором. Дані входять зверху, виходять знизу, а між вузлами пересуваються тільки через порти з сусідами, і запис у порт чекає, доки сусід прочитає. Завдання: перетворити вхідні потоки чисел на очікувані вихідні (сума, порівняння, сортування, малювання на дисплеї). Після розвʼязку — оптимізація за трьома метриками й гістограми.

## Поле і час
- Поле — **сітка 4×3 вузлів** (квадратна, кожен вузол — велика клітина з текстовим редактором усередині); сусіди — 4 напрямки, діагоналей нема.
- Зверху вузлів — колонки входів (IN.A, IN.B…), знизу — виходів (OUT.A…) і, у пізніх пазлах, графічний дисплей; конкретний пазл задає, до яких вузлів вони приєднані.
- Деякі вузли **зіпсовані** (червоні, з повідомленнями) — їх обходять; у пазлах з памʼяттю частину вузлів замінено на **стек-вузли**.
- Час `programmed`: цикл — кожен вузол паралельно виконує одну інструкцію (або чекає на порт); програма кожного вузла циклічна (після останнього рядка — на перший).
- Детермінізм у межах тесту; тести — набори вхідних чисел, частина згенерована випадково (?).

## Сутності
| Сутність | Роль | Параметри | Поведінка |
|---|---|---|---|
| Обчислювальний вузол (T21) | player | ≤ 15 інструкцій, ACC, BAK | виконує свою програму циклічно; стан: RUN / READ / WRTE / IDLE (?) |
| `ACC` | container | ціле −999…999 (?) | акумулятор: усі обчислення через нього |
| `BAK` | container | ціле | резерв; доступний лише через `SAV` і `SWP` |
| `NIL` | static | — | читання дає 0, запис зникає |
| Порти `UP`/`DOWN`/`LEFT`/`RIGHT` | conduit | 1 значення | спільні з сусідом; запис блокує, доки сусід не прочитає |
| `ANY` / `LAST` | conduit | — | будь-який готовий порт / той, що вжили останнім |
| Стек-вузол (T30) | container | до 15 значень | будь-який сусід може покласти/зняти значення (LIFO) |
| Зіпсований вузол | static | — | не виконує нічого, не спілкується з сусідами |
| Вхід IN.x | source | список чисел | подає наступне число при читанні |
| Вихід OUT.x | sink | очікуваний список | приймає число; невідповідне — позначено помилкою |
| Графічний дисплей | sink | малий растр, 5 кольорів | малює пікселі за потоком x, y, кольори… |
| Інструкції даних | — | `MOV src, dst` · `SWP` · `SAV` | пересилання між регістрами/портами/ACC; обмін і копія ACC↔BAK |
| Арифметика | — | `ADD src` · `SUB src` · `NEG` | ACC ± значення; зміна знака |
| Переходи | — | `JMP` · `JEZ` · `JNZ` · `JGZ` · `JLZ` · `JRO src` | стрибок на мітку (за умовою ACC = 0, ≠ 0, > 0, < 0) або відносний на N рядків |
| `NOP` | — | — | нічого (еквівалент `ADD NIL`) |
| Мітка | mark | `NAME:` | ціль стрибка |
| Коментар / breakpoint | mark | `#` / `!` | `!` на рядку зупиняє виконання для дебагу |
| `HCF` | hazard | недокументована | «Halt and Catch Fire» — аварійно зупиняє систему |

## Правила (КОЛИ → ЯКЩО → ТО)
- КОЛИ `tick` → ТО `custom: «кожен вузол, що не чекає, виконує поточну інструкцію; потім переходить на наступну (циклічно)»`.
- КОЛИ `exec(MOV)` → ЯКЩО `custom: «dst — порт сусіда»` → ТО `custom: «вузол чекає, доки сусід прочитає значення»`.
- КОЛИ `exec(MOV)` → ЯКЩО `custom: «src — порт»` → ТО `custom: «вузол чекає, доки сусід запише значення»`, потім `set_value(dst, v)`.
- КОЛИ `exec(MOV ANY)` → ТО `custom: «взяти з першого готового порту / віддати першому, хто читає»`; `LAST` — той самий порт, що й минулого разу.
- КОЛИ `exec(ADD|SUB)` → ТО `set_value(ACC, ACC ± src)`; ЯКЩО `custom: «результат поза межами»` → ТО `custom: «значення обрізається до межі»` (?).
- КОЛИ `exec(NEG)` → ТО `set_value(ACC, −ACC)`.
- КОЛИ `exec(SAV)` → ТО `set_value(BAK, ACC)`; `exec(SWP)` → ТО `swap(ACC, BAK)`.
- КОЛИ `exec(JMP)` → ТО `custom: «перехід на мітку»`.
- КОЛИ `exec(JEZ|JNZ|JGZ|JLZ)` → ЯКЩО `counter(ACC, ==|!=|>|<, 0)` → ТО `custom: «перехід на мітку»`; інакше на наступний рядок.
- КОЛИ `exec(JRO)` → ТО `custom: «перехід на src рядків відносно поточного, з обмеженням першим/останнім рядком»`.
- КОЛИ `custom: «вузол пише в стек-вузол»` → ТО `custom: «значення на вершину стека»`; читання ЯКЩО `custom: «стек порожній»` → ТО `custom: «читач чекає»`.
- КОЛИ `custom: «вузол читає IN.x»` → ЯКЩО `custom: «у потоці ще є числа»` → ТО `custom: «наступне число»`.
- КОЛИ `custom: «число записано в OUT.x»` → ЯКЩО `custom: «не збігається з очікуваним на цій позиції»` → ТО `custom: «позначити помилку в колонці виходу»`, тест провалено.
- КОЛИ `exec(HCF)` → ТО `crash`.
- КОЛИ `custom: «рядок з !»` → ТО `custom: «пауза для дебагу»`.
- КОЛИ `custom: «усі виходи отримали очікувану кількість правильних значень»` → ТО `custom: «наступний тестовий набір»`.
- КОЛИ `custom: «усі тестові набори пройдено»` → ТО `win`, `window(end-screen)` з метриками й гістограмами.
- Перемога: виходи збігаються з очікуваними на всіх тестах · Поразка: нема — невдалий тест показує помилку, правиш код · Рахунок: **cycles** (тривалість), **nodes** (зайняті вузли), **instructions** (рядки коду) — менше краще.

## Керування і ввід
- Клік у вузол → текстовий редактор усередині (≤ 15 рядків, обмежена ширина рядка (?)); набір асемблера з клавіатури.
- Кнопки внизу: STOP, STEP (один цикл), RUN, FAST; `!` на початку рядка — точка зупинки.
- Під час покрокового запуску кожен вузол показує ACC, BAK, режим (RUN/READ/WRTE/IDLE) і підсвічує поточний рядок; порти показують значення «в польоті».
- Копіювання/вставлення між вузлами; мануал — окремий PDF, задуманий для друку.

## Пропозиції до словників
- `+trigger:port_read(node, dir)` — сусід прочитав значення з порту (розблокування писача).
- `+cond:port_ready(dir)` — у порту є значення / сусід готовий читати.
- `+effect:send(port, v)` / `+effect:recv(port)` — обмін повідомленням між акторами (ширше за `set_value`).
- `+effect:jump(to)` — перехід вказівника програми (спільне з Core War).
- `+effect:wait` — актор пропускає тік, доки не виконана умова.
- `+role:node`, `+role:port`.
- `+window:spec-panel` (завдання + потоки IN/OUT), `+window:manual`.
- `+ui:node-mode-label`, `+ui:io-columns`, `+ui:breakpoint`.
- `+feature:breakpoints`, `+feature:specification-editor`.
