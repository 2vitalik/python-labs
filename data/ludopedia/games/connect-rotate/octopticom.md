# OCTOPTICOM — «оптична електроніка»: збери з дзеркал і фільтрів схему, що читає кольорову стрічку і пише потрібну

## Суть
Зах-подібна (Zachtronics-стиль) програмувальна гра без коду: на сітці розставляєш дзеркала, розщеплювачі, кольорові фільтри й оптичні «транзистори», щоб світло перетворило вхідні послідовності кольорових клітин на вихідні. Рівні — це задачі цифрової логіки (AND, XOR, двійкове↔вісімкове, додавання), але сигнал — колір променя з 8 можливих. Розвʼязок можна оптимізувати за площею і вартістю.

## Поле і час
- Квадратна сітка-«плата»; зайняту схемою площу міряють у клітинах (ліміт площі в челенджах).
- Вхід/вихід — **стрічки** кольорових клітин на краю плати (Input 1, Input 2 → Output 1, Output 2).
- Час програмний: симуляція йде **ітераціями** — на кожну ітерацію подається наступна клітина вхідної стрічки, промені поширюються, результат пишеться в наступну клітину виходу.
- Колір = множина з трьох основних (R, G, B): чорний (жодного), червоний, зелений, синій, блакитний, пурпуровий, жовтий, білий — 8 станів, тобто 3 біти.
- 3D-версія: та сама логіка, тривимірна графіка (?), переписана симуляція.

## Сутності
| Сутність | Роль | Параметри | Поведінка |
|---|---|---|---|
| Джерело світла | source | білий | дає білий промінь; від нього живляться перемикачі й комплементор |
| Вхідна стрічка | source | послідовність кольорів | щоітерації випромінює колір поточної клітини |
| Вихідна стрічка | sink | очікувана послідовність | записує колір променя, що прийшов; порівнюється з еталоном |
| Блок | static | — | поглинає промінь з будь-якого боку |
| Тунель | conduit | вісь | пропускає промінь через два протилежні боки, інші два блокує |
| Дзеркало | conduit | орієнтація | відбиває промінь з одного боку |
| Двобічне дзеркало | conduit | орієнтація | відбиває з обох боків |
| Розщеплювач | conduit | орієнтація | ділить промінь на кілька; також зливає промені (кольори додаються) |
| Фільтр основного кольору | conduit | R/G/B | пропускає лише свій основний колір |
| Фільтр вторинного кольору | conduit | C/M/Y | блокує одну основну складову (C — червону, M — зелену, Y — синю) |
| Дихроїчне дзеркало (основне) | conduit | R/G/B | відбиває один основний колір, решту пропускає |
| Дихроїчне дзеркало (вторинне) | conduit | C/M/Y | відбиває дві складові, пропускає доповняльну |
| Перемикач тип 1 | switch | керуючий вхід знизу | пропускає промінь, лише коли на керуючому вході є промінь |
| Перемикач тип 2 | switch | керуючий вхід знизу | пропускає промінь, лише коли керуючого променя **нема** |
| Акумулятор | container | значення | переносить вхід з однієї ітерації в наступну (памʼять) |
| Комплементор | conduit | потребує білого знизу | перетворює колір на доповняльний у тій самій ітерації |

## Правила (КОЛИ → ЯКЩО → ТО)
- КОЛИ `input(place, part, cell)` → ЯКЩО `free(cell)` → ТО `place(part, cell)`.
- КОЛИ `input(rotate, part)` → ТО `rotate(part, 90)` (?).
- КОЛИ `custom: «почалась ітерація»` (+trigger:iteration_start) → ТО `custom: «кожна вхідна стрічка випускає колір поточної клітини»` (+effect:emit_beam).
- КОЛИ `custom: «промінь влучив у дзеркало»` (+trigger:beam_hit) → ТО `bounce(beam)`.
- КОЛИ `custom: «промінь влучив у блок або в бік тунелю»` → ТО `block`.
- КОЛИ `custom: «промінь влучив у розщеплювач»` → ТО `custom: «промінь ділиться на кілька»` (+effect:split_beam).
- КОЛИ `custom: «кілька променів сходяться на розщеплювачі»` → ТО `custom: «один промінь, колір = обʼєднання складових»`.
- КОЛИ `custom: «промінь проходить фільтр»` → ТО `custom: «лишити / прибрати складову кольору»` (+effect:recolor_beam).
- КОЛИ `custom: «промінь влучив у дихроїчне дзеркало»` → ЯКЩО `custom: «складова збігається з кольором дзеркала»` (+cond:beam_color) → ТО `bounce(beam)` для неї; решта складових проходить прямо.
- КОЛИ `custom: «промінь на вході перемикача тип 1»` → ЯКЩО `custom: «є керуючий промінь знизу»` (+cond:beam_present) → ТО `custom: «пропустити»`; інакше `block`.
- КОЛИ `custom: «промінь на вході перемикача тип 2»` → ЯКЩО `not custom: «є керуючий промінь знизу»` → ТО `custom: «пропустити»`; інакше `block`.
- КОЛИ `custom: «промінь у комплементорі»` → ЯКЩО `custom: «знизу білий промінь»` → ТО `custom: «колір → доповняльний»`.
- КОЛИ `custom: «промінь в акумуляторі»` → ТО `set_value(accumulator, color)`; КОЛИ `custom: «наступна ітерація»` → ТО `custom: «акумулятор випускає збережене»`.
- КОЛИ `custom: «промінь дійшов до вихідної стрічки»` → ТО `custom: «записати колір у поточну клітину виходу»` (+effect:write_output).
- КОЛИ `custom: «ітерація завершена»` → ЯКЩО `custom: «записана клітина ≠ еталон»` → ТО `custom: «помилка, симуляція зупиняється»` (?).
- КОЛИ `all_constraints_met` (усі вихідні стрічки збіглися з еталоном) → ТО `win`, `window(end-screen)` з метриками.
- Перемога: виходи збігаються з еталоном на всій стрічці · Поразка: нема (лише невдала перевірка) · Рахунок: площа, вартість (+ інші метрики в 3D).

## Цікавинки для курсу
- Колір як 3-бітова маска: фільтри = AND з маскою, злиття = OR, комплемент = NOT — 🌱.
- Трасування кількох променів з розщепленням і злиттям за одну ітерацію (BFS по променях, виявлення циклів) — 🥉.
- Перемикачі тип 1/2 = оптичні транзистори; залежність «промінь керує іншим променем» вимагає порядку обчислення або фіксованої точки — 🥈.
- Акумулятор: стан між ітераціями, тобто схема стає скінченним автоматом — 📎.
- Перевірка розвʼязку по стрічці + метрики площі/вартості + гістограма серед гравців — 📎.
- Пісочниця й креслення (копіювати фрагмент схеми) — 📎.
